# Tasks and CI

`Taskfile.yml` defines the tasks. `.gitlab-ci.yml` has one job for each stage, and each job calls the task of its stage. So CI and a person run the same step.

## Tasks

| Task                 | Stage    | What it does                                                                                                                                                                                                                                                                                                         | It fails when                                                   |
| -------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `task format`        | none     | Formats the Python scripts with ruff, and the Markdown files with mdformat. It does not change `sources/model-operating-rules.md`, because only a new version changes the system prompt. `CHECK=true` changes no file.                                                                                               | `CHECK=true` and a file needs a change                          |
| `task lint`          | none     | Lints the Python scripts with ruff, and the Markdown files with pymarkdown. It reads the rules file with the same settings.                                                                                                                                                                                          | a linter finds a problem                                        |
| `task review`        | review   | Runs `task format CHECK=true`, then `task lint`. Format always runs before lint.                                                                                                                                                                                                                                     | either task fails                                               |
| `task build`         | build    | Checks the version line of the rules file against `version.json`, then copies the release files to `.build/agent-operating-rules-<version>/`, each at its own path.                                                                                                                                                  | the two versions differ                                         |
| `task test`          | test     | Runs the unit tests of `bin/` in `tests/unit/`, and checks `tests/evaluation/pairs.json` with `bin/run-evaluation.py --plan`. Then runs `bin/deterministic-tests.py --check` on the rules file at 20 words, and on `README.md` and `tests/evaluation/evaluation-tests.md` at 25 words.                               | a unit test fails, a pair is not valid, or a file has a finding |
| `task eval:plan`     | none     | Checks `tests/evaluation/pairs.json`, and prints the calls and the cost estimate of `task eval`. It calls no API.                                                                                                                                                                                                    | a pair is not valid                                             |
| `task docs`          | docs     | Runs `bin/deterministic-tests.py --check` on each page of `docs/` at 25 words, then `bin/check-links.py` on `docs/` and `README.md`.                                                                                                                                                                                 | a page has a finding, or a link has no file                     |
| `task package`       | package  | Runs `task build`, then zips the folder into `dist/agent-operating-rules-<version>.zip`.                                                                                                                                                                                                                             | the build fails                                                 |
| `task ci`            | all      | Runs review, build, test, docs and package, in that order.                                                                                                                                                                                                                                                           | a stage fails                                                   |
| `task eval`          | evaluate | Sends the evaluation prompts through the Perplexity Agent API. It runs `task eval:provider` for each provider at the same time, then `task eval:merge`. An executor answers, and two judges score each answer. It reads `PERPLEXITY_TOKEN`. `PROVIDER`, `PROMPTS`, `SAMPLES`, `ALL_PAIRS` and `RUN` choose the work. | the key is missing                                              |
| `task eval:provider` | evaluate | Runs one `PROVIDER` into `.eval/RUN/results/PROVIDER.jsonl`, one line for each score, call or failure. A failed call is a line of the file, not a failed task.                                                                                                                                                       | the key, `PROVIDER` or `RUN` is missing                         |
| `task eval:merge`    | report   | Reads the JSONL files of `.eval/RUN/results/`, and writes `scores.csv`, `calls.csv`, `human-test.csv` and `summary.md`. It calls no API.                                                                                                                                                                             | a call failed, or a line is not a record                        |
| `task eval:probe`    | none     | Runs `task eval` with prompt C1 one time, for each main pair or for `PROVIDER`.                                                                                                                                                                                                                                      | as `task eval`                                                  |

`task ci` leaves out the evaluation tasks, because they cost money.

`task format` and `task lint` run each tool with `uvx --python 3.12`. The versions in `Taskfile.yml` are ruff 0.16.10, mdformat 1.0.0 with mdformat-gfm 1.0.0, and pymarkdownlnt 0.9.40. The tools stay in the cache of uv, not in a `.venv` folder.

`task build` skips its copy when the release files, `Taskfile.yml` and `.build/` are the same as at the last build. Task keeps their checksum in `.task/`. So `task package` and `task ci` do not copy the files a second time.

The release files are `README.md`, `version.json`, the folder `sources/`, `bin/deterministic-tests.py` and `tests/evaluation/evaluation-tests.md`. They keep their paths in the zip, so the script finds `sources/banned-words.txt`.

## CI

| Setting               | Value                                                                                                                                                                                                                                                                                         |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Image                 | `ghcr.io/astral-sh/uv:0.12.23-python3.12-alpine`                                                                                                                                                                                                                                              |
| Task                  | 3.53.1, checked with its SHA-256 sum                                                                                                                                                                                                                                                          |
| uv cache              | `.uv-cache`, with `Taskfile.yml` as its key. Only the review job gets it                                                                                                                                                                                                                      |
| Stages                | review, build, test, docs, package, evaluate, report                                                                                                                                                                                                                                          |
| Mirror                | The push mirror of GitLab, not a job, copies the protected branch `main` to `thecastandbloomgroup/agent-operating-rules` on GitHub. The [GitHub mirror](../how-to/set-up-the-github-mirror.md) page gives the setup.                                                                          |
| Artifact of build     | `.build/` and `.task/`, kept for 1 week. The package job gets only these, and does not build again                                                                                                                                                                                            |
| Other artifacts       | The test and docs jobs download no artifacts                                                                                                                                                                                                                                                  |
| Cancel                | A new commit cancels each job of its older pipeline                                                                                                                                                                                                                                           |
| Evaluate              | One job for each provider, and the jobs run at the same time. Each runs `task eval:provider` into `.eval/pipeline-ID/`. It runs only on `main`, when a person starts it or a schedule runs it. It is not interruptible, it can fail without failing the pipeline, and it stops after 2 hours. |
| Report                | The job `evaluate:report` runs `task eval:merge` on the JSONL files of all the evaluate jobs of the pipeline. A schedule runs it after the evaluate stage. On a manual run, start it after the provider jobs end. It needs no secret.                                                         |
| Secrets of evaluate   | `DOPPLER_TOKEN`, a protected and masked variable. `doppler run` reads `PERPLEXITY_TOKEN` from Doppler. The [Doppler setup](../how-to/set-up-doppler-for-evaluation.md) page gives the steps.                                                                                                  |
| Artifacts of evaluate | `.eval/`, kept for 3 months, also when the job fails. The artifact of `evaluate:report` holds the final view.                                                                                                                                                                                 |
| Artifact of package   | `dist/*.zip`, kept for 1 month                                                                                                                                                                                                                                                                |
