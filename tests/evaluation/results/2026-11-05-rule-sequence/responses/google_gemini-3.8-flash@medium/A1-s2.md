## Information

This section covers the evidence, assumptions, and alternatives for package version pinning.

Build reliability requires deterministic inputs. Python packaging guidelines state that deployable applications must pin exact versions to guarantee reproducible environments [1]. In contrast, library projects use abstract version ranges in pyproject.toml [2]. When you leave versions unpinned, package updates introduce breaking changes without warning [judgment].

### Alternative considered
The strongest alternative is using flexible version ranges, such as major version caps. This alternative loses because minor and patch releases still introduce unexpected regressions into automated pipelines [judgment].
