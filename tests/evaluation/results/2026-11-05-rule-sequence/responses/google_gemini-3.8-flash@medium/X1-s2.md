## Headline

Establishing an evaluation benchmark, capturing agent feedback, and applying constrained prompt engineering will resolve summariser errors.
First, an evaluation benchmark establishes baseline accuracy and categorises existing summary errors.
Second, an interface feedback widget captures ongoing failure cases from support agents.
Third, an updated prompt enforces factual consistency against ticket transcripts.

## Background

The engineering team deployed a large language model (LLM) summariser in the customer support console.
Support agents report that the summaries are sometimes inaccurate.
The system lacks quality metrics, and the user requested an improvement plan.

## Relevance

Inaccurate ticket summaries slow agent resolution times and risk incorrect customer advice [1].
Therefore, creating reliability metrics protects service operations from ongoing communication failures.

## Information

This section covers the baseline evidence, the assumption log, and the alternative considered.
Support leadership reports qualitative agent complaints regarding factual errors in ticket summaries [judgment].
Industry benchmarks show factual errors in 15% to 30% of zero-shot summaries [1].
However, the current system lacks numerical metrics to verify these failure rates [judgment].
Therefore, fixing the summariser requires measurable metrics before engineering prompt changes [judgment].
It is likely (66% to 100% probability) that model hallucination causes the agent complaints [judgment].
For example, unconstrained models often invent details when source tickets omit specific resolution steps [judgment].

A1. The support tool database stores complete raw conversation transcripts. Why not measured: The material does not state it. Validate by: Inspect the production database schema. If wrong: Add conversation logging before evaluating summaries.

A2. Support agents will submit feedback if the interface requires only one click. Why not measured: The material does not state it. Validate by: Test the interface with five agents during one shift. If wrong: Replace agent feedback with weekly audit sampling.

Alternative: Fine-tune an open-source model on historical ticket data immediately.
Reason it loses: Fine-tuning requires clean training data that does not exist yet [judgment].
Furthermore, prompt constraints achieve accuracy gains at lower computational cost [judgment].
