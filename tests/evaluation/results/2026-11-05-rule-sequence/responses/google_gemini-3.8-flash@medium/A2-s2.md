### Information

Direct column rename in PostgreSQL acquires an ACCESS EXCLUSIVE lock on the relation [1].
This lock blocks all concurrent reads and writes for the duration of the transaction [1].
Furthermore, client services that run SQL queries with the user_id column fail immediately [2].
In contrast, an expand-contract pattern creates account_id alongside user_id to ensure backward compatibility [2].
A trigger mirrors new writes while background workers backfill historical data [judgment].
Once all application code references account_id, the database drops user_id safely [2].
