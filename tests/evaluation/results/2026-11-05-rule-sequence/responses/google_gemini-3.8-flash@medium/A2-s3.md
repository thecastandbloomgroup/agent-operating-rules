### Information

This section covers the database locking behavior and execution risks.
First, PostgreSQL requires an ACCESS EXCLUSIVE lock on the table for column renames [1].
This lock blocks concurrent read and write queries until the DDL transaction finishes [1].
Next, application services fail immediately if queries reference the old column name [judgment].
For example, an active order query that requests user_id fails with an undefined column error [judgment].
So, an unplanned schema change risks a production outage (high confidence, PostgreSQL specification [1]).
