## Headline

No prompt stops hallucination; the best prompt reduces it by forcing grounding, citations, and abstention. The mechanism behind hallucination is fluent generation without source support [1], so the prompt below makes support checkable. The larger gain comes from retrieval plus a verification pass [2], not from wording alone.

```text
Answer only from the sources supplied in this conversation.
For each claim, add the source in brackets after it.
If the sources do not answer the question, write exactly: "Not in the sources."
Where a number, name, date, or version is unknown to you, leave it out.
Do not add praise, filler, or a summary of the request.
```

## Background

The request asks for the best prompt to stop model hallucination in a single message. No product, tool route, or task type is named. The reply therefore targets a general chat model with a system prompt.

## Relevance

Unsupported facts reach end users when staff or agents copy model text without a check [1]. A prompt plus a measured loop removes most of that risk in one working session.

## Information

**Define the target.** A hallucination is generated text that the source text or retrievable facts do not support [1]. The failure has two parts: the model produces fluent text without support, and no later step detects it [1]. A prompt acts on part one, so a prompt that produces a checkable output treats the root better than a bare ban.

**Why citations and abstention.** A claim with a bracketed source can be checked by a reader, so unsupported text has a place to hide, and abstention removes invented numbers and names. The "answer only from the source" line narrows the output space, which is the same narrowing that grounded generation applies at the architecture level [2]. This design choice is a judgment, not a measured result: [judgment].

**Data note.** Fine-tuning a model on facts it does not know raises the rate of hallucination on them [3]. Prompt changes are therefore not equivalent to training changes, and prompt work is the cheap level to start at.

**Assumption log.**

`A1. The model is a general chat model with a system prompt. Why not measured: the request names no product. Validate by: read the product name in the next message. If wrong: move the prompt into that product's system field.`

`A2. The task is fact questions over changing topics. Why not measured: the request states no task. Validate by: list the last ten questions the model received. If wrong: drop retrieval, because tasks that only transform given text need no source.`

**Alternative considered.** The prompt "Do not make things up as your entire prompt." It loses: a bare ban does not define the supported state, so the model still cannot separate supported from unsupported text, and no one can check the output [judgment]. The citation-and-abstain form gives a check.

## End

I recommend that we run four steps. Step 2 depends on Step 1. Step 3 must not start until the Step 2 test passes.

1. **Build the test set.** Write 20 questions with answer keys. Include 5 unanswerable questions with the key "no answer". Deterministic work over fixed data. This removes the test-first blocker for all later steps. Test in Gherkin [14]:
   ```gherkin
   Given a question list of 20 items with answer keys
   When the list is checked against the keys
   Then each item has one key, 5 items have the key "no answer", and no item repeats
   ```
   Domain: Clear. Cause and effect are known to everyone, so the action is one step and leverage is reliable.

2. **Insert the prompt and measure.** Put the prompt above into the system text. Run all 20 questions with and without it, one trial per question per arm. Then accept the prompt only when the unsupported share of answers is half the baseline or less at a sample of 20 questions per arm. Stochastic output: model text under a prompt edit varies run to run. Domain: Complex. Cause and effect between wording and rate is visible only after the run, so this runs as a safe-to-fail probe with the 20-question stop condition and a budget of one session. Leverage is a guess [judgment].
   ```gherkin
   Given the grounded prompt in system text and the 20-question set
   When each question is answered once per arm and each answer is checked against its key
   Then the unsupported share is half the baseline or less
   ```

3. **Add retrieval for source-backed tasks.** Route questions that have a fixed source text (a document, a manual) through retrieval into the source list in the prompt. Then compare the retrieval arm with the Step 2 arm on the same set, and accept retrieval at the same threshold. This adds the capability that narrows generation [2]. Stochastic: retrieval quality varies per run. Domain: Complicated. More than one good route exists, so analysis (the side-by-side compare above) picks the one. Its test has the same metric, baseline, threshold, and sample size as Step 2.

4. **Add a check pass.** After each answer, run one more model turn that removes every claim without a bracketed source. This unsticks the second failure part: an unsupported claim that survives generation [1]. Stochastic: it depends on model judgment. Domain: Complex; run it as a probe with the same 20-question measure, same threshold, and a stop if it slows output by more than 2 times.

Hedge on Step 3: if all ten recent questions from A2 fall into transform tasks, replace Step 3 with a source-attach step: paste the fixed source into the conversation before each question.
