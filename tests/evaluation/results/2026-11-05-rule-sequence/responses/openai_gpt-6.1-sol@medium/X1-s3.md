## Information

### Define “better”

Use these separate measures rather than one overall quality score:

| Measure | Definition | Purpose |
|---|---|---|
| Unsupported claims | Claims that lack support in the ticket | Detect invented facts |
| Incorrect claims | Claims that conflict with the ticket | Detect factual errors |
| Required facts omitted | Missing facts from a ticket-specific checklist | Detect incomplete summaries |
| Attribution or status errors | Wrong speaker, owner, action, or resolution state | Detect operational mistakes |
| Agent correction rate | Summaries agents must correct before use | Measure usefulness |
| Response time and cost | Seconds and cost per summary | Detect service trade-offs |

These definitions are proposed measures, not observed findings. [judgment]

Mark an error as **severe** when it can change the next action, expose sensitive data, or misstate a commitment. [judgment]

Fluent but false output is a documented risk of generative artificial intelligence. Therefore, fluency alone is not evidence of accuracy. [2]

### Match the fix to the failure

- **Missing source text:** fix ticket assembly or truncation before changing the prompt. [judgment]
- **Incorrect or unsupported claims:** require source references and explicit “not stated” responses. [judgment]
- **Missing required facts:** use fixed fields for issue, actions taken, current status, and next action. [judgment]
- **Wrong attribution or status:** require the speaker and source timestamp for each action or commitment. [judgment]
