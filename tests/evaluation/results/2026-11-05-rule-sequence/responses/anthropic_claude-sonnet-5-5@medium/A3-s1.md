Your API returns JSON that averages 400 KB per response. The question is whether to compress those responses with gzip, a common lossless compression format [1].

Relevance: every response sends 400 KB over the network today. Compression changes both user latency and bandwidth cost.

Evidence follows. Gzip on repetitive JSON text usually removes 70 to 90% of the bytes [inference]. It is 90% likely that the reduction exceeds 60%, because JSON repeats keys and structure. A 400 KB response would then shrink to about 40 to 120 KB. On a 10 Mbit/s link, 400 KB takes about 0.32 s to send. At 80 KB it takes about 0.06 s [judgment, simple arithmetic on an assumed link speed]. Gzip at a middle level costs roughly 5 to 20 ms of CPU for 400 KB [judgment].
