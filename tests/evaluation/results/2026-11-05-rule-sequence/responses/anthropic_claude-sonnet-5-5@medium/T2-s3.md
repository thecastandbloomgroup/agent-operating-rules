## Headline

No prompt stops hallucination fully, but a grounding prompt with a refusal rule cuts it the most.

- Language models guess when they lack facts, so the prompt must make "the sources do not say" an allowed answer.
- The prompt must tie each claim to a quote from supplied sources.
- A test set must confirm the gain, because the size of the effect varies by model and task.

## Background

You want one prompt that stops a model from stating false facts. The request does not name a model, a task, or a source of truth. This section assumes a chat model and factual questions.

## Relevance

A false answer that reads well is hard to catch. A prompt costs nothing to change, so you can test a fix today.

## Information

**Evidence**

1. Some hallucination cannot be removed from a calibrated language model, per a statistical argument [1]. [inference] from that result: a prompt lowers the rate but does not make it zero.

2. Supplying retrieved documents to the model improves factual output on knowledge tasks [2].

3. A second pass that checks each claim lowers false statements [3].

4. Confidence: high for the direction of the effect, because three studies agree. Confidence: low for the size of the effect on your task, because no measurement exists yet.

**The prompt**

```text
Answer only from the text inside <sources>.
If the sources do not contain the answer, write: "The sources do not say."
Do not use outside knowledge.
After each claim, add a short direct quote from the sources.
If you cannot find a quote, delete the claim.
Do not guess names, numbers, dates, or references.
Mark any inference with [inference].
If the question is unclear, ask one question.
```

**Assumption log**

A1. The task is factual Q&A where you can paste source text. Why not measured: the material does not state it. Validate by: check that one real question has a source passage. If wrong: replace the quote rule with "say 'not sure' when unsure" and expect a smaller gain.

A2. A 50-question test set shows a real effect. Why not measured: measuring more costs more than the decision is worth. Validate by: compare scores across three runs. If wrong: raise the sample size to 100.

**Alternative considered**

Fine-tuning the model on correct answers. It loses because it costs days and money, while a prompt change takes one working session [judgment].

## End

I recommend that we take these steps in order:

1. **Build a test set.** Write 50 questions with reference answers, and make 10 of them unanswerable from the sources. This removes the blocker that no one can measure progress. Kind: deterministic. Domain: Clear, by deduction from a known rule (a labeled test set is standard practice). Test, written first:

   Given a file of 50 questions with reference answers
   When the file is checked
   Then 10 questions are marked unanswerable and 40 each cite a source passage

2. **Measure the baseline.** Run your current prompt on the set, 3 runs each. Step 2 MUST NOT start until the test in Step 1 passes. This gives the number to beat. Kind: stochastic. Domain: Clear, by deduction (counting errors follows a known method). Test, written first: the metric is the share of answers with an unsupported claim. The baseline is what this step records. The pass threshold is that the 3 runs agree within 10 points. The sample is 50 questions times 3 runs.

3. **Probe the grounding prompt.** Run the prompt above on the same set. Step 3 MUST NOT start until Step 2 records a baseline. This adds the refusal rule and the quote rule. Kind: stochastic. Domain: Complex, by induction from trials. The pattern could break when the model version or question type changes. Leverage is a guess. Test, written first: the metric is the unsupported-claim rate. The pass threshold is half the baseline or lower, and at least 9 of 10 unanswerable questions refused. The sample is 50 questions times 3 runs. Budget: one session. Stop after two failed prompt revisions.

4. **Probe a verification pass.** Run Step 4 in parallel with Step 3. Add a second prompt that checks each claim against its quote and deletes unsupported claims. This adds a second filter for errors that Step 3 misses. Kind: stochastic. Domain: Complex, by induction from trials. The checker could share the blind spots of the first pass. Leverage is a guess. Test, written first: the same metric, threshold, and sample as Step 3. The pass threshold is also a lower rate than Step 3 alone. Budget: one session. Stop after two failed revisions.
