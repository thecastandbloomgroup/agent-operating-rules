## Headline

Yes, pin every version, including indirect dependencies, and update the pins on a schedule.

- Floating versions are the likely cause of both breaks last month [1].
- A pinned file makes each build install the same versions every time [2].
- A compile step pins indirect dependencies (packages that your libraries need) without hand-written lists.
- A scheduled update job stops the pins from going stale.

## Background

The project has a `requirements.txt` with no pinned versions. The build broke twice last month after a library update. The question is whether to pin.

## Relevance

Each unpinned build can install new versions without a code change. The breaks cost build time now, and the failure rate stays unchanged until the team fixes the cause.
