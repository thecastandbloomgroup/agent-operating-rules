## Headline

Yes, pin every version in requirements.txt, and update the pins on a schedule.

- Unpinned installs pick up new releases on each build, so the build changes without a code change.
- A pinned file makes each build repeat the last good build.
- Pins age, so a scheduled update job must replace manual upgrades.

## Background

The project has a requirements.txt with no pinned versions. The build broke twice last month after a library update [1]. The question is whether to pin.

## Relevance

Each break blocks the team until someone finds the cause. At the current rate, that is 2 breaks per month.

## Information

**Evidence**
- Baseline: 2 build breaks in the last month, each after a library update [1].

- An exact pin such as `requests==2.31.0` fixes the version that pip installs [2].

- A tool called pip-tools turns a short list of direct dependencies into a full pinned file [3]. That file includes indirect dependencies.

- Pinning likely removes update-caused breaks (66 to 100%). Basis: high confidence in the mechanism, but no measurement on this project yet.

- Cost of pinning: security fixes no longer arrive by themselves. [judgment]

**Assumption log**

A1. The project is Python and installs with pip. Why not measured: the material does not state it. Validate by: run `pip --version` in the CI log. If wrong: replace the commands with the matching package tool.

A2. The breaks came from library versions, not from the Python version or the OS image. Why not measured: the material does not state the cause. Validate by: compare the package lists of the last good and first bad builds. If wrong: pin the base image first (see Follow-up).

A3. A CI job (an automated build server run) exists and runs tests. Why not measured: the material does not state it. Validate by: open the CI configuration. If wrong: add Step 2 as a local script.

**Alternative considered**

Use version ranges, such as `requests>=2.31,<3`. This blocks major changes but still lets minor releases break the build. It loses because it does not repeat a past build.
