## Headline

Yes, pin every version, direct and transitive, in a lock file that a tool generates from a short list of loose requirements.

- Unpinned installs take the newest release on each build, so a library update can break a build with no code change.
- A tool such as pip-tools writes the pinned file, so the team does not edit it by hand.
- The team then updates pins on purpose, through a tested pull request.

## Background

The project's `requirements.txt` has no pinned versions. The build broke twice last month after a library update (per the user's message). The question is whether to pin versions.

## Relevance

Each unpinned build can install a different set of packages. Two breaks in one month show that this risk already costs the team time.
