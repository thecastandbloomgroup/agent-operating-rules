## Headline

Replace all 14 `print` calls in `service.py` with a module logger that runs at INFO level.

- The change is mechanical, because the file has one place to configure logging and 14 calls to convert [1].
- Messages that already name a severity keep it, so the WARNING and ERROR prints become `warning` and `error` calls.
- The standard `logging` module formats arguments lazily and adds time and level, so no new dependency is needed [2].
- Four small steps, each with a test written first, keep the change safe.

## Background

`service.py` is a 129-line HTTP service over an orders database. It reports events with 14 `print` calls. One call writes to stderr and the other 13 write to stdout [1]. The request is to use the standard `logging` module at INFO level.

## Relevance

Print output has no timestamp, no level, and no filter. Operators cannot separate errors from routine events. The service also runs unattended, so log quality decides how fast a fault is found.

Add this setup. Put `basicConfig` in `main` so that an import in a test does not change global logging:

```python
import logging
logger = logging.getLogger("orders")

# first line of main():
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s %(message)s",
)
```
