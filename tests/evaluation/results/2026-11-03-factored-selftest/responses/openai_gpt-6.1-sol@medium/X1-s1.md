## Information

**Define an error before measuring it.** Use these three distinct categories. [judgment]

| Category | Definition | Example |
|---|---|---|
| Unsupported statement | The summary contradicts the ticket or adds an unsupported claim. | It says a refund happened when someone only requested one. |
| Material omission | The summary excludes information needed for the next support action. | It excludes an unresolved account lock. |
| Unusable presentation | The facts are present, but their order or wording obscures the next action. | It mixes an earlier workaround with the current status. |

Treat an error as **material** when it changes the agent’s understanding, customer response, or next action. [judgment]

Track these measures separately rather than hiding them inside one average score. [judgment]

- **Material-error rate:** summaries with at least one material error divided by reviewed summaries.
- **Category rates:** summaries with each error category divided by reviewed summaries.
- **Review time:** seconds needed to check and correct a summary.
- **Coverage:** tickets with enough source information to support a useful summary.

A summary can contain multiple error categories, so category rates do not need to total 100%.

A2. Staff can review existing tickets within approved access controls. Why not measured: The material does not state it. Validate by: Check access with the support owner. If wrong: Use an approved, masked sample.
