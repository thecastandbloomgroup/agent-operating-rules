The only product evidence is the agent report and the absence of metrics. [1] This supports an investigation, but not a specific model diagnosis. [judgment]

Confidence in any specific fix is **low**, because no failed summaries or source tickets are available.

Use these separate measures. The thresholds below are proposed starting points, not measured results. [judgment]

| Measure | Definition | Initial acceptance rule |
|---|---|---|
| Factual error rate | Share of summaries with unsupported or contradicted claims | At most half the baseline rate |

| Severe errors | Errors involving account identity, money, security, or customer commitments | Zero observed |

Define required facts before reviewing each summary: customer problem, current status, recorded action, and recorded next step. Mark absent source information as “not recorded.” [judgment]

## End

I recommend that we complete these three actions in order.

### 1. Add an agent approval gate

**Kind:** Deterministic.  
**Domain:** Clear, because the approval rule has a direct, testable effect.

**Test first:**
```gherkin
Given a generated summary without agent approval
When a workflow tries to send or save it as an official record
Then the workflow requires agent approval
```

**Increment:** In one work session, configure summaries as editable drafts with source-ticket access and explicit approval.

**Blocker removed:** An unchecked summary cannot become an official record through that workflow. [judgment]

Test every entry point that uses the summary. End the session with the gate working, or disable the affected entry point.

### 2. Establish a baseline and identify the main failure

**Kind:** Evaluative.  
**Domain:** Complicated, because source comparison and error analysis determine which change to test.

**Rubric first:** Use this weighted decision score. All weights and thresholds are proposed. [judgment]

| Criterion | Weight | Evidence required |
|---|---:|---|
| Factual accuracy | 50% | Every claim checked against the ticket |
| Required-fact coverage | 30% | Required facts marked present or absent |
| Correct attribution | 20% | Correct customer, speaker, action, and date |

Score each criterion from 0 to 100 using the proportion of checks passed. Pass at **90/100 overall**, with **zero severe errors**.

**Current scores:** Unavailable for all three criteria; no source tickets or summaries were supplied. Do not treat missing evidence as a pass.

**Increment:** After Step 1 passes, review 20 consecutive recent summaries in one work session.

Record the source, summary, criterion scores, error severity, agent correction, and review time. Have a second reviewer check every severe error and five other cases.

**Capability added:** A baseline and a ranked list of observed failures. [judgment]

Choose the first fix by severe-error count, then total error count. Keep these 20 cases separate from the release test.

### 3. Run one bounded comparison

**Kind:** Stochastic.  
**Domain:** Complex, because the effect of a prompt change requires observation.

**Acceptance test first:**

- **Sample:** 50 different, held-out tickets, each processed by the current and candidate versions.
- **Baseline:** Current-version results on those same 50 tickets.
- **Metrics:** The four measures in Information.
- **Pass:** Meet every acceptance rule in that table.
- **Zero-error baseline:** Require zero candidate errors too; report no demonstrated improvement.
- **Budget:** One candidate and one four-hour review session per reviewer.
- **Stop:** Reject the candidate after any severe error.

These limits support a small pilot, not proof that rare errors cannot occur. [judgment]

**Increment:** Step 3 MUST NOT start until Step 2 produces a baseline and a leading failure category.

Change one cause at a time. For unsupported claims, test a source-only prompt that forbids invented details and uses “not recorded” for missing facts. For missing facts, test a fixed summary template.

Keep the model and other settings unchanged. Hide version names from reviewers and vary display order.

**Capability added:** A measured comparison instead of an opinion-based release decision. [judgment]

Accept the candidate only after the trials meet every threshold. No trials have run in this conversation.
