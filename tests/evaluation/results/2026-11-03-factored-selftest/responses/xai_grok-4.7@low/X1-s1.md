## Headline

Measure errors on a frozen set, then change one cause and keep the change only if the error rate falls.

First, a two-rater sample names the error type.
Second, a gold set, that is a fixed labeled list, gives a baseline rate.
Third, one lever per trial shows what moved the rate.
Fourth, a pass rule blocks a change that does not beat that rate.

## Background

The support tool now writes a summary with a large language model (LLM). Agents say that summary is sometimes wrong. The team has no metrics, and the request is to make the summariser better.

## Relevance

Agents read these summaries while they handle live tickets. Therefore a false summary can drive a bad reply, and trust in the tool drops.

## Information

This section covers the evidence, the assumptions, and the alternative.

The request states that agents report errors and that no metrics exist [1].
Because no rate exists, a prompt edit has no pass test [judgment].
Abstractive means the model writes new sentences, not a cut from the source.
Studies find that abstractive summaries often add facts absent from the source [2].
The same study finds that word-overlap scores do not track faithfulness [2].
Medium confidence, one user report plus one study, and no local counts.

A1. Wrong means a missing fact, an invented fact, or a wrong priority. Why not measured: the material does not state the error type. Validate by: the label pass in Step 1. If wrong: use the types that agents name.

A2. Two agents can label 40 summaries in one session. Why not measured: the material does not state capacity. Validate by: time 10 items first. If wrong: cut the set to 20.

A3. The LLM sees only the ticket text. Why not measured: the material does not state the context builder. Validate by: read the prompt and the context code. If wrong: audit context before Step 3.

The strongest alternative is to rewrite the prompt now and ask agents if it feels better. It loses because feel has no baseline, so a worse prompt can ship [judgment].

## End

I recommend that we run four steps in this order.

Step 1. Classify the failure before any fix.
Domain: Confused, because the error type is unknown and that fact decides the next domain.
Test first. Kind: evaluative, that is a judgment score.
Criteria and weights: rater agreement 40%, written label rules 20%, tickets from the last 14 days 20%, both raters finish 20%.
Pass threshold: 70 points.
Evidence: one shared label sheet.
Increment: label 40 summaries with two agents in one session.
Use four labels: faithful, missing fact, invented fact, wrong priority.
Blocker removed: the unknown error type.

Step 2. Record a baseline on a fixed set.
This step MUST NOT start until the Step 1 test passes.
Domain: Clear, because freeze, run, and score is a known practice.
Test first. Kind: deterministic, that is the same input gives the same score sheet.
Given 30 tickets with source text and a rater label
When the current LLM runs once on each source
Then the sheet records the error rate and the top class
Increment: build the gold set and store the baseline in one session.
Blocker removed: the missing baseline.

Step 3. Pick one fix from the top class.
This step MUST NOT start until the Step 2 test passes.
Domain: Complicated, because several good fixes exist and a map must pick one.
Test first. Kind: evaluative.
Criteria and weights: top class named 40%, fix matches the class 40%, one lever only 20%.
Pass threshold: 80 points.
Evidence: a one page map.
Increment: write that map in one session.
Map invented fact to a quote-then-summarise rule.
Map a missing fact to a required field list.
Map wrong priority to a ticket-type template.
Blocker removed: no chosen practice.

Step 4. Probe that one fix on the gold set.
This step MUST NOT start until the Step 3 test passes.
Domain: Complex, because cause and effect show only after the run.
Leverage is a guess.
Test first. Kind: stochastic, that is the output varies by run.
Metric: error rate on the gold set.
Baseline: the Step 2 rate.
Pass threshold: a drop of at least 10 percentage points.
Sample size: 30 summaries, one run each.
The 10 percentage point rule is a decision threshold, not a measured effect [judgment].
Increment: apply only the Step 3 fix and rescore the same 30 tickets in one session.
Budget: one session and 30 items.
Stop if the rate does not fall by 10 percentage points from the Step 2 baseline.
Do not roll the change out on a fail.
Blocker removed: no measured effect.

## Follow-up

If A3 is false, add a context audit before Step 3 and do not edit the prompt yet.
If Step 1 scores under 70, rewrite the label rules and repeat Step 1.
