## Headline

End the format debate by enforcing one machine-written SQL style; do not try to fix it through team discussion. Support:

## Background

The team disagrees on how to format SQL. Reviews carry style arguments, and the request asks for a culture fix. The mechanism, not the people, removes this friction.

## Relevance

Every review pays the cost until one style exists and a gate enforces it. The fix is small and runs in hours.

## End

I recommend that we run four steps. Step 2 must not start until Step 1 is scored.

1. **Step 1, pick the tool** (evaluative, Complicated: more than one good tool exists, so an analysis must choose). In one session, score the two candidate tools, for example sqlfluff and sqlfmt, in a Pugh matrix [2]. Pugh matrix criteria: dialect coverage, weight 3; stable diffs across runs, weight 2; CI support, weight 2; ability to override rules, weight 1. Pass threshold: no criterion scored negative against the baseline of the current hand-formatted SQL. The increment is the completed matrix. The blocker it removes is the unmade tool decision.
2. **Step 2, gate the repo** (deterministic, Clear: one known best practice applies). Commit the chosen config plus a CI job in one session. Write the test first, in Gherkin [3]:
   Given the repository with the format config
   When the CI job formats each SQL file and compares the result
   Then the job fails on any file whose formatted output differs from the committed file
   The blocker it removes is any SQL that skips the format.
3. **Step 3, format at the source** (deterministic, Clear: one known best practice applies). Add a pre-commit hook that formats changed SQL files, in one session. Test:
   Given a commit with unchanged-format SQL
   When the hook runs
   Then the commit contains formatted SQL
   The capability it adds is a fix before review, so reviewers never see raw format.
4. **Step 4, probe the residual friction** (stochastic, Complex: cause and effect show up only after the run). Run a safe-to-fail probe for 4 weeks: the rule "format what you touch, in its own commit". Acceptance test: metric, share of reviews with style-only comments; baseline, the last 10 reviews on this team [judgment]; pass threshold, a fall of 50% or more; sample size, 10 reviews. Stop condition and budget: stop if format-churn-only commits rise above 1 in 5 pull requests, and cap the probe at 4 weeks. Leverage is a guess here; the probe decides.

Culture note: no meeting, charter, or values statement appears in the steps, because the gate, not agreement, ends the friction [inference].
