Headline
Measure the error before you change the summariser. First, define wrong with a short rubric that agents can apply. Next, score a fixed sample so the error rate has a baseline. Then, change only the top error class and re-score that sample. Last, log agent edits so the rate stays visible.

Background
Agents report that the support summariser is sometimes wrong. The tool has no metrics, so the failure mode and the rate are unknown. The request is to make the summariser better.

Relevance
A wrong summary can send an agent toward the wrong fix and waste handle time. Without a baseline, a model change cannot be shown to help.

Information
The only measured facts are the agent report and the lack of metrics. Both come from this request. Abstractive summarisers can add facts that are not in the source.

Correctness is a named software quality characteristic.
[2]
Therefore a human rubric on faithfulness should come before any model change [judgment]. Overlap scores such as ROUGE do not check whether a fact is in the ticket [judgment].

A1. Summaries cover text tickets, not voice. Why not measured: the material does not state the channel. Validate by: open one live ticket and confirm the input. If wrong: use transcripts in Step 3.
A2. An agent can score one summary in under two minutes. Why not measured: no tool can reach the live workflow. Validate by: time one agent on five tickets. If wrong: score faithfulness only.
A3. Thirty tickets can rank the error classes. Why not measured: a full census costs more than this decision is worth. Validate by: check that the top class is at least 40 percent of errors. If wrong: add thirty tickets before Step 4.

The strongest alternative is to swap or fine-tune the model now. It loses because there is no labeled set and no baseline, so a gain cannot be shown [judgment].

End

1. Write the test before the scores. Criteria and weights: faithfulness 50 percent, coverage of the customer ask 30 percent, next action for the agent 20 percent. Pass threshold: two reviewers name the same error class on at least 24 of 30 tickets. Evidence: a ticket quote that supports or breaks each summary sentence. Increment: one rubric page and five error classes, namely invented fact, missed ask, wrong product, wrong tone, and other. This removes the blocker that wrong has no shared meaning. Domain: Confused. 3. Use the Step 1 rubric as the test. Given 30 tickets from the last 14 days, When two agents score each summary, Then each error class has a count and a rate. Increment: one scored sheet. This removes the blocker that the top error is unknown. Domain: Complicated. The counts pick the later practice. Step 3 MUST NOT start until Step 1 is done.

4. Write the acceptance test before the prompt change. Metric: mean faithfulness on the same 30 tickets, on a scale from 1 to 5. Baseline: the Step 3 mean. Pass threshold: the mean rises by at least 0.5 points, and the top-class count falls. Sample size: 30. Increment: one prompt rule for the top class, with a budget of one session. If the top class is invented fact, the rule bars facts that are not in the ticket. If the top class is different, write one rule for that class instead. Stop if the pass test fails. This removes the largest error class. Domain: Complex. The leverage is a guess. Step 4 MUST NOT start until Step 3 names a top class.
