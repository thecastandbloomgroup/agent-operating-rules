## Headline

Migrate to a hybrid design: short-lived JWT access tokens plus an opaque refresh token in an HttpOnly cookie, and fix sign-up conversion by instrumenting the funnel before changing anything.

- Short access tokens avoid the hardest JWT problem: revocation, because logout and key rotation need server state anyway [19][20].
- Pure stateless JWT (no server state) is lower risk only if no service revokes access before token expiry; this design keeps that state in one table [20][judgment].
- Sign-up conversion has no measured loss point in the material, so the first action is measurement, not redesign.
- The two goals touch different code, so they run in parallel after the design step.

## Background

The request has two goals: move the auth service from sessions to JWT, and raise sign-up conversion. The conversation contains no codebase, metrics, or constraints.

## Relevance

Auth is security critical; a bad migration locks users out or exposes accounts. Sign-up conversion affects every new user, so changes need a measured baseline.

## Information

**Evidence.**

- A JWT is a signed, self-contained token; a server validates it with the key alone and does not look up state per request [19].
- Because a JWT stays valid until it expires, logout, ban, and key rotation require extra server state or short lifetimes [19][20].
- Server-side sessions allow instant revocation with a lookup; this is the baseline behavior the migration must preserve or replace [20].
- Form length and required fields are a common conversion loss point; the material gives no funnel data, so the loss point here is unmeasured [inference].

**Assumption log.**

- A1. Another service or client needs stateless token validation, so the JWT move has a technical driver. Why not measured: the material does not state it; the user has not answered. Validate by: list the services that call session validation and ask the user for their needs. If wrong: keep sessions in cookies and do only the conversion work.
- A2. The session store holds login state that users expect to revoke on logout within minutes. Why not measured: no codebase access in this session. Validate by: read the session store config and the logout handler. If wrong: token lifetimes in Step 2 change.
- A3. The sign-up funnel loses users, and the loss point is unknown. Why not measured: no analytics data in the conversation. Validate by: the funnel events in Step 1. If wrong: conversion work redirects to the measured loss point.
- A4. All traffic runs over HTTPS today. Why not measured: no environment access. Validate by: one curl check per host. If wrong: TLS comes first; a cookie without HTTPS is not safe (high impact on Step 3).

**Alternative considered.** Keep sessions and skip the JWT move. It loses only if A1 is true. If A1 is false, this becomes the recommendation per the hedge in the End section.
