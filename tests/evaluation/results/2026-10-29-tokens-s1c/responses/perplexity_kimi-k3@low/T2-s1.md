## Headline

No single prompt prevents hallucination, because prompt wording controls style, not factual accuracy. The strongest results come from combining a well-formed prompt with grounding and verification. Three techniques do most of the work: cite-or-refuse instructions, retrieved sources, and output checks.

## Background

Hallucination means the model states false content as fact. The user asks for one prompt that stops it. Research shows no prompt eliminates it, because the failure comes from the model itself, not the instruction format [1].

## Relevance

A bad belief here, that one magic prompt exists, wastes time. The useful answer is a short prompt plus two lightweight controls.

## Information

Quantitative evidence is thin for "hallucination stopped by prompt alone." Surveys report that hallucination is an intrinsic property of large language models, and mitigation needs grounding or verification, not phrasing alone [1]. Retrieval augmentation, giving the model source documents to quote, reduces unsupported claims compared with the same model without sources [2] (comparison: grounded vs ungrounded generation).

A1. The user means a general chat or API setting, not one specific pipeline. Why not measured: the material does not state it. Validate by: ask what the model is used for. If wrong: the retrieval step may not apply.

A2. The user can add instructions and, if needed, provide documents. Why not measured: the material does not state it. Validate by: check access to the system or user prompt field. If wrong: only Step 1 and Step 3 apply.

Alternative considered: fine-tune the model on domain data. It loses for this request because it costs days of work and data, while prompt plus retrieval gives most of the gain in one session [judgment].

## End

I recommend that we do four steps:

1. Add a cite-or-refuse instruction (deterministic, Clear domain). Increment: paste this into the system prompt: "Answer only from the provided sources or your confident knowledge. If you are not sure, say 'I do not know.' Never invent facts, names, dates, or citations. Quote the source for each factual claim." Blocker removed: silent fabrication. Test (write first): Given a question whose answer is not in the sources, When the model answers, Then it must say "I do not know" rather than invent a fact.
2. Provide source documents with the question (deterministic, Complicated domain). The choice of which documents to retrieve needs a simple relevance analysis. Increment: attach the 3 most relevant documents and require quotes. Blocker removed: the model fills gaps from training memory. Test: Given a question and 3 documents, When the model answers, Then every factual claim carries a quote from a document.
3. Verify quoted claims (deterministic, Clear domain). Increment: after each answer, check that each quote exists in the documents. Blocker removed: fabrications that survive Steps 1 and 2. Test: Given 20 answers with quotes, When checked against the documents, Then at least 19 of 20 quotes appear verbatim.
4. Measure the effect (stochastic, Complex domain; run as a capped probe in parallel with Steps 1 to 3). Budget: one session, stop after 100 questions. Acceptance test (write first): metric is factual claims containing an error; baseline is the model with no changes; pass threshold is a drop of at least 50%; sample size is 100 questions.

Step 4 MUST NOT report success until the checks in Steps 1 to 3 run on all 100 answers.

## Follow-up

If the user cannot supply documents (A2 false), skip Step 2 and keep Steps 1, 3, and 4. The result degrades to a smaller error reduction; the exact size is unknown [no source].
