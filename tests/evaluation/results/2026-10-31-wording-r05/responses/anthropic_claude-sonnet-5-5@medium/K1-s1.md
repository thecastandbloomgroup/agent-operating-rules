## Headline

Restore the database pool to a size that fits the connection limit, because the cap of 8 connections per pod causes most of the added delay.

- Pool wait grew from 3 ms to 690 ms at p95, which is 88% of the 780 ms rise (A to B) [2].
- Query and serialize spans did not change, so the ORM change is not the main cause [2].
- The shorter cache TTL raised the miss rate from 12% to 31%, which adds load [2].
- The new connection limit in OPS-412 is unknown, so the new pool size needs one lookup first [3].

## Background

The p95 latency of GET /customers/{id}/orders rose from 120 ms to 900 ms after release 2026.10.21. The release cut the pool size from 50 to 8, cut the acquire timeout from 30 s to 5 s, cut the cache TTL from 300 s to 60 s, and added eager loading of order lines [3]. Each pod runs 8 worker threads [3].

## Relevance

The error rate rose from 0.02% to 0.40%, and 96% of the errors are pool timeouts [2]. Users now get 503 responses after 5 s [1].
