### What to measure

Use the ticket record as the source of truth. Treat these severity levels as proposed policy, not measured facts. [judgment]

| Severity | Definition | Example |
|---|---|---|
| Critical | An error creates a privacy, security, or serious customer-harm risk. | The summary exposes another customer’s details. |
| Major | A noncritical error changes the agent’s next action. | The summary invents a refund promise or omits an unresolved blocker. |
| Minor | An error does not change the next action or create material risk. | The summary repeats a detail. |
| None | The reviewer finds no error. | All required facts match the ticket. |

Assign each summary its **highest severity**, so the categories do not overlap.

Track these measures:

- **Critical-error rate:** summaries with a critical error divided by all reviewed summaries.
- **Major-error rate:** summaries classified as major divided by all reviewed summaries.
- **Correction time:** seconds an agent needs to make a summary acceptable.
- **Use rate:** accepted summaries divided by summaries shown to agents.

Also record ticket type, input length, missing messages, model version, prompt version, and source access. These fields support analysis of where errors cluster. [judgment]

For each error, record the first failed stage: source record, context selection, summary generation, or display. Use “unresolved” when evidence cannot locate it.
