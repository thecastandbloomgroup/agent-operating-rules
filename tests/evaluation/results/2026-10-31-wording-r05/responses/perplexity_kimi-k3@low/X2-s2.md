## Headline

Retrospectives stall when they produce discussion instead of owned, timeboxed actions, so the fix is to shrink the format around follow-through.

- Retros fail when actions have no owner or date, not when people lack honesty [inference].
- The fastest fix is to audit the last three retros for action completion, which most teams never measure [judgment].
- A capped probe of a fixed follow-through format for three sprints tests the fix without a process overhaul.

## Background

The team's retrospectives happen but produce no change. Attendance is fine; outcomes are absent. This is a common failure pattern in agile teams [5].

## Relevance

A retrospective that changes nothing costs 60 to 90 minutes per sprint per person (typical sprint ceremony sizing, [judgment]) and teaches people the ceremony is theater. Fixing it restores the main feedback loop the team has.

## Information

No session data, team size, or current retro format was provided. The analysis therefore rests on stated assumptions plus established facilitation practice.

Assumption log:

- A1. The team runs a standard format (for example, "what went well / what didn't") with action items captured somewhere. Why not measured: the material does not state it. Validate by: review the notes of the last three retros. If wrong: adapt the probe format, the diagnosis still holds.
- A2. Action items from past retros mostly lack owners and completion dates. Why not measured: no tool can reach it in this session. Validate by: the 15-minute audit in Step 1. If wrong: the problem is action quality, and Step 2 becomes the first priority.
- A3. The team still trusts the process enough to try a new format. Why not measured: measuring costs more than the decision is worth for a first probe. Validate by: ask in the next retro opening round. If wrong: run a one-off trust repair session first.

Alternative considered: replace retros entirely with continuous async feedback. It loses because an absent completion loop would carry over to the new channel, and the audit (Step 1) can confirm the real cause in 15 minutes [judgment].

Confidence: likely (66 to 100%) that missing action follow-through is the primary cause, based on facilitation practice literature [5] plus judgment, not session data.

## End

I recommend that we run the following steps:

1. Audit the last three retros in one 15-minute session. List every action item, its owner, its due date, and whether it shipped. This removes the blocker of working from guesses about why changes stall. Domain: Clear, because counting completed actions is a known, mechanical procedure. Test (deterministic): Given the notes of the last three retros, when each action is scored for owner, date, and shipped status, then a table exists showing completion rate per retro.

2. Cap retro actions at one per retro, each with a named owner and a due date inside the sprint. This adds the capability of focused follow-through instead of a list nobody reads. Domain: Clear, because single-action discipline is an established facilitation practice [5]. Test (deterministic): Given the next retro, when it closes, then exactly one action exists with an owner and a date, recorded where the team works.

3. Open each retro with a 5-minute review of the previous single action. This removes the blocker of actions vanishing between sprints. Step 3 MUST NOT start until Step 2 has run once. Domain: Clear, because closing the loop is a fixed routine, not an experiment.

4. Run this format as a probe for three sprints, then decide. Metric: percentage of retro actions shipped; baseline: the completion rate from Step 1; pass threshold: at least 2 of 3 actions shipped; sample size: 3 retros. Domain: Complex, because cause and effect in team behavior appear only afterward, so the probe is capped at three sprints with a stop condition (revert to diagnosis if zero ship). This step runs in parallel with Steps 2 and 3, since they are its material.

Test written first for each step, per the classifications above.

## Follow-up

Condition that changes the recommendation: if A2 is false (actions already have owners and dates), replace Step 2 with raising action quality, for example, requiring each action to name a process change, not a person.
