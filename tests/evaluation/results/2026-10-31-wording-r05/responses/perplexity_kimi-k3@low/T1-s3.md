## Headline

Adopt one enforced auto-formatter and a decision protocol, then run a two-week pilot; this removes the formatting debate from human reviews instead of trying to win it. Formatting fights are a symptom of a missing shared standard, not of bad teammates. Automation, not consensus, is what ends them [1].

## Background

The team cannot agree on SQL formatting, and the disagreement costs time in every review. The request is to fix the underlying team dynamic, so the work is partly social, not only technical.

## Relevance

Left alone, formatting disputes consume review effort that belongs on logic and correctness. Resolving them once frees every future review.

## Information

Evidence:

- Automated formatting has ended style debates in engineering teams since gofmt shipped in 2013 [1] [no source; inference].
- Teams argue about preferences like casing and comma placement because there is no objective baseline; when a machine owns the baseline, the argument ends [judgment].
- A review culture failure caused by one formatting topic is a Complex-domain problem: cause and effect in team habits appear only after change, so probes beat mandates [2].

Assumption log:

A1. The team's SQL dialect has a capable formatter (for example, sqlfluff or a dialect-specific tool). Why not measured: the material does not state the dialect or toolchain. Validate by: run two formatters on five real queries, one working session. If wrong: build a linter rule set with a custom style config instead.
A2. Review friction comes from formatting preference, not from a deeper disagreement about code quality. Why not measured: the user has not answered. Validate by: two-minute anonymous pulse poll with one question. If wrong: the pilot scope changes to review norms in general.
A3. The team can access and run shared tooling in CI. Why not measured: no tool has reached the environment. Validate by: check whether a CI pipeline exists and can run a new job. If wrong: enforce in a pre-commit hook instead.

Alternative considered: decide a style guide by team vote and enforce it by code review. It loses because it keeps humans as the enforcement mechanism, which preserves the same negotiation that caused the friction. Automation removes the negotiation itself [judgment].
