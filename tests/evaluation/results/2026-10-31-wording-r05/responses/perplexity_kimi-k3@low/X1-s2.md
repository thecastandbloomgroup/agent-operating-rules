# Headline

You cannot fix "sometimes wrong" without measuring it first, so the priority is a small evaluation loop before any prompt or model change. Three supporting points: build a 50-case test set from real tickets, score the summariser against it to find the error types, then fix the dominant failure and re-measure.

# Background

A support tool now uses an LLM to summarise tickets. Agents report errors, but there is no quantified feedback. The request is to improve the feature.
