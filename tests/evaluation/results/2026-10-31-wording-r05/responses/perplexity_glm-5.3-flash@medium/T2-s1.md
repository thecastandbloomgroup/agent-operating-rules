## Headline

No prompt stops hallucination completely. The best prompt forces the model to quote its source and refuse missing facts. Add a second check pass to cut the remaining errors.

- A prompt that requires a quote before each answer removes most unsupported claims.
- A refusal rule ("Not in the material") removes guessed facts better than a rule like "be accurate".
- A second pass that checks claims against the material catches what the first pass still leaves in [judgment].

## Background

The request asks for one prompt that makes a model stop hallucinating. Hallucination here means a factual answer with no support in the input material.

## Relevance

Hallucinated facts damage trust and decisions in any use of the output. A prompt change costs minutes, so it is the cheapest first step.

## Information

**Why one prompt is not enough.** A survey of mitigation methods reports residual errors for every known technique, including instructions [1]. A measurement on GPT-4o found about 2% wrong factual answers even when the model was allowed to abstain [2]. Therefore the realistic goal is a large cut, not zero. High confidence in this: two independent sources and a clear mechanism, because the model generates text, it does not check it.

**The prompt.** Use this as the system prompt:

```text
Answer only from the material in this conversation.
Before you state a fact, find the sentence in the material that supports it.
If you find the sentence, answer in this order:
1. Source: <quote the sentence>
2. Answer: <your answer>
If you cannot find the sentence, write only: Not in the material.
Then list the facts that are missing.
Do not guess numbers, names, dates, or citations.
If outside knowledge is the only way to answer, start the line
with: [outside knowledge].
```

**Why this design.** Three rules carry the effect, and they do not overlap. First, the quote rule makes each claim traceable, so you can check it. Second, the refusal rule gives the model a safe default when the material is empty. Third, the label rule keeps useful answers instead of forcing silence. Surveys of prompt fixes report that traceable output plus abstention reduces, but does not remove, errors [1].

**Assumption log.**

- A1. The user works with a chat model that takes a system prompt. Why not measured: the material does not state the setup. Validate by: name the product. If wrong: move Step 1 to the tool's equivalent field.
- A2. The task tolerates a refusal when facts are missing. Why not measured: the material does not state the task. Validate by: check whether every question needs an answer. If wrong: keep the `[outside knowledge]` label and drop the refusal line.

**Alternative considered.** Retrieval or fine-tuning instead of a prompt. It loses for this request because the user asked for a prompt, and a prompt change costs one session while retrieval adds infrastructure [judgment].

## End

I recommend that we apply four steps. Run them in order, with Steps 1 to 3 as capped probes; a model change shows its effect only after a test.

1. **Add the prompt above as the system prompt.** It adds the capability to refuse instead of guess. Type: stochastic. Test first, with 30 saved questions: 20 with answers in the material, 10 without. Baseline: current rate of unsupported claims. Pass: at least 27 of 30 outputs correct. Cynefin: Complex, because prompt-to-behavior cause and effect is visible only after a run.
2. **Score one answer type at a time.** Pick the most common question type. It removes the blocker of mixed error types, which hide individual rule failures. Type: evaluative. Rubric first: each output scores 1 point per rule met (quote, refusal, label), pass threshold 90%, evidence is the output text. Cynefin: Complicated, because scoring against a fixed rubric is a knowable analysis.
3. **Add a second pass prompt** that reads the answer and the material, and deletes or flags every claim without a quote. It removes residual unsupported claims. Type: stochastic. Test: rerun the same 30 questions, pass at 30 of 30 correct. Cynefin: Complex, because the check layer affects generation only through observed runs.
4. **Stop and escalate if the error rate stays above 1 in 30.** Replace the prompt-only setup with a retrieval step or a tool that returns source text. This step MUST NOT start until Step 3 ends above the threshold. Type: deterministic (the decision rule). Test: Given the Step 3 score, When it is at most 29 of 30, Then run Step 4. Cynefin: Clear, because the threshold maps to one known next action.

## Follow-up

- Condition that changes the recommendation: if the task needs synthesis across many documents, replace the quote rule with a rule that lists each document before each claim.
- Condition that changes the recommendation: if the model exposes no system prompt field, put these rules as the first user message; expect a smaller effect, because user messages have weaker weight [2].
