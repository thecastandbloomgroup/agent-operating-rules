## Headline

The disagreement is a tooling gap, not a culture problem: adopt one SQL formatter, enforce it in CI, and remove formatting from human review. The program runs in five parts: (1) one config, decided once by rubric, becomes the single source of truth; (2) a CI gate makes the format decision outside human control; (3) a saved-format hook removes the memory burden; (4) the review guide drops format items; (5) a small probe measures whether review friction falls.

## Background

The team debates SQL style in every code review. The request asks to fix the culture. Repeated identical comments point to a missing process rule, not a value conflict.

## Relevance

Every review now spends time on style instead of logic. The fix touches one config file, so the team can stop the cost this week.

## Information

**Evidence**

- SQLFluff is a configurable SQL formatter and linter for many SQL dialects, and it rewrites files with "sqlfluff fix" [1]. Style stops depending on author habits because the tool owns it.
- Baseline comparison: today each reviewer applies a personal standard, so each pull request reopens the debate [judgment].
- Theme: one source case, "friction in every review", supports a process-gap reading; no source in the material supports a values-conflict reading [judgment].

## End

1. **Decide the config values in one timeboxed session (30 minutes).** Increment: a one-page rubric that ranks the choices sqlfluff leaves open: dialect, keyword case, line length, join style. Criteria: diff noise (0.4), readability (0.4), tool support (0.2); pass threshold 70%; evidence: three sample formatted files. Blocker removed: the debate moves to one session instead of every review. Rubric first, then score [judgment]. Evaluative, because more than one good config exists, so analysis picks it. 2. **Adopt sqlfluff with the Step 1 config and gate merges on it.** Increment: one committed config file plus one CI job that fails on "sqlfluff lint" errors. Blocker removed: unformatted code can no longer reach reviewers. Test (write before the work): Given a file formatted after "sqlfluff fix", When CI runs, Then the merge is not blocked; and Given a file with a format error, When CI runs, Then the merge is blocked [14]. 3. **Enable format-on-save or a pre-commit hook for editors.** Increment: one hook file. Blocker removed: developers forget to run the formatter. Test: Given a staged SQL file, When a developer commits, Then the hook applies "sqlfluff fix" and exits clean. Deterministic. Cynefin **Clear**: the tool ships this pattern [1].
4. **Update the review guide and pull request template.** Increment: delete format items; state that review covers logic, schema change risk, and query plans. Blocker removed: reviewers keep flagging style out of habit. Test: Given the new guide, When a reviewer opens it, Then it contains no format rule. Deterministic.
