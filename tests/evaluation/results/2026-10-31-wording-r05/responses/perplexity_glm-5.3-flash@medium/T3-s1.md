# Background

On November 1, 2026, the auth service stores sessions. The request names two goals: replace sessions with JSON Web Tokens, and raise sign-up completion. A JSON Web Token (JWT) is a signed token that carries claims the server verifies without a session lookup.

# Relevance

Token design gates every later service change, and a wrong design is costly to reverse. Conversion changes pay back only when measured against a baseline number.

# Information

Key facts that drive the plan:

1. A JWT verifies with a signature alone, so stateless verification needs no session store [1].
2. Sessions live in a server-side store, and that store makes logout and forced expiry possible [2].
3. A stateless JWT cannot be revoked before it expires. The guide pattern is a short access token plus a revocable refresh token [3].
4. The token switch alone will not raise sign-up rate, because tokens are issued after sign-up completes. Confidence: high, from position in the funnel [judgment].
