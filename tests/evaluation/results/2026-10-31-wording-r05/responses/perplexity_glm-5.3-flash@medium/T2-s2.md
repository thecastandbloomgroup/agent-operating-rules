## Headline

No prompt can make a model fully stop hallucinating, because hallucination follows from how language models generate text. The best prompt cuts the error rate, labels uncertainty, and demands sources. Prompt effects vary by task and model, so the prompt must be measured against a baseline. High-stakes facts still need a check outside the prompt.

## Background

The request asks for one prompt that stops model hallucination. The answer below gives two prompt variants and a way to test which one wins.

## Relevance

Hallucinated output reads as fluent and true, so it can mislead a decision the moment it is trusted. [judgment]

## Information

Language model surveys classify hallucination causes as data errors, training flaws, and generation steps that favor fluent text over true text. [1]

The same surveys list prompt-only methods as partial mitigations, not full fixes. [2]

Therefore a claim that "no prompt removes all errors" follows from this taxonomy. [inference, from [1] and [2]]

For each claim the recommendation depends on, the source type check: both surveys are secondary sources, so the driving claims carry a tertiary-free, secondary basis only if the primary records are unpublished benchmark logs; the surveys themselves are the best reachable source here. [1] [2]

**Prompt variant A, chat without documents:**

```
Answer from what you know.
Before each main fact, write your confidence as: high, medium, or low.
When your confidence is low, write: I am not sure; verify this.
Do not invent names, numbers, or sources.
If you do not know, write: I do not know.
```

**Prompt variant B, with documents in context:**

```
Answer from the documents only.
After each fact, cite the section that supports it.
If the documents do not answer the question, write: The documents do not answer this.
Do not add outside facts.
If you add outside facts by mistake, the user may reject the answer.
```

Prompt changes act on model output whose cause and effect show per run only. So prompt work is a Complex problem in the Cynefin sense, and each variant needs a measure and a stop condition. [3]

**Assumption log**

A1. The target is a chat assistant in a domain without answers I can check today. Why not measured: the material does not state the model, task, or answers to check. Validate by: build the test set in step 1 with the user's real questions. If wrong: use variant B, because attached documents allow citation checks.

A2. The user can produce at least 50 questions with known answers. Why not measured: no tool in this session can reach that list. Validate by: count the questions in step 1. If wrong: run 20 questions and state the smaller sample in the result.

**Alternative considered**

Replace the prompt with a retrieval system that cites sources; it loses for this request, because it needs engineering work that a one-prompt request does not include. [judgment]
