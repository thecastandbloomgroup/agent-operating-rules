## Headline

There is no single prompt that stops hallucination; the best prompt is a grounding prompt that requires sources and allows "unknown", and it works only when paired with a spot-check test.

- Hallucination is when a model states made-up facts with a confident tone. Surveys of text generation name missing source access as a main cause [S1].
- Prompts that add retrieval and citation duties reduce unsupported statements in measured trials [S2].
- A prompt cannot check its own output, so a test set must measure the false-answer rate before and after the change.

## BRIEF

**Background**: The request asks for the best prompt to make a model stop stating made-up facts. The request names no product, task, or current prompt.

**Relevance**: Made-up facts break trust and can spread errors into conclusions. A prompt change is the cheapest first step, and a measured rate shows whether it worked.

**Information**:

Evidence and analysis:

1. Cause. A model generates one token at a time from its training weights. When the facts are not in the prompt context, the model must supply them from memory [S1].
2. Prompt effects. A prompt with three parts reduces this risk: (a) require a source for each claim, (b) require the exact words "unknown" when the answer is not in the material, (c) ban invented numbers, names, and quotes. Retrieval plus citation also lowered unsupported speech in a measured dialogue study [S2].
3. Verification gap. No prompt can prove that a statement is true. Only a test with known answers can measure the rate of false claims. Therefore a prompt change is a probe, not a fix [inference].
4. Uncertainty. The prompt template is likely (66 to 100%) to reduce the false-answer rate, with the basis "consistent with retrieval and citation studies" [S2]. The size of the drop is unknown for any single product, so the spot-check must measure it.

Assumption log:

- A1. The user works with a general-purpose chat model or app. Why not measured: the request does not state the product. Validate by: check the product name or ask. If wrong: the template needs task-specific fields.
- A2. The task is general question answering, not medical, legal, or financial advice. Why not measured: the user has not answered. Validate by: ask the user one question. If wrong: a prompt alone is not a defensible control; add retrieval and human review first.
- A3. The user can run a 20-question test in one session. Why not measured: the user's tooling is unknown. Validate by: ask how answers get generated and checked. If wrong: cut the set to 5 questions.

Alternative considered: fine-tuning a model or building a retrieval pipeline gives a lower error rate at scale, but it costs hours of work and a data set. The prompt template wins on cost for a first change [inference].

**End**: I recommend that we take four steps, in this order.

1. Write the grounded-prompt template: three required parts (source per claim, "unknown" rule, ban on invented numbers and quotes), plus any product-specific fields. Blocker removed: the model currently has no permission to say "unknown", so it invents answers. Test (deterministic, Gherkin): Given the template text, When a reviewer reads it, Then each of the three required parts appears with its exact rule text. Domain: Clear, because a known best practice from published studies is being applied [S2].
2. Build the spot-check set: 20 questions with one verifiable answer and one source each. Blocker removed: there is no way to measure the current error rate. Test (deterministic, Gherkin): Given the answer key, When each of 20 items is checked, Then it has one answer and one source the checker can open. Domain: Complicated, because picking questions that cover the task needs analysis. This step MUST finish before Step 3.
3. Run the set twice: once with the old prompt, once with the new prompt, and count false claims in each run. Metric: false-claim rate. Baseline: the old-prompt run. Pass threshold: the new-prompt rate is at most half the baseline rate. Sample size: 20 items (so rates move in steps of 5%). Domain: Complex, because model output varies from run to run, so the action is a capped probe: budget one session, stop when both runs finish. Leverage is a guess until both rates are measured [inference].
4. If the new rate stays above 2 of 20, add retrieval with citations to the prompt instead of relying on the model's memory. Blocker removed: prompt-only grounding fails with a high rate because the facts are absent from the model's memory [S1]. Test (evaluative, rubric first): criteria = answer correctness, citation presence, setup cost; weights = correctness 50%, citation 30%, cost 20%; pass threshold = 70%; evidence = the Step 3 run of the shortlisted tool. Domain: Complicated, because choosing a tool needs a scored comparison.

Condition that changes this plan: if A2 is wrong and the task is regulated advice, add human review of every answer before Step 3 runs on real questions, and treat the prompt as a draft.

**Follow-up**:

Conditions: if the model output changes format between runs, log the format break and rerun Step 3 before comparing rates.
