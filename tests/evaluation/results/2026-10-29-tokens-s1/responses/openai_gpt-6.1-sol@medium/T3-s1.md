## Relevance

Authentication changes can affect access control, while sign-up changes affect how users create accounts. Therefore, each workstream needs its own acceptance tests. [judgment]

## Information

**Security scope.** JSON Web Tokens (JWTs) carry claims between parties; they do not define a complete replacement for session management. [2]

The migration must address token validation, client storage, expiry, renewal, logout, and account changes. [judgment] JWT security guidance requires explicit validation rules, including allowed algorithms and intended recipients. [3]

**Conversion scope.** Start with a funnel from sign-up start to completed account creation. Select changes from observed losses, rather than removing verification or other safeguards without evidence. [judgment]

**Assumption log**

A1. Conversion means completed accounts divided by sign-up starts. Why not measured: The material does not state it. Validate by: Check the existing metric definition. If wrong: Change the funnel endpoint.

A2. Existing security guarantees remain required. Why not measured: The material does not state them. Validate by: Review current authentication tests and policy. If wrong: Record approved changes before implementation.

**Alternative considered.** Change token handling and sign-up screens together. This loses because it makes conversion changes harder to attribute and expands the rollback scope. [judgment]

**Confidence:** High confidence in separating acceptance tests, because the requested outcomes differ; low confidence in implementation choices without service details. [judgment]
