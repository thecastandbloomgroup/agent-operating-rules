Background
The support tool now writes a short summary with a large language model (LLM), which generates text from a prompt. Agents say the summary is sometimes wrong, and there is no error count. You asked to make the tool better.

Relevance
A wrong summary can point an agent at the wrong fix. Therefore the next change needs a score, or a new prompt can miss the same errors.

Information
This section covers the evidence, the assumptions, and the alternative.

SummEval treats consistency as factual fit with the source, separate from fluency and relevance.
[1]
Therefore a fluency check does not show that a summary is right.

Abstractive summaries can state content the source does not support.
[2]
So the first score is faithfulness. Faithfulness means each claim has support in the source text.

No sample states your error share. Confidence is low, because no labeled sample exists. A prompt change with no labels is about as likely as not (33 to 66%) to reduce the main error. [judgment]

A1. The input is a support thread and the output is a short agent brief. Why not measured: the material does not state it. Validate by: open one saved summary and its source. If wrong: point Step 1 at the real input and output.

A2. The harm is an unsupported claim or a missing fact the agent needs. Why not measured: the material does not state it. Validate by: the tag counts in Step 1. If wrong: move rubric weight to the tag with the most cases.

A3. Two people can label 40 cases in one working session. Why not measured: the material has no staffing data. Validate by: time five labels, then scale the count. If wrong: use 20 cases and keep the same pass rule.

A4. The live model call uses one fixed temperature. Why not measured: the material does not state it. Validate by: read the model call config. If wrong: run Step 4 at the live setting.

Rewrite the prompt now and ask agents which text they prefer. This loses because there is no baseline, so a new error can hide inside a nicer tone. [judgment]

End
I recommend that we run four actions in the order below.

Domain labels follow. Confused means the right fix is not yet known. Complicated means analysis picks the fix. Clear means a known practice applies. Complex means a small test shows the result.

Step 1. Domain: Confused. This step gathers the facts that classify the work.
Test first. Rubric: four tags of equal weight, unsupported claim, missing action fact, wrong party or product, and other. Pass threshold: both raters share one primary tag on at least 32 of 40 cases. Evidence: the source thread and the saved summary.
Increment: label 40 closed cases from the last 30 days. Blocker removed: the unknown error type.

Step 2. Domain: Complicated. The score split picks the later fix. Step 2 MUST NOT start until the Step 1 test passes.
Test first. Rubric: claim-support share weight 70 percent, required-fact share weight 30 percent. Pass threshold: all 40 cases have both scores, and a 10-case overlap has at least 80 percent rater agreement. Evidence: a source span for each supported claim, plus the required-fact list.
Increment: one score sheet with the mean claim-support share. Blocker removed: no numeric baseline.
Claim-support share is the share of claims linked to a source span. Required facts are the facts an agent needs for the next action.

Step 3. Domain: Clear. Step 3 MAY run in parallel with Step 2. It MUST NOT change the prompt.

Step 4. Domain: Complex. Leverage is a guess. Budget: one session and two variants. Step 4 MUST NOT start until Step 2 records the baseline. Do not ship the winner to all agents in this step.
Test first. Metric: mean claim-support share. Baseline: the Step 2 mean. Pass threshold: at least 0.05 higher than that mean. Sample size: the same 40 cases, one run each.
Increment: change only the largest Step 1 tag. Blocker removed: an untested prompt change.
Stop if the mean does not rise by 0.05, and discard that variant. If the largest tag is an unsupported claim, require a source span after each claim. If it is a missing action fact, add a required-fact list. If it is the wrong party or product, copy names only from the source.
