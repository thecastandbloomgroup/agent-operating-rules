## Headline

Make the summariser measurable first, then fix the largest source of error, then gate it with a quality threshold. Agent feedback of "sometimes wrong" cannot guide fixes because it has no error rate or error type. A labelled set of 200 real conversations gives a baseline within one week. ## Background

You added a language-model summariser to a support tool. Agents report it is "sometimes wrong", and no metrics exist yet. You asked how to make it better.

## Relevance

Without a baseline, any change can reduce quality while looking better in demos. A measured error rate turns agent complaints into a fixable, testable problem.
