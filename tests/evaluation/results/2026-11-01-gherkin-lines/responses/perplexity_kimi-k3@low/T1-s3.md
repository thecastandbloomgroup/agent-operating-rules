## Headline

The fix is one enforced formatter plus one written decision record, so that reviews cover logic, not layout.

- The team lacks a shared standard, not better arguments [judgment].
- A tool enforces the standard without human effort [1].
- A written record prevents the debate from reopening each review [judgment].
- People follow tools they chose once more than rules imposed forever [judgment].

## Background

Team members disagree on SQL formatting. Every review contains formatting disputes. The request is to end the friction.

## Relevance

Review time spent on formatting is time not spent on defects. A settled standard removes this cost in every future review.

## Information

**Assumption log**

A1. The team uses one or two SQL dialects. Why not measured: the material does not state it. Validate by: list dialects in the first meeting. If wrong: pick one ruleset per dialect, no other change.

A2. A continuous integration pipeline exists. Why not measured: the material does not state it. Validate by: check for a CI config file in the repository. If wrong: run the linter as a pre-commit hook instead.

A3. The team will accept a tool over manual rules. Why not measured: the user has not answered. Validate by: the vote in Step 1. If wrong: the friction persists; revisit with the vote data.

**Alternative considered.** Write a manual style guide and enforce it in review comments. It loses because humans apply rules inconsistently, while a formatter applies them identically every run [1].

Tool choice: SQLFluff is an open source SQL linter and formatter with autofix and rule configuration [1]. A published community style guide exists as a base for debate points [2]. Adoption certainty: high confidence, because convention-by-tool removes recurring judgment calls [judgment].

## End

I recommend that we take four actions.

1. **Decide once, in one meeting.** Evaluative, Complicated domain, because the choice needs analysis, not research. Rubric: readability 40%, diff noise 30%, tool support 30%; threshold 70 points; evidence is one formatted sample per option. Score each option, record the winner in a one-page decision record in the repository.
2. **Configure the formatter.** Deterministic, Clear domain, because a known best practice exists. Depends on Step 1. Write a SQLFluff config matching the winning option. Test first:
   - Given a SQL file that breaks the chosen rules,
   - When the linter runs,
   - Then it reports the violations, and `--fix` rewrites the file to pass.
3. **Block merges on style.** Deterministic, Clear domain. Depends on Step 2. Add the lint check to CI so reviews stop citing formatting. Test first: a pull request with a violation fails the check; a clean one passes.
4. **Probe the culture result.** Stochastic, Complex domain, because team response is visible only afterward. Metric: formatting comments per review. Baseline: count from the last four weeks. Threshold: under 0.5 per review across 20 reviews. Budget: two sprints. Stop condition: if the count fails to fall, hold one retrospective and adjust the rules, not the tool.

## Follow-up
