## Information

### What to measure

Use three distinct defect classes. These are proposed definitions, not observed findings. [judgment]

| Defect | Definition | Example |
|---|---|---|
| Contradicted detail | The summary conflicts with the ticket. | “Refund approved” when the agent refused it. |
| Unsupported detail | The ticket neither supports nor contradicts the claim. | An invented delivery date. |
| Missing required detail | The summary omits a fact required by the support workflow. | An unresolved customer request. |

Mark severity separately. Treat errors about money, account access, promised actions, or case resolution as severe until the team approves narrower rules. [judgment]

Record each defect rate as **summaries with that defect ÷ summaries reviewed**. A summary can contain multiple defects.

Also record **severe-error rate** and **agent edit time per summary**. Compare each candidate with the current version on identical tickets. [judgment]

Do not treat agent approval as proof of accuracy. The reference should come from the ticket itself. [judgment]

**Kind:** Stochastic, because generated summaries vary.

### 3. Test one fix against the baseline

**Kind:** Stochastic.  
**Domain:** Complex, because the effect of a prompt, context, or model change requires a controlled probe.

**Acceptance test first:**

- **Metrics:** Overall defective-summary rate, severe-error count, missing-detail rate, and median edit time.
- **Baseline:** Saved current-version results from Step 2.
- **Sample:** The same 50 tickets, with candidate identity hidden from reviewers.
- **Pass threshold:** At least 50% fewer defective summaries and zero severe errors.
- **Guardrails:** Missing-detail rate and median edit time must not exceed baseline.
- **Budget:** One candidate and four working hours.
- **Stop condition:** Reject the candidate after any severe error.

**Increment:** Change only the cause supported by the baseline’s highest-priority defect.

For example, fix absent ticket context before changing the model.
If context is complete, test a source-linked summary template or another evidence-supported change.

**Blocker removed:** The team can distinguish a measured improvement from a persuasive demonstration.

Step 3 MUST NOT start until Step 2 passes.
If the baseline has zero defects, use a fresh sample rather than claim improvement.
