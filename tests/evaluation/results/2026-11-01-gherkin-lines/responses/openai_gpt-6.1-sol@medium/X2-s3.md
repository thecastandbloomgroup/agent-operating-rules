## Information

The Agile Manifesto pairs team reflection with an adjustment to behavior, rather than reflection alone. [2] That supports a focus on what happens after the meeting.

**Working diagnosis:** Low confidence about the cause, because the available evidence describes attendance and results, not the steps between them.

## End

I recommend that we take these three steps:

### 1. Trace the latest three retrospective actions

**Test first, deterministic:**
```text
Given the latest three agreed actions, or all available actions
When the team checks each action
Then each has a recorded owner, deadline, implementation status, and result
And each missing fact is marked unknown
```

Spend 20 minutes checking the records together. If no actions exist, record that finding instead.

Mark the first missing link for each action. Use the most common missing link to choose the next intervention. If records are missing, first restore a visible action record.

**Output:** One short action trail that removes uncertainty about where progress stops.

**Domain: Complicated**, because the team must inspect the action trail before choosing a response.

### 2. Create one change card, not another action list

Step 2 MUST NOT start until Step 1 passes.

**Test first, deterministic:**
```text
Given the most common missing link
When the team chooses its next change
Then one card names the change, owner, deadline, measure, and review date
And the owner confirms authority and time to act
```

Spend 15 minutes creating that card. Choose a change small enough to start during the meeting and complete within two weeks. [judgment]

Use the diagnosis to select it:

- **No agreed action:** Convert one recurring complaint into a specific change.
- **No owner or time:** Assign an owner and reserve work time.
- **An external dependency:** Name one decision-maker and request one specific decision.
- **Completed action without benefit:** Replace it with a measurable trial.

**Output:** One feasible commitment that removes the next known blocker.

**Domain: Clear**, because the card has fixed, observable requirements.

### 3. Run a bounded trial and review the result

Step 3 MUST NOT start until Step 2 passes.

**Acceptance test first, stochastic, meaning results can vary:**

- **Metric:** Use the outcome measure named on the card.
- **Baseline:** Record the preceding five comparable cases.
- **Pass threshold:** Set a numeric target before the trial starts.
- **Sample:** Compare the next five comparable cases with that baseline.
- **Acceptance:** Keep the change only if it reaches the target without exceeding the agreed cost.

Cap the trial at two weeks and one hour of extra team effort. Stop earlier if it causes harm or exceeds that budget. If five cases do not occur, record insufficient evidence rather than success.

**Output:** One keep, revise, or stop decision at the next retrospective.

**Domain: Complex**, because the effect becomes visible through the trial. Its value is uncertain; five cases provide a local signal, not statistical proof. [judgment]
