## Background

The request combines an auth migration with a sign-up conversion goal. [1] No repository, security requirements, or sign-up data accompanies the request.

## Relevance

A JWT migration changes how the service accepts credentials; it does not establish which sign-up changes improve conversion. [judgment] Therefore, use separate acceptance tests for security and conversion. [judgment]

## Information

**Security evidence.** JWT guidance requires explicit controls for algorithms, keys, and token validation. [2] These controls belong in the migration contract, not just the token creation code. [judgment]

**Conversion evidence.** The supplied material contains no funnel counts, failure rates, or conversion baseline. [1] Therefore, no specific interface change has enough evidence for selection. [judgment]

**Assumption log**

A1. Measure the existing sign-up path before changing it. Why not measured: No tool can reach it. Validate by: Inspect existing funnel reports. If wrong: Use those reports instead of adding measurement.

**Alternative considered.** Replace sessions and redesign sign-up in one release. This loses because separate releases make failures easier to trace and reverse. [judgment]

**Confidence:** High confidence in separating the work, because the two goals require different acceptance evidence. [judgment]
