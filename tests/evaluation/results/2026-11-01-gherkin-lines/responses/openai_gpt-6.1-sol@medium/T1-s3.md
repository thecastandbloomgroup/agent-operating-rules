## End

I recommend that we take these three steps:

### 1. Publish a one-page working agreement

**Test first, deterministic:**

```gherkin
Given a review comment concerns only personal format preference
When the author follows the agreed format rules
Then that comment does not block the change
```

In one 30-minute team session, write the agreement and name one accountable owner.

Include these rules:

- The owner decides unresolved format choices after everyone has a chance to object.
- Reviewers distinguish required changes from optional suggestions.
- Authors can challenge rules without defending their competence.
- Rule changes happen outside active reviews.
- Exceptions require a reason, not seniority.

Record unresolved objections without requiring unanimous enthusiasm. This removes repeated debate about decision authority. [judgment]

**Domain: Clear**, because the output is a written agreement with explicit acceptance criteria. Publication completes the step only when the test matches its wording.

### 2. Automate the agreed format on a small SQL sample

**Test first, deterministic:**

```gherkin
Given representative SQL files and the proposed formatter configuration
When the formatter runs twice
Then the second run produces no additional changes
```

After Step 1 passes, test one formatter that supports the team's SQL dialect in a 60-minute session.

Inspect its changes before adding a shared command and an automated format check. Keep repository-wide reformat changes separate from behavior changes.

This removes manual enforcement of the rules that the tool covers. [judgment]

**Domain: Complicated**, because dialect support and output need technical inspection.

If no suitable formatter passes, retain a minimal written convention and defer automation. Do not expand the style guide to compensate.

### 3. Run a limited review trial

**Acceptance test first, stochastic:** Review outcomes vary across authors and changes.

- **Metric:** Share of reviews containing human comments about format alone.
- **Baseline:** Measure the previous 10 SQL reviews.
- **Sample:** Measure the next 10 SQL reviews.
- **Pass threshold:** At most half the baseline rate, with zero changes blocked solely by personal format preference.
- **Evidence:** Classify comments from review records, not recollection.

These thresholds are proposed trial criteria, not measured results. [judgment]

After Step 2 passes, or its fallback applies, run the trial for at most two weeks. Cap extra administration at 60 minutes.

Stop early if the format check rejects valid dialect syntax. If fewer than 10 reviews finish, report insufficient evidence rather than success.

**Domain: Complex**, because team behavior becomes visible through experience. This is a limited experiment; its expected benefit remains a judgment. [judgment]

Adopt the process only after the full sample meets the threshold. Otherwise, inspect the remaining disputes before adding rules.
