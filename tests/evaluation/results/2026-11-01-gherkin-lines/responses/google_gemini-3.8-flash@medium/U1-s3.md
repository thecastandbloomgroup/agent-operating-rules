## Information

This section covers the evidence, assumptions, and alternatives for pipeline remediation.
First, empirical research shows that non-deterministic tests affect sixteen percent of automated tests in large codebases [1].
Because engineers lose trust in failing test gates, they merge unverified pull requests [2].
Intermittent test failures stem from three mutually exclusive causes: concurrency races, shared environment state, and resource limits [judgment].
For example, uncontrolled thread timing causes assertion failures before state updates complete [judgment].
Next, see A1 and A2 for key operational premises.

A1. The build failures originate from software test non-determinism rather than hardware defects. Why not measured: The material does not state it. Validate by: Review the most recent five build failure logs. If wrong: Replace test isolation actions with hardware diagnostic actions.
A2. The continuous integration platform supports test tags and non-blocking pipelines. Why not measured: The material does not state it. Validate by: Inspect repository configuration files for workflow definitions. If wrong: Quarantine tests with branch filters or separate script targets.

Alternative considered: Automatically retry failed builds up to three times without a test quarantine.
However, this alternative loses because retries hide regressions, increase compute costs by up to two hundred percent, and delay merges [judgment].
