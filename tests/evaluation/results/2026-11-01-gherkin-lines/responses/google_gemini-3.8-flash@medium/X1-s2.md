# Headline

Measure summary defects with an agent evaluation rubric before you change prompts or models.
First, a baseline error rate quantifies the reported complaints.
Second, an error taxonomy reveals the root causes of incorrect summaries.
Third, targeted prompt constraints resolve specific failure modes without high engineering costs.

# Background

Support agents report that the new support tool summariser produces incorrect output.
The engineering team currently operates the summariser without quality metrics or automated evaluation.
You requested a plan to improve the quality of the tool.

# Relevance

Unreliable summaries slow ticket resolution and increase agent rework today.
Therefore, establishing quality metrics protects agent trust and directs engineering effort effectively.

# Information

Large language model (LLM) summaries suffer from hallucinations and omission defects without explicit constraints [1].
Agent complaints without error categories indicate an unmeasured system [judgment].
In a support workflow, summary defects fall into three primary error categories: factual inconsistency, omitted details, and extraneous text [2].
Baseline metrics must exist before engineering changes occur, because changes without metrics conceal regression [judgment].

The assumptions for this plan are:
A1. Agents have access to ticket logs to grade past summaries. Why not measured: The material does not state it. Validate by: Inspect agent permissions in the tool. If wrong: Engineering must extract ticket text for external review.
A2. Hallucination of resolution actions causes most agent complaints. Why not measured: The material does not state it. Validate by: Review 30 agent feedback samples. If wrong: Reorder Step 3 to address omission rather than hallucination.

### Alternative considered
Prompt tuning with ad hoc manual reviews was considered.
It loses because manual inspection without a rubric fails to detect silent quality regressions across edge cases [judgment].
