## Headline

Roll back the last change before 09:12 now, then send a status update before the exec call.

- Stop the damage first, because cause and effect are unclear and users fail on every checkout.
- Change is the most likely cause, so the change log is the fastest lead.
- The exec call needs impact, action, and next update time. It does not need a root cause.

## Background

Checkout returns HTTP 500 for every user since 09:12. You are the on-call engineer. The exec call starts in ten minutes.

## Relevance

Each minute of downtime blocks all checkout revenue. The exec call sets the tone for the incident, so a clear status helps you.

A3. The exec call needs status, not a root cause. Why not measured: the user has not answered. Validate by: read the call invite. If wrong: add a cause line in Step 2.

Alternative considered: debug the 500 error first. It loses because the debug time is unbounded, while a rollback takes minutes [judgment].
