## Headline

No single prompt stops hallucination, but a grounding prompt (one that limits answers to source text you supply) cuts it most.

- Wording alone cannot remove false output, because the model predicts text and does not check facts.
- Source text plus a rule to quote it gives the model something to check against.
- A permitted "not found" answer removes the pressure to invent.
- You must test the prompt on your own questions to know its effect.

## Background

Hallucination means the model states something false or unsupported. You asked for the best prompt to stop it. The prompt below is the strongest general form, but it needs source text in the same message.

## Relevance

Without a test, you cannot tell whether the prompt works for your task. A wrong answer that looks sure costs more than a refused answer.

## Information

**The prompt.** Replace the tag content with your documents.

```text
Answer using only the text inside <sources>.
For each claim, quote the exact sentence that supports it.
If the sources do not contain the answer, reply: "Not found in the sources."
Do not use outside knowledge. Do not guess.
If a claim has no quote, delete the claim.

<sources>
...paste documents here...
</sources>

Question: ...
```

**Evidence.**

- Hallucination appears across many text generation tasks, so no wording removes it fully.

  Source: [1]

- Grounding answers in retrieved text improved factual output on knowledge tasks, against a model with no retrieved text.

  Source: [2]

- The size of the gain on your task is unknown. [judgment]
- It is likely (66 to 100%) that the prompt lowers unsupported claims when sources are supplied. Basis: one survey, one study, [judgment].
- It is unlikely (0 to 33%) that the prompt helps much on factual questions when no source text is supplied. [judgment]

**Assumption log.**

A1. You can paste source text or connect a search tool. Why not measured: the material does not state it. Validate by: check whether your documents exist as text. If wrong: Step 3 becomes a request for a search tool.

A2. You use a general chat model, not a tuned one. Why not measured: the material does not state it. Validate by: read the model name in your settings. If wrong: rerun Step 2 on the actual model.

**Alternative considered.** Fine-tune the model on your domain. It loses because it costs far more than one working session, and it still gives no quote to check. [judgment]

## End

I recommend that we:

1. **Build a test set.** Write 30 questions with known answers from your documents. Make 10 of them unanswerable. This removes the blocker that you cannot measure the effect. Kind: deterministic. Cynefin: Complicated, because expertise picks representative questions.

   Test:

   Given a file of 30 questions with an answer key
   When a reviewer checks each question against the documents
   Then every answerable question cites one source sentence and every unanswerable question is marked "none"

2. **Run the prompt as a probe.** Step 2 MUST NOT start until the test in Step 1 passes. Run the question set without the prompt, then with it, three runs each. Kind: stochastic. Cynefin: Complex, because model behavior shows only after the run. Budget: one session. Stop condition: stop if the prompt run shows no drop after the first full pass. Acceptance test, written first: metric is the share of claims with no supporting quote. Baseline is the no-prompt run. Threshold is a 50% relative drop, and unanswerable questions must give "Not found" in at least 9 of 10 cases. Sample size is 30 questions times 3 runs.

3. **Supply sources automatically.** Add a step that pastes or retrieves the right documents before each question. This adds the capability the prompt relies on. Kind: deterministic. Cynefin: Complicated, because you must analyze which retrieval method fits your documents. Run it in parallel with Step 2.

   Test:

   Given a question from the test set
   When the pipeline builds the message
   Then the <sources> block contains the document with the answer

4. **Add a check pass as a probe.** Step 4 MUST NOT start until Step 2 meets its threshold. Send each answer to a second call that confirms every quote appears in the sources. Kind: stochastic. Cynefin: Complex, because the gain is a guess until measured. Budget: one session. Stop condition: stop if the check pass cuts unsupported claims by less than 20% relative to Step 2. Acceptance test, written first: metric is unsupported claims after the check. Baseline is the Step 2 result. Threshold is a 20% further drop. Sample size is 30 questions times 3 runs.

If A1 is false, replace Step 3 with a request for a search tool and keep Steps 1 and 2.
