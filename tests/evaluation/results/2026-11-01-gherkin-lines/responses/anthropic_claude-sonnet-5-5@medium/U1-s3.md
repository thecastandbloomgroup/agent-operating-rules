## Headline

Measure the flake rate first, then quarantine the worst tests and fix their causes.

- The cause is unknown, so data must come before fixes.
- Test code is the usual source of flaky builds, so start there.
- Quarantine protects the team while the fixes proceed.

## Background

The request says the build is flaky. Here, "flaky" means the same code passes and fails on different runs. The message gives no logs, no build tool, and no failure rate.

## Relevance

Flaky builds teach the team to ignore red results. Real defects then pass unnoticed. Each rerun also costs CI time and delays merges.

## Information

**Evidence**

- An empirical study of flaky-test fixes found three leading causes: async wait (45%), concurrency (20%), and test order (12%) [1].
- Test code is therefore the likely source (66 to 100%) [judgment]. Infrastructure is the main alternative.
- The current flake rate is unknown. No baseline exists yet [no source].
