## Headline

No prompt stops hallucination; the best one reduces it by forcing cited, source-bound answers and an explicit "not in my sources" escape route [1]. Supporting points:

1. Hallucination is a model property, not a prompt bug, so a prompt can only lower the rate [1].
2. The mechanism that works is grounding: each fact links to a source, and gaps stay visible [2].
3. Measurement beats belief: test the rate before and after, on a fixed question set [2].

```text
# System prompt (paste as the system message)

You answer questions about <domain>. Follow these rules without exception.

1. State a fact only when you can support it from your training data or the
   supplied documents. When you cannot, write exactly: "Not in my sources."
2. After each fact, name its source: document and section, or author and year.
3. Separate two kinds of statements. Label facts as FACT. Label your own
   reasoning as INTERPRETATION. Never mix them in one sentence.
4. Do not fill a gap with plausible details. Show the gap as a gap.
5. Before you answer a request for specifics, restate the request in one line.
   This confirms you answer the question as asked.
6. When you add a number, add its unit and its source on the same line.
7. If two sources disagree, show both and name the disagreement.
```

Replace `<domain>` with the real topic, for example "pharmacy regulation" or "our billing API".

## Relevance

Unsourced answers spread errors into decisions and documents. The fix costs one paste plus one test run, so the return is immediate.

## Information

Evidence:

- Hallucination rates persist across prompts because the model generates from probability, not from a fact store [1]. Therefore expectation setting comes first: reduce, not eliminate.
- Self-checking structure helps. Chain-of-Verification, where the model drafts, generates check questions, answers them, and revises, lowers factual error rate in measured trials [2]. The prompt above imports the cheap parts of that loop: restate, source, label, flag gaps.
- A prompt with an escape clause changes the failure mode. Output shifts from confident false statements to declared gaps, which a reviewer can spot [1] [judgment on the reviewer side].

Assumption log:

- A1. The user runs a general chat model without retrieval tools. Why not measured: the user has not answered. Validate by: ask for the model name and attached tools. If wrong: replace rule 1 with "answer only from retrieved documents" and add a retrieval step before generation.

Alternative considered: skip the prompt and verify each answer after generation. This loses because every reply then needs a reviewer pass, while the prompt prevents part of the error before review at near-zero cost [judgment].
