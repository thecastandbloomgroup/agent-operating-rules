**Headline**

No prompt stops hallucination, because the errors come from how the model was trained, not from missing instructions.

- Prompt-only fixes reduce the rate of invented facts but leave a large share of errors in place.
- The best known prompt forces answers from supplied material only and makes the model write "I don't know" when the material runs out.
- The rest of the gain comes from measuring the rate and checking each claim, not from better wording.

**Background**

The request asks for one prompt that stops a model from inventing facts. Hallucination here means output that states false or untraceable facts as true. No supplied documents bound this answer, so the reply assumes general assistant and work use [A1].

**Relevance**

Unsupported claims reach decisions, reports, and code without a warning sign. A prompt costs minutes to install, so it is the first control to fix.

**Information**

The evidence comes from two lines of research.

A survey of hallucination research catalogs the mitigation options and reports that none removes the failure mode.

[1]

A later analysis argues that the training and scoring setups reward guessing over abstention, so models tend to produce a plausible answer even when they lack the fact.

[2]

A baseline for ungrounded generation: in a study of six generative search engines, only 51.5% of generated sentences were fully supported by citations, and only 74.5% of citations supported their sentence.

[3]

So the goal is a lower rate, not zero. Unsupported claims will still pass through a prompt-alone fix, and this outcome is very likely (90 to 100%) [judgment].

**The prompt**

```text
You answer only from the material in this message and the earlier conversation.
For each factual claim, add the exact quote or section name that supports it.
If the material does not contain the answer, write exactly: "I don't know from the given material."
Do not guess names, numbers, dates, or events that the material does not state.
If the material is ambiguous, ask up to three questions before you answer.
End with a section named "Not verified" that lists every claim you could not support.
```

The design rule behind it: give the model an observable action for each case. Quoting handles the known case, abstention handles the unknown case, and the "Not verified" section handles the partial case.

**Assumption log**

- A1. The use case is general question answering and work tasks. Why not measured: the user has not answered. Validate by: ask which tasks showed hallucinations. If wrong: the prompt needs domain citation rules instead of quotes.
- A2. The deployment has no retrieval tool in this context. Why not measured: the material does not state it. Validate by: check the platform configuration. If wrong: tool grounding replaces most of Step 4.

**Alternative considered**

An instruction such as "Be accurate and never make things up" is the strongest rival. It loses because it states a goal without a procedure, so the model cannot act on it beyond what it already does [judgment].

**End**

I recommend that we install the prompt above and then measure its effect, in four steps.

1. **Step 1 (deterministic, Clear):** Install the prompt in the system instruction slot. Increment: one edit session. Blocker: answers with no grounding rule. Test:
   ```
   Given a session with the prompt installed
   When the model receives a question outside the supplied material
   Then the reply contains "I don't know from the given material" and no invented names, numbers, or events
   ```
   Domain: Clear, because the abstention pattern is a published practice.

[1]

1. **Step 2 (stochastic, Complicated):** Build 30 test questions: 15 answerable from supplied text, 15 not answerable. Run the model with and without the prompt. Increment: one session. Blocker: no rate data, so all later claims stay guesses. Acceptance test first: metric = share of replies with at least one unsupported claim; baseline = the no-prompt run; pass threshold = a relative drop of 50% or more; sample size = 30. Domain: Complicated, because measurement design and threshold choice need analysis.
2. **Step 3 (evaluative, Complicated):** Add a check pass: for each claim in an output, a reviewer confirms the named quote or section against the material. Increment: one session on three outputs. Blocker: claims that pass the prompt but fail fact check. Rubric first: support weight 0.6, invented-entity count weight 0.2, completeness weight 0.2, pass threshold 0.8 on average. Step 3 waits for the Step 2 baseline. Domain: Complicated, because reviewer judgment picks the verdicts.
3. **Step 4 (stochastic, Complex):** Run only if Step 2 misses the threshold. Supply the source documents with each query and re-run the 30 tests, with a budget of two sessions and a stop condition: stop if the rate does not drop by half. Domain: Complex, because the rate depends on material coverage, which only shows after the run.

If A2 is false, replace Steps 1 and 4 with the platform's retrieval tool and keep Steps 2 and 3 unchanged.

**Follow-up**

Conditions that change the recommendation: a date-bound or niche fact domain, where quoting helps less and Step 4 gains weight; a creative writing task, where abstention rules are the wrong control.
