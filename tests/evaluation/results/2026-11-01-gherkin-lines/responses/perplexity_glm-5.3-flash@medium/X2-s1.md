I recommend including the action status check at the start of each retrospective, one owned action per retrospective, a rubric score of past failures, and a two cycle completion measurement.

Headline

Turn each retrospective into one owned change, and check that change at the start of the next one.

- The cause is likely the missing loop from decision to done work, not attendance.
- Limit each retrospective to one action with one owner and one due date.
- Open every retrospective with the status of the previous action.
- Measure the action completion rate for two cycles before you judge the fix.

Background

The team holds retrospectives on some cadence. People attend. The sessions end without changes to the work.

Relevance

A retrospective costs the whole team one hour or more per cycle [judgment]. That time yields no return while the loop from talk to change stays open.

Information

The report gives two facts: attendance happens, and nothing shifts. It gives no cause. Three non-overlapping causes cover the space [judgment]:

1. Decisions do not become work items with named owners.
2. The chosen changes are too large to finish in one week.
3. The sessions surface symptoms, not root causes.

Because attendance is present, the gap sits after the session, not during it [judgment]. Cause 1 is therefore likely (66 to 100%). Causes 2 and 3 then feed cause 1 without owners, nothing gets finished or tested.

Assumption log

A1. Action items are written down but not tracked to done. Why not measured: the material does not state it. Validate by: read the last three retro notes and their action lists. If wrong: drop Step 1 and let the Step 3 rubric drive the fix.

A2. Team composition is stable across cycles. Why not measured: the material does not state it. Validate by: check the roster across the last three cycles. If wrong: add a handover rule for owners who leave.

A3. People feel safe to raise real issues. Why not measured: no tool can reach it. Validate by: one anonymous question after the next retro. If wrong: run Step 3 with anonymous input before any format change.

Alternative considered

Change the format, for example a new board layout or a new facilitator. It loses because a new format still leaves actions unowned and unchecked, so the loop stays open [judgment].

End

I recommend that we run this sequence over the next two cycles:

1. **Open with status (Clear; deterministic).** Start each retrospective with the status of the last action. This adds the closure loop, so progress no longer depends on memory. Test first per Gherkin [14]:
   ```gherkin
   Given a retrospective starts
   When the first agenda item is read
   Then the note shows the last action with status Done or Not done
   ```

2. **One owned action (Clear; deterministic).** File each retrospective with one action, one owner, and one date. This removes the blocker of changes too large or too vague to start. No wait between Step 1 and Step 2; run both in the same session. Test first [14]:
   ```gherkin
   Given a retrospective ends
   When the note is filed
   Then it lists one action, one owner, and one date
   ```

3. **Score the old failures (Complicated; evaluative).** Rate the actions from the last three retrospectives against a rubric. The analysis shows which failure cause dominates, so the team fixes the real mode. Rubric per Kepner-Tregoe [15]: owner named and present, weight 0.4; action fits one week, weight 0.3; action targets the root cause, weight 0.3. Pass threshold: total score at or above 0.7. Evidence: the retro notes. Step 3 uses notes from before Step 2, so it can run first.

4. **Measure the closure rate (Complex; stochastic).** Run a two cycle probe: measure the share of actions marked Done by the following retrospective. This tests whether the loop now closes under a capped budget, so the team does not commit to a process change before evidence returns [18]. Leverage here is a guess until the probe returns. Acceptance test: metric is share of actions Done; baseline is the rate from Step 3 scoring; pass threshold is 50% or more Done; sample is two cycles, about two actions per cycle. Step 4 MUST NOT start until Steps 1 and 2 have run for one full cycle.

Follow-up

Conditions that change the recommendation: if A1 is false because actions were owned and tracked, drop Step 1. If A3 is false, run Step 3 with anonymous input before any other step. If the closure rate stays under 50% after two cycles, repeat Step 3.
