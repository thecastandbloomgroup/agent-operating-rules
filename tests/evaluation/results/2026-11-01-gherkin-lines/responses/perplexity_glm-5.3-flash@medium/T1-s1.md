Headline

Make a formatter, not the reviewers, the single authority on SQL style; the friction ends when nobody has to judge format by hand.

- Review friction over style comes from a missing shared authority, not from a values conflict [judgment].
- One formatter with one shared config removes the decision from every review.
- A blocking check in CI makes the rule cheaper to follow than to argue about.
- A one-line policy document replaces pages of style rules that fuel debate.

Background

The team disagrees on SQL format at every code review, and this causes repeated friction. The request is to remove that friction. Current date: Sunday, November 1, 2026.

Relevance

Each unformatted pull request costs reviewer time and stores a small social grievance. A mechanical fix in one session removes both costs for every future review [judgment].

Analysis. A formatter is a program that rewrites SQL into one fixed layout. Two mature open source options exist for most SQL dialects: sqlfluff and sqlfmt [no source]. The style war is not fixable by argument, because each side loses time either way [judgment]. A documented style guide alone does not fix it, because reviewers still must check format by hand and still disagree [judgment]. A blocking check removes the human judgment, so the topic stops appearing in reviews [judgment]. Confidence: high, because the cause is a missing shared authority, not a social conflict [judgment].
