## Headline

Ship the JWT flow behind a feature flag with short-lived access tokens and a server-side revocation path. Keep the session flow until the token flow proves parity. Treat the sign-up change as a measured probe, not a redesign. The plan covers three parts: token design, a gated cutover, and one conversion experiment.

## Background

The request bundles two changes. The auth service moves from server-side sessions to JSON Web Tokens (JWTs, digitally signed tokens that a service can verify without a database lookup). Sign-up conversion should also improve. The query names no stack, no client types, and no funnel numbers.

## Relevance

Both changes touch the login path, the path that gates every other user action in the product. An unmeasured conversion change gives no way to know whether the work paid off, so the baseline comes first.

## Information

Evidence:

- A session record lives in one place, so the server can invalidate it at once and act as a kill switch [2].
- A JWT, once issued, is hard to revoke before its expiry, because any service can verify it without a lookup. The accepted mitigation pairs a short access-token lifetime with a denylist (a server-side list of rejected token IDs) [3].
- Tokens held in web storage are open to any script that runs on the page. HTTP-only cookies lower that exposure [3].
- In one United States adult survey, 26% of shoppers abandoned an order because the site forced account creation [4]. This supports friction reduction at the form, and it suggests the sign-up path has real room to gain.
- Controlled experiments need a pre-set metric, a pre-set sample size, and a fixed runtime. Reads after the fact inflate false positives [5].
