## Headline

Measure the error rate first, then fix the top error type with a grounding change. The path: tag 60 summaries into countable error types, build a reference test set, score the summariser against it, probe a grounded prompt, and keep an agent rating button live.

## Background

A support tool now summarises tickets with an LLM. Agents report that summaries are "sometimes wrong", and no metrics exist. The request is to improve the summariser.

## Relevance

Without a baseline, any prompt change is a guess, and agents will stop reading the output. One measurement cycle finds the dominant error and gives proof for the next change.

## Information

**Evidence**

1. "Sometimes wrong" carries no base rate. The material contains one agent report [no source]. I treat it as one theme: unmeasured quality leads to distrust and to no feedback loop. One source supports it, so it needs the recommended measurement, not literature confirmations.
2. Summarisation quality has four standard failure groups: wrong facts, missing key facts, wrong focus, and brevity or style [1].
3. Automatic scores such as ROUGE do not track human judgments of factual consistency well [2]. So we score with a rubric and reference summaries, not with string overlap [3].
4. Reference summaries written by humans are the standard basis for summarisation evaluation [3].
5. Sample plan: 30 agent flagged summaries plus 30 random ones. This gives the flagged group and a base rate [judgment]. Two raters at about 5 minutes per item cost about 10 hours total [judgment]. If that cost is too high, cut to 40 items.
6. In LLM summarisation benchmarks, human raters judge factual consistency weaker than coherence across models [1]. So the rubric weights factual consistency highest.

- A2. We own the prompt or configuration. Why not measured: the deployment is not stated. Validate by: check who owns the prompt. If wrong: replace Step 4 with a vendor change request that cites the Step 3 score.
- A3. 60 tickets can be used in an eval set. Why not measured: the data policy is not stated. Validate by: apply the masking rules and sample check. If wrong: mask ticket text or reduce the set.
- A4. Two people can spare part of a session to tag and score. Why not measured: staffing is not stated. Validate by: ask the team lead. If wrong: one rater with a 5 item self check.

**Alternative considered**

Replace the LLM with extractive summarisation or drop the feature. This loses: without a baseline we cannot compare any option, and Step 3 produces the baseline for about 10 hours of work [judgment].
