## Headline

No prompt can make a model stop hallucinating, because hallucination comes from how the model produces text, not from bad wording. The best prompt is one that forces the answer to cite the context, allows the model to refuse, and labels claims it cannot support. Because no criterion exists for "the best", I give the strongest prompt family plus the measurement that replaces guessing.

## Background

The request is a single line: the best prompt to make the model stop hallucinating. It does not name the model, the task, or whether a context document exists.

## Relevance

Hallucinated output fails silently when the text sounds correct [1]. A prompt change is the cheapest control available, so it is worth testing before other measures.

## Information

**Evidence.**
Hallucination in text generation has known causes: training data with errors, knowledge gaps, and sampling from the model's probability distribution [1]. Prompts work at the output layer only. Therefore a prompt can suppress unsupported claims in the visible answer, but it cannot remove the underlying cause [1], [inference]. No published study shows a single prompt eliminates hallucination for an open-domain task [inference].

**The prompt.** Use it when the model answers from documents. Paste the clauses into the system prompt:

```text
1. Answer only from the provided context.
2. After each factual claim, quote or cite the exact line that supports it.
3. If the context lacks the answer, reply exactly: "Not in the given context."
4. Never invent names, numbers, dates, or citations.
5. End with a section named "Unverified."
   List there every claim you could not trace to the context.
```

**The prompt without context.** If the model answers from its own knowledge, replace clause 1 with: "Separate confirmed facts from inference. Label each sentence as Fact or Inference. Use 'I do not know' when you do not know."

**Assumption log.**
A1. The user wants a reusable prompt, not a research review. Why not measured: the query does not state it. Validate by: one question. If wrong: the surrounding method below still applies.
A2. The model answers from a context or retrieval step. Why not measured: the query does not state it. Validate by: check whether the app feeds documents. If wrong: use the second prompt variant above.

**Alternative considered.** "Just write 'do not hallucinate' or 'be accurate' in the prompt." This loses because such words state a goal without an output rule. Clause 3 gives an exact refusal string, which is checkable, and clause 2 adds evidence to the answer [inference].

## End

I recommend that we install the five-clause prompt, then measure its effect instead of trusting it:

1. **Add the prompt clauses to the system prompt, in order above.** This removes the blocker of invented answers with no traceable source. Configure each clause with the requested refusal string. Kind: deterministic. Domain: Clear. Test:
   `Given a context that lacks the answer, when the model answers, then it returns exactly "Not in the given context."` [2]
2. **Build a test set of 50 real questions with checked answers before rollout.** This removes the blocker of no baseline for unsupported claims [judgment]. Kind: evaluative. Domain: Complicated. Test: a rubric with three criteria: faithfulness (weight 0.5), coverage (weight 0.3), refusal correctness (weight 0.2); pass threshold is 80% weighted score; evidence per item is the checked answer plus the cited line.
3. **Run the probe: score the new prompt against the old prompt on the 50-question set.** Each run uses the same questions and the same temperature of 0. Budget: one working session. Stop condition: two rounds with a gain below 5 points in unsupported-claim rate ends the probe. Do not commit further prompt tuning until the gain is 5 points or more [judgment]. Kind: stochastic. Domain: Complex.

Step 1 proceeds without dependencies. Step 2 is the input to step 3, so step 3 MUST NOT start until the set in step 2 exists.

Condition that changes this recommendation: if the answers drive contracts or safety decisions, add retrieval with citations as the primary control and treat the prompt as a support layer.

## Follow-up

If you name the model and the task, the refusal string and the test set can be tuned to your domain.
