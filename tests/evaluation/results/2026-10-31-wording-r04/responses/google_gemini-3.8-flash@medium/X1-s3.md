### Headline

Establish an evaluation benchmark and feedback telemetry before changing model prompts or architectures.

- Diagnostic measurement must precede model changes because unmeasured changes risk worsening accuracy.
- A golden test dataset of support tickets isolates specific factual errors from stylistic preferences.
- Structured agent feedback in the interface captures production errors at low collection cost.

### Background

You deployed a Large Language Model (LLM) summariser in your customer support tool. Support agents report that the generated summaries are sometimes wrong. The system currently records no quality metrics or baseline performance data.

### Relevance

Unreliable summaries increase handling time and risk incorrect customer advice. Establishing metrics now lets you fix factual errors without guessing agent intent.

### Information

Customer support summarisation requires high factual accuracy across conversation threads [judgment]. LLM summarisation often introduces hallucinations, omitted customer details, or inverted resolutions [1]. Without baseline metrics, teams cannot distinguish hallucination from poor formatting [judgment].

A2. Support agents can spend thirty seconds per ticket to flag summary errors. Why not measured: The material does not state it. Validate by: Testing a one-click error tag in five agent sessions. If wrong: Rely on offline expert review instead of in-app feedback.

A3. Ticket logs with human summaries exist in the support database. Why not measured: The material does not state it. Validate by: Querying past ticket records for manual resolution notes. If wrong: Generate reference summaries manually for the test set.
