# Headline

Establish an evaluation benchmark on historical support tickets before you alter the prompt or model.
First, a sample of agent tickets will define the primary error modes.
Next, an evaluative rubric will measure accuracy against human summaries.
Finally, prompt adjustments will target the top error mode under measured validation.

# Background

Support agents report that the new language model summariser generates incorrect outputs. The system currently operates without error logging or performance metrics. Therefore, you cannot identify whether errors stem from hallucination, omitted facts, or unclear source text.

# Relevance

Unreliable summaries increase agent handling time and risk incorrect customer advice. You need an objective baseline now to prevent wasted effort on unmeasured prompt changes [judgment].

# Information

Without metrics, model changes yield unknown results. In customer support summarisation, factual consistency errors represent the main operational risk [1]. Benchmarking requires golden references created from actual conversations [2]. 

## Evidence

Subjective agent complaints show that error rates exceed user tolerance [judgment]. A baseline measurement on a sample of 100 historical tickets is sufficient to identify top failure categories with high confidence [judgment].

## Assumption log

A1. Agents have access to the source conversations and can spot errors accurately. Why not measured: The user has not answered. Validate by: Review five flagged summaries with two senior agents. If wrong: Agent feedback cannot serve as ground truth for error categories.

A2. Ticket volume provides at least 100 closed conversations for testing. Why not measured: The material does not state it. Validate by: Query the ticket database for closed records from the past month. If wrong: Reduce the evaluation sample size to 50 conversations.

## Alternative considered

Modifying the prompt immediately with general instructions to reduce errors was considered. It loses because without metrics you cannot verify whether changes improve or degrade output accuracy [judgment].

# End

I recommend that we:

1. Classify agent-reported errors to determine failure modes.
   - Domain: Confused.
   - Increment: Audit 30 flagged summaries in one working session.
   - Capability: Identifies the root error categories.
   - Task kind: Evaluative.
   - Test: Score summaries against this rubric. Criterion 1 is Hallucination (weight 0.4). Criterion 2 is Omission of key facts (weight 0.4). Criterion 3 is Formatting (weight 0.2). Pass threshold is 100% agreement on primary error category across two reviewers.

2. Build an evaluation dataset of 100 tickets with reference summaries.

   - Domain: Complicated.

   - Task kind: Stochastic.
