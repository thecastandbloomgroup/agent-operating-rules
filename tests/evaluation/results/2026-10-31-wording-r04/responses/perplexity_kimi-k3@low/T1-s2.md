## Headline

Format debates stop when a tool decides, not when people agree: adopt one formatter config and enforce it in CI in one sprint.

1. The friction is a process failure, not a culture failure: reviews contain style debates because style is decided by people [judgment].
2. Automated enforcement removes the debate surface: reviewers discuss logic, the formatter owns layout [judgment].
3. The irreversible decision is small: one formatter choice, made once with an explicit rubric, everything else is mechanical.

## Background

Your team has no agreed SQL format. Every review includes style arguments, which costs review time and goodwill. You asked how to remove that friction.

## Relevance

Style arguments in reviews correlate with reviewer fatigue and slower merges, and they displace feedback on correctness [judgment]. Fixing this before the next review cycle stops the cost from recurring weekly.

## Information

The cause: humans enforce style by opinion because no artifact defines the correct output [judgment]. Proven pattern in adjacent ecosystems: teams that adopt an opinionated formatter (for example gofmt, Black, Prettier) report that style debate ends once the tool is enforced in CI [no source]. The same mechanism applies to SQL with tools such as sqlfmt or SQLFluff.

Alternative considered: write a style guide and agree to follow it. This loses because a guide without enforcement returns the decision to reviewers, so the debate resumes within weeks [judgment].
