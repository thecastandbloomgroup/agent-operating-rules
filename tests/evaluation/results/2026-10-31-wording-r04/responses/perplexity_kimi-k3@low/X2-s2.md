Headline
Run fewer retrospectives outputs and treat each one as a owned, funded, checked experiment.
1. Separate the problem into ownership, capacity, and closure: actions lack an owner, time, and a review at the next retrospective.
2. Keep event quality, but change the system around it: the meeting can be healthy while follow-through is broken.
3. Use one measured probe for repeated disengagement: test causes before changing the whole format.

Background
Retrospectives still happen, but outcomes do not change team behavior or delivery. This pattern usually means the output is disconnected from backlog priority, ownership, and review.

Relevance
This matters because repeated meetings without change teach people that speaking has no effect. That reduces participation and hides delivery risks.

Information
The main failure is plausible as follow-through failure, not meeting failure: about as likely as not, based on the symptom "people attend but nothing shifts."
Retrospective guidance emphasizes few actions, visible ownership, and review of prior actions [1].
Project retrospective practice also treats follow-through as the point where learning becomes change [2].

Alternative considered
Stop retrospectives for a quarter. It loses because it removes the feedback channel; the defect is weak closure, so repair closure first [judgment].

End
I recommend that we do four steps in order.
1. Deterministic, Clear. Test first: Given one retrospective ends, When the facilitator closes the meeting, Then exactly one improvement item exists with one named owner, due date, and Definition of Done. Increment: cap output at one item and record it before leaving. Blocker removed: too many vague actions. Start now.
2. Deterministic, Complicated. Test first: Given sprint planning starts, When the team selects work, Then the retrospective item is in the backlog with capacity reserved equal to its estimate. Increment: add the item as normal work, not extra work. Blocker removed: improvement loses to feature pressure. Start after Step 1 passes.
3. Deterministic, Clear. Test first: Given the next retrospective opens, When the first agenda item runs, Then the team reviews the prior item as done, not done, or stopped with reason in five minutes. Increment: make review the fixed opening agenda. Blocker removed: closed-loop is missing. Step 3 MUST NOT be skipped once Step 1 exists.
4. Stochastic, Complex probe. Acceptance test first: run two retrospectives; metric is action completion rate; baseline is current completed actions ÷ committed actions; pass threshold is 2 of 2 completed; sample size is two cycles. Probe: rotate facilitator and use anonymous item collection for two cycles only. Budget: two cycles. Stop condition: any drop in psychological safety pulse below 4 of 5. Capability added: evidence on whether format or ownership causes silence. Run in parallel with Steps 1 to 3.

Follow-up
Conditions that change the recommendation: if A3 is false, replace Step 4 with an external safety review. If A2 is false, create the action register before any format change.
