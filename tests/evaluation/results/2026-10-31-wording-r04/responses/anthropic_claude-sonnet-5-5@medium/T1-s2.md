## Headline

**Choose one SQL style by a fixed rule, then let a tool enforce it, so reviewers stop debating format.**

- Decision: one named owner picks the style by a deadline, using a scored comparison.
- Enforcement: a formatter and a CI check apply the style, so no person argues for it.
- Measurement: a four-week probe shows whether review friction falls.

## Background

The team has no shared SQL format. Each review repeats the same style argument. You asked for a fix to the culture problem.

## Relevance

Style comments take review time and cause conflict without improving correctness. A rule that a tool enforces ends the argument. This fix is cheap now and costs more as the SQL code base grows.

## Information

**Evidence**

- A linter can both report and auto-fix SQL style, and it reads its rules from a config file in the repo. [1]
- Style arguments continue because people hold the decision, not because the rules are hard [judgment].
- A tool enforcing the style removes the personal element from the comment [judgment].
- It is likely (66 to 100%) that the fix works if the owner decides once and the CI check blocks merges [judgment].

**Assumption log**

**Alternative considered**

The strongest alternative is a team vote on a written style guide. It loses because a vote gives a guide that people still debate and apply by hand [judgment].

## End

2. **Apply the style in one commit and enforce it in CI.** Deterministic. Cynefin: Complicated.
   - Step 2 MUST NOT start until Action 1 ends with a signed decision.

     ```gherkin
     Feature: SQL style gate
       Scenario: Unformatted query is blocked
         Given a pull request with a query that breaks the style config

         Then the check fails and names the broken rule
       Scenario: Formatted query passes
         Given a pull request with a query that follows the style config
         When the CI check runs
         Then the check passes
     ```
   - Write both scenarios, see the first one fail, then add the config. Refactor the config last.

3. **Set the review rule.** Evaluative. Cynefin: Clear.

   - Step 3 MUST NOT start until the test in Step 2 passes.

   - Increment: one count of style comments per review, collected weekly.

   - Test, written first: the metric is style comments per review. The baseline is the last 20 reviews before the change. The pass threshold is a drop of at least 80% [judgment]. The sample size is 20 reviews after the change.
   - Stop condition: after two weeks, if the count has not fallen at all, stop and run a 30-minute retrospective with the team. Budget: one hour per week to count.
