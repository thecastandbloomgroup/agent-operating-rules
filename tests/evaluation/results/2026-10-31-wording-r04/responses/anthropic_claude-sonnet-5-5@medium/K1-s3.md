## Headline

Restore the connection pool size and timeout first, because the 8-connection pool causes most of the slowdown.

- The pool change explains about 88% of the p95 increase (see Information, E1).
- The shorter cache lifetime adds load, but it is a minor cause (E3).
- The ORM change shows no measured cost (E4).
- Fix the pool within the new database limit, then revert the cache setting, then add an alert.

## Background

The API p95 latency rose from 120 ms to 900 ms after release 2026.10.21. That release cut the pool size from 50 to 8, cut the pool timeout from 30 s to 5 s, cut the cache lifetime from 300 s to 60 s, and added eager loading of order lines. You asked what to do.

## Relevance

Users now see 503 errors at 20 times the old rate. Each request that waits for a connection holds a worker, so the problem grows with load.
