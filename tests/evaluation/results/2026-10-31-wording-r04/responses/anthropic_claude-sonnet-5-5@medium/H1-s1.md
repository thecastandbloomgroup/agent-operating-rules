## Background

Checkout has returned a 500 error to every user since 09:12. You are the on-call engineer. You have ten minutes before the exec call.

## Relevance

A full outage of checkout stops all orders. Each minute of delay adds to the loss, and the cause is still unknown.

- A rollback fixes a change-caused outage: 60% likely [judgment].
- In a chaotic situation, act first to stabilise, then sense, then respond [1].

**Assumption log**

A2. A one-command rollback path exists. Why not measured: no tool can reach your system. Validate by: run the rollback dry run or read the runbook. If wrong: use a feature flag to disable the new code path.

A3. You can post to a status page or team channel. Why not measured: the material does not state it. Validate by: open the page. If wrong: send the note by direct message.

**Alternative considered**
Debug the root cause first. It loses because diagnosis takes longer than ten minutes [judgment], and a rollback restores service while you diagnose.
