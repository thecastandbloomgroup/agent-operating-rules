## Headline

I recommend that we stop debating style and let one automated formatter decide it.

- The friction comes from people judging style by taste, so a tool must take that judgment away.
- The tool only works when the team agrees once, in a fixed time box, on the tool and its settings.
- A review rule then keeps style out of review comments.

## Background

Your team has no shared SQL format. Each review turns into a style argument. You asked for a fix to this culture problem.

## Relevance

Every review that debates style delays merges and wastes reviewer time. The cost repeats with each pull request, so a fix now removes a recurring cost [judgment].

## Information

**Evidence**

- Style rules without automatic enforcement depend on reviewer memory and taste [judgment].
- A formatter gives the same output for the same input, so it cannot disagree with itself [judgment].
- Disagreement of this kind is a preference conflict, not a fact conflict. A single owner for the decision ends it faster than consensus [judgment].

**Assumption log**

A1. The team keeps SQL in a git repository with a pull request workflow. Why not measured: the material does not state it. Validate by: ask one person to open the repository. If wrong: replace Step 2 with an editor-level setting and a shared config file.

A2. A formatter exists for your SQL dialect (for example SQLFluff). Why not measured: the material does not name the dialect. Validate by: run each candidate on ten real files. If wrong: write a short written style guide and keep Step 4.

A3. Someone on the team can make a binding decision after the time box. Why not measured: the material does not state it. Validate by: name the decider in the first meeting. If wrong: escalate the choice to the team manager.

**Alternative considered**

The strongest alternative is a written style guide enforced by reviewers. It loses because it keeps the argument inside every review and depends on human memory [judgment].
