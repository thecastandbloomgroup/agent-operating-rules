Headline
Ship short-lived access JSON Web Tokens (JWTs) with a revocable refresh store, and change signup only after a baseline.
- Map the session store, clients, and signup drop-off first.
- Keep access tokens short, and keep refresh tokens in a store you can delete.
- Dual-run the new path until parity tests pass.
- Run one signup probe in parallel, with a stop rule and a small budget.

Background
This request asks for a move from sessions to JWT auth.
It also asks for better signup conversion.
The material does not name the stack, the clients, or the drop-off step.
Therefore the plan assumes a browser session plus one service client.
That client calls an application programming interface (API).
The plan treats conversion as completed signups per start.

Relevance
Token choice decides whether logout and theft response still work.
Signup edits without a baseline can cut completed accounts while starts rise.

Information
A JWT is a compact claim set that the receiver can check from the token itself.
[1]

[inference]
