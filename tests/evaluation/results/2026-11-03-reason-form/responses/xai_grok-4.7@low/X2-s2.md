Headline
The team should close the action loop before it adds new topics.
A review of prior actions comes first in each retrospective.
Each retrospective leaves with one owner and one date.
A small probe tests whether that format change works.

Background
People still attend the retrospective, but the work does not change.
The request is to restore a link from talk to action.
This pattern is common when actions have no owner, no date, and no later review.

Relevance
Without that link, the meeting spends time and trust falls.
Therefore the next retrospective can test a fix in one session.

Information
This section covers the evidence, the assumptions, and the alternative.
Unfinished actions are the likely blocker (66 to 100%).
The basis is attendance with no shift in the work [judgment].
Derby and Larsen treat the retrospective as a place for small experiments [1].
The Scrum Guide says the team plans improvements after it inspects the last sprint [2].
The request has no count of closed actions [no source].
A one-action limit is a tightening of those sources [judgment].

A1. The team holds a recurring retrospective.
Why not measured: the material does not state the cadence.
Validate by: read the last three meeting notes.
If wrong: use the meeting that is meant to change the work.

A2. The blocker is unfinished actions, not a lack of ideas.
Why not measured: the material does not list past actions.
Validate by: count actions marked done in the last three notes.
If wrong: change the experiment if actions are done and results stay flat.

A3. A facilitator can set the next agenda.
Why not measured: the material does not state authority.
Validate by: the facilitator confirms agenda control before the meeting.
If wrong: a manager sponsors the format first.

The strongest alternative is to stop the retrospective or hire a coach.
It loses because a one-session format test is cheaper and reversible [judgment].

End
I recommend that we take these four steps.

1. Review last actions before any new topic.
Domain: Clear, by deduction from the inspect-and-adapt rule [2].
Kind: deterministic. The test comes first.
Given the last notes list open actions,
When the facilitator opens the meeting,
Then each action is marked done, not done, or dropped before new topics start.
Increment: one opening review of ten minutes.
Blocker removed: hidden unfinished work.
Step 2 MUST NOT start until this test passes.

2. Select one action with a rubric.
Domain: Complicated, because analysis picks the action.
Kind: evaluative. The rubric comes first.
Criteria: named owner (weight 40), date within 14 days (weight 30), task fits one work session (weight 30).
Pass threshold: a score of 70 or more, with evidence for all three criteria.
Evidence: a name, a date, and a task size note in the retrospective record.
Increment: one selected action in the same meeting.
Blocker removed: a list of actions that nobody owns.
This step waits on Step 1.

3. Record a stop rule for that one action.
Domain: Complex, because cause and effect show up only after the trial.
This is a safe-to-fail probe, so leverage is a guess [judgment].
Kind: stochastic. The acceptance test comes first.
Metric: status of the one action at the next retrospective.
Baseline: zero closed actions in the request [no source].
Pass threshold: the action is done or explicitly dropped.
Sample size: one retrospective cycle.
Budget: five minutes to write the rule, and one cycle to read the result.
Stop condition: drop the action if the owner cannot name a next step in the meeting.
Increment: the check and the stop rule in the record.
Blocker removed: no signal on whether the format works.
This probe runs in parallel with Steps 1 and 2 and does not block them.

4. Put the accepted action where the team sees daily work.
Domain: Clear, by deduction from a visible-work practice [judgment].
Kind: deterministic. The test comes first.
Given one action that passed the Step 2 rubric,
When the facilitator writes it on the team board or shared note the same day,
Then the owner, the date, and the status are visible without opening retrospective notes.
Increment: one board line or note line.
Blocker removed: an action that lives only in meeting notes.
Step 4 MUST NOT start until the rubric in Step 2 passes.

Follow-up
If A2 is false, replace Step 2 with a check of the last experiment result.
If A3 is false, pause Steps 1 to 4 until a sponsor sets the agenda.
