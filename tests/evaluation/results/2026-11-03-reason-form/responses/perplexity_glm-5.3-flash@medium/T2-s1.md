Headline

No prompt stops hallucination. A prompt can cut the error rate, but only verification steps in your process catch the rest [judgment]. Use a prompt that forces "I do not know" answers plus citations, then add checks outside the prompt. The three support points: (1) models generate plausible text, so instructions alone cannot remove errors [1]; (2) semantic checks and retrieval with verification reduce error rates in tests [2]; (3) the cheap prompt change is the fastest first step, the process change is the lasting one [3].

Background

The request: give the best prompt that makes the model stop hallucinating. This response assumes a general text generation task with an application that can call the model and run extra checks.

Relevance

Hallucinations reach end users as false facts, numbers, and citations. Each one that ships costs trust and rework, so the fix sequence matters now.

Information

Analysis, ordered by the decision flow:

1. Prompt-only is the floor, not the fix. Models are trained to fill plausible text, and that training objective produces errors even on asked questions [1]. Error rates stay above a base level because prompts do not change the training objective.
2. Instructions that permit refusal help. Studies of hallucination mitigation group fixes into prompt-level, retrieval, and post-check classes [3]. Prompt-level fixes that explicitly allow refusals lower unsupported claims. The size of the drop depends on the task.
3. Trustworthy output needs a check outside the model. Semantic consistency checks flag answers that change meaning across samples [2]. Retrieval with citation and a verifier step catches content that no prompt catches.
4. Quantitative baseline [judgment]: before any change, measure the unsupported-claim rate on 50 samples from your own task set. Without this number, no improvement is provable.

Assumption log

A1. The task is general generation through an API. Why not measured: the material does not state the task. Validate by: read one sample task. If wrong: a domain with a closed fact set changes Step 3 toward rule checks.

Alternative considered

The strongest alternative is a single long system prompt that bans false statements in strict words. It loses because word choice does not change the generation objective [1], so error rates stay near their base level [inference].

End

I recommend that we (1) run a baseline of 50 samples and count unsupported claims [judgment, stochastic, Complex: measure first, stop if the rate is under 1 percent]. (2) Add a prompt that permits refusal and demands a source for each claim; test with 20 questions where the model cannot know the answer, pass when it refuses at least 19 of 20 [deterministic, Clear: the rule is known]. (3) Add a verification step that compares each claim against a source and rejects claims without one; test in Gherkin form: Given a model answer with a claim reduced to a small phrase, When the checker runs against the source set, Then unbacked claims return a flag [deterministic, Complicated: analysis picks the check method]. (4) Sample each answer twice and compare meanings; pass flag threshold at 90 percent agreement over 50 paired samples [stochastic, Complex: probe capped at 1 week budget; what could break the pattern: paraphrase looks like disagreement].

Follow-up

Conditions that change the recommendation: a closed fact domain removes Step 4. Open question: what is the target task and error budget?
