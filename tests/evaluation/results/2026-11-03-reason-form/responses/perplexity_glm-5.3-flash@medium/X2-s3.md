## Headline

Stop the window dressing: end each retrospective with one owned action and review the last actions at the start of the next one. Retros stop producing change when findings repeat but no one owns, schedules, and verifies the actions. The fix has three parts: review past actions, cut to one owned action, and treat blockers as retro topics.

## Background

The team attends retrospectives, but work does not change. Attendance continues, so the meeting happens; output stops. [no source]

## Relevance

Retros are the team's main tool for improvement. When they produce nothing, improvement work stops too. [no source]

## Information

The pattern "talk, list actions, forget" repeats in retrospective practice. Reviews of retrospective use name weak follow-up as the common failure, with actions left unowned and untracked. [judgment]

## End

I recommend that we do the following.

1. Recover the rule. Correct the contract between the meeting and the work: each retrospective ends with at most one action, one named owner, and one due date inside the next cycle. Blocker removed: actions stay as talk. Test, written first:

```gherkin
Given a retrospective that just ended
When the action list is read
Then each action has one owner and a due date
And the count of actions is at most one
```

Kind: deterministic. Domain: Clear, because the rule applies in one step.

2. Recover the memory. Open the next three retros with a count: actions completed out of actions proposed, from the last three retros. That count becomes the stated completion rate. Blocker removed: invisibility of the A1 assumption. Test, written first:

```gherkin
Given the last three retros produced three actions
When the next retro opens with the review
Then the count of completed actions is read aloud
And any action older than one cycle is closed or re-owned
```

Kind: deterministic. Domain: Clear, because the count is one step. This step MUST finish first. It decides whether A1 holds. [judgment]

3. Probe the cause. If the completion rate stays below 50%, run a small change: rotate who leads, or change the format each retro. Measure with the same count. Stop condition: two consecutive retries with no gain. Budget: 2 retros or 2 weeks. Blocker removed: unknown true cause. Kind: stochastic. Domain: Complex, because the cause is hidden. Leverage is a guess until the probe runs. [inference]

Decision rule: if Step 2 shows a rate of 50% or above, skip Step 3. Then the problem sits in finding quality, and the review of past actions at each retro start handles it. [inference]
