## Headline

No prompt removes hallucination, but a grounding prompt with a permitted "I don't know" cuts it the most. Use the prompt in the End section.

- The model guesses because training rewards a guess over an abstention [1].
- Supplied source text gives the model facts to quote instead of facts to recall [2].
- A verification pass catches unsupported claims after the first draft [3].
- A person must check high-stakes claims, because prompts lower the rate but do not remove errors [4].

## Background

You ask for one prompt that stops a language model from stating false facts (a hallucination). Models produce fluent text whether or not they know the answer. The request names no task, model, or source material.

## Relevance

A false claim that looks confident costs you time or credibility when you act on it. A prompt costs nothing to try, so you can start today.

## Information

Evidence:

- Hallucination is a documented, broad failure across text generation tasks [4].

- Evaluations that score only correct answers reward guessing, so models learn to guess [1]. A prompt that allows "the sources do not say" counters this. Confidence: medium, because the paper explains the cause and does not test this prompt.

- Retrieval of source text before generation improves factual accuracy on knowledge tasks [2].

- Drafting verification questions and answering them separately lowered hallucination in the tested tasks [3].

- No source here gives a reduction rate for one specific prompt. Any claim of "stops" is false. [judgment]

Assumption log:

A1. You can paste source text into the prompt. Why not measured: the material does not state it. Validate by: ask yourself if a document exists for the task. If wrong: use Step 2 and Step 3 only, and expect a smaller gain.

A2. Your tasks are factual questions, not creative writing. Why not measured: the user has not answered. Validate by: read your last five prompts. If wrong: skip this guidance, because invention is the goal in creative work.

Alternative considered: fine-tune or switch to a retrieval system with citations. It lowers errors more, but it takes weeks and money. A prompt takes one session. [judgment]

## End

I recommend that we use this prompt, and then test it in four steps.

```text
Answer using only the text inside the <sources> tags.
Quote the supporting sentence for each claim.
If the sources do not answer the question, write: "The sources do not say."
Do not use outside knowledge. Do not guess.
After your answer, check each claim against its quote.
Delete any claim that has no quote.
Last, state your confidence as high, medium, or low, with the reason.
```

1. Build a prompt template with a sources slot, a question slot, and the rules above.
   - Increment: one template file, done in 20 minutes.
   - Blocker removed: the model has no facts to quote.
   - Kind: deterministic.
   - Test, written first:
     - Given the template and a sample document and question
     - When the prompt is assembled
     - Then the text contains the sources tag, the question, and the phrase "The sources do not say."
   - Cynefin: Clear. A known best practice applies, so deduction from a known rule is enough [2].

2. Run the grounding prompt as a probe against a plain prompt.
   - Step 2 MUST NOT start until the test in Step 1 passes.
   - Increment: 50 questions, 20 of them unanswerable from the sources.
   - Blocker removed: no measured rate for your model.
   - Kind: stochastic.
   - Test, written first: the metric is the share of answers with an unsupported claim. The baseline is the rate from the plain prompt on the same 50 questions. The pass threshold is at least half the baseline rate. The sample size is 50.
   - Stop condition: end the probe if the threshold fails at 50. Budget: one session.
   - Cynefin: Complex. Induction from trials. A new model version or a longer document could break the pattern. The leverage is a guess.

3. Add a verification pass as a second probe, in parallel with Step 2.
   - Increment: one follow-up prompt that asks the model to write check questions for its own answer and answer each from the sources [3].
   - Blocker removed: errors that survive the first draft.
   - Kind: stochastic.
   - Test, written first: the metric is the unsupported-claim rate. The baseline is the Step 2 result. The pass threshold is a further 25% relative drop. The sample size is the same 50 questions.
   - Stop condition: end it if the extra cost passes twice the Step 2 cost. Budget: one session.
   - Cynefin: Complex. Induction from trials. Long answers could break the pattern.

4. Check every high-stakes claim against its primary source before you act.
   - Step 4 MUST NOT replace Steps 2 and 3, because it only catches errors after they occur.
   - Increment: a rubric for one real answer.
   - Blocker removed: residual errors that no prompt removes [4].
   - Kind: evaluative.
   - Rubric, written first: criteria are quote exists (weight 50%), quote matches the source wording (30%), and claim follows from the quote (20%). The pass threshold is 90% per claim. Each criterion needs the source page as evidence.
   - Cynefin: Complicated. The analysis of the claim against the source selects the check.

If A1 is false, drop Step 1 and add "answer only what you know with high confidence" to the prompt. Expect a smaller gain.
