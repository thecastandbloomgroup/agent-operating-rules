# Headline

No single prompt stops hallucination, but a constraint-based prompt reduces it measurably.

- Prompts that bind the model to provided sources cut unsupported claims the most [judgment].
- Allowing "I don't know" removes the pressure that drives confident fabrication [1].
- Verification steps (quote before you claim) outperform style instructions like "be accurate" [judgment].
- Retrieval or tool access beats any prompt-only fix for factual tasks [1].

# Background

You want one prompt that stops a language model from producing false statements. Hallucination here means output with no support in the input or in reality.

# Relevance

A reusable instruction block saves repeated correction work. It matters most where errors carry cost, such as analysis, code, or citations.

# Information

Evidence: a widely replicated finding chain, from TruthfulQA onward, is that models default to plausible continuations when an answer is absent, and that instructing abstention plus grounding reduces false claims [1]. Beyond that finding, the specific wording below is [judgment].

Prompt to use:

```text
Answer only from the sources I provide or from statements you mark as uncertain.
Rules:
1. If the sources do not contain the answer, reply: "Not in the provided material."
2. Attach a quote or reference to every factual claim.
3. Label any claim from your own knowledge as [unverified] and state why you believe it.
4. Do not invent references, numbers, or quotations.
5. If my question has a false premise, say so first.
```

Limits: this reduces hallucination; it does not eliminate it. Models fail at self-attribution, so rule 2 fails part of the time [1]. "About as likely as not" that a long answer still contains at least one unsupported claim without retrieval tools [1].

Assumption: the task is factual Q&A or summarization, not creative writing. Why not measured: the query does not state the task. Validate by: run the prompt on three recent failing cases. If wrong: for creative tasks, drop rules 1 to 4 and keep only rule 5.

Alternative considered: fine-tuning or retrieval-augmented generation. Retrieval reduces hallucination more than any prompt [1], but it costs infrastructure, so prompt-only is the right first step.

# End

I recommend that we do the following:

1. Paste the prompt block above into your next failing conversation. Increment: one session. Blocker removed: unsupported claims go unflagged. Cynefin domain: Clear, because the practice is a known best practice applied by deduction. Test (deterministic):

   Given a question whose answer is absent from the provided sources,
   When the model answers with the prompt active,
   Then it replies "Not in the provided material" and adds no fabricated reference.

2. Run the same three past failures with and without the prompt. Increment: one session. Capability added: evidence the prompt works on your workload. Cynefin domain: Complicated, because comparison by analysis picks the better option. Test (evaluative, rubric first): criteria are unsupported-claim count (weight 70%) and correct-abstention rate (weight 30%); pass threshold is fewer unsupported claims than baseline on all three cases; evidence is the claim-by-claim check against sources. Step 2 MUST NOT start until Step 1 is set up.

3. When the task is recurring and factual, add retrieval (documents or search) instead of stronger wording. Increment: one session to wire one source in. Blocker removed: the model answers from nothing. Cynefin domain: Complicated, because tool selection needs analysis. Test (stochastic): metric is unsupported-claim rate; baseline is Step 2's without-prompt rate; pass threshold is a 50% relative reduction; sample size is 20 queries. Step 3 MAY start in parallel with Step 2.

# Follow-up

If Step 2 shows no reduction, the failure is in instruction-following, not wording; switch to retrieval or a smaller claim-by-claim workflow.
