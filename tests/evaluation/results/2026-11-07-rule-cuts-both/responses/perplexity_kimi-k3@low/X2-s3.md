## Headline

The team should change how it runs retrospectives and how it tracks the work that comes out of them. The causes are:

- Retrospectives fail when actions have no owner, no deadline, and no follow-up.
- Facilitation matters: the same format every time stops producing new insight.
- Trust limits honesty: people stay silent when raising problems has a cost.
- Track a small set of actions visibly, and phase them into the sprint as real work.

## Background

The retrospectives happen, but they do not change behavior or results. Attendance is fine, so the format and follow-through are the likely failure points. This is a common pattern, so established methods apply.

## Relevance

Repeated meetings without change waste team time and lower trust in the process. A small set of changes can make the next two or three retrospectives produce visible results.

## Information

Retrospective research and practice point to three causes [judgment]:

1. No closure on actions. Actions that lack an owner and a review step get dropped. Derby and Larsen stress that each retrospective should end in a small number of concrete, owned experiments [1].
2. Format fatigue. One fixed format yields the same topics. Rotating formats and adding structure (set the stage, gather data, generate insights, decide, close) surfaces new material [1].
3. Low safety. People do not raise real problems when they fear blame. A safety check at the start shows whether this is the case [2].

Assumptions:

- Assumption: The team is colocated enough to run one monthly retrospective already. Why not measured: The material does not state it. Validate by: Ask the facilitator. If wrong: Adjust Step 3 frequency.
- Assumption: Actions from past retrospectives were not tracked. Why not measured: The material does not state it. Validate by: Review the last three meeting notes. If wrong: Skip Step 1 tracking and focus on facilitation.

Alternative considered: Replace retrospectives with an anonymous feedback tool. This removes the group dialogue that builds shared ownership, so it loses on trust-building [judgment].

## End

I recommend that we:

1. Audit the last three retrospectives. List every agreed action and mark it done, started, or dropped. This removes the guesswork about follow-through. Test (evaluative): rubric, each action scored owned yes/no, done yes/no, threshold: data complete for all actions. Complicated domain; analysis of notes decides the fix.

2. Cap each retrospective at two actions, each with a named owner and a review at the next meeting. This removes the overload blocker. Test (deterministic):
  - Given the retrospective ends,
  - When actions are recorded,
  - Then each action has one owner and appears on the next meeting's agenda. Clear domain; a known best practice applies.

3. Rotate the format for the next three sessions, for example start/stop/continue, then a timeline, then a lean coffee. This adds the capability to surface new topics. Test (stochastic): metric is count of new topics raised, baseline is the average of the last three sessions, threshold is baseline plus two, sample size three sessions. Complex domain; cause and effect appear only after trials, so cap the probe at three sessions.

4. Run a one-question safety check at the start of the next session. This shows whether silence is the blocker. Test (deterministic):
  - Given the session starts,
  - When the facilitator asks for an anonymous 1 to 5 safety score,
  - Then scores are collected and shown before discussion. Clear domain.

Step 2 and Step 4 start in the next session. Step 3 depends on Step 1: Step 3 MUST NOT start until the audit in Step 1 is complete.

If the safety check scores below 3, replace Step 3 with a session on working agreements before any format change.

## Follow-up

Open question: Who facilitates today, and is that person also a manager? The answer decides whether an outside facilitator is needed for the safety check.

Condition that changes the recommendation: average safety score below 3.
