## Information

Because you are boarding, the safe default is the two-step pattern: rename now, keep old code alive with a view, then drop the view after the new code ships.

Preflight check, run first:

```sql
SELECT DISTINCT dependent_ns.nspname AS schema_name,
       dependent_view.relname AS view_name
FROM pg_depend
JOIN pg_rewrite ON pg_depend.objid = pg_rewrite.oid
JOIN pg_class AS dependent_view ON pg_rewrite.ev_class = dependent_view.oid
JOIN pg_namespace AS dependent_ns ON dependent_view.relnamespace = dependent_ns.oid
WHERE pg_depend.refobjid = 'orders'::regclass
  AND pg_depend.refobjsubid = (
      SELECT attnum FROM pg_attribute
      WHERE attrelid = 'orders'::regclass AND attname = 'user_id'
  );
```

Run the migration:

```sql
BEGIN;
ALTER TABLE orders RENAME COLUMN user_id TO account_id;
CREATE VIEW orders_user_id_compat AS
    SELECT account_id AS user_id, orders.*
    FROM orders;
COMMIT;
```
