## Headline

No prompt makes a model stop generating false text. A prompt can force the model to quote sources and to write "not in the sources" when it lacks evidence. A check of the output against those sources then catches the false text that the prompt misses. So the answer is a pattern, not a single line.

### Background

The request asks for one prompt that ends false output from a model. The request names no documents, no tools, and no task type.

### Relevance

False output spreads into decisions when it reads as confident. A prompt that demands source lines and gap labels makes the false part visible before it spreads.

### Information

"Hallucination" here means text with content that no input supports. Surveys of the field report that such text appears even when instructions ask for accuracy [1]. Therefore a prompt reduces the rate; it does not remove it [judgment]. Detection methods that compare each stated claim against a source find unsupported text with no extra training [2].

Paste this pattern as the system prompt:

```text
Answer only from the sources below. After each claim, give its source line in brackets.
If the sources do not answer the question, write: "Not in the sources."
Do not add facts from memory. Mark any fact that you cannot trace as: [unverified].
For each number, give its source line or write: [unverified].
```

The pattern works with one pasted document as well as with a document set, so the user can start without extra tooling.

Assumption: The user works with a chat model without attached documents or tool access. Why not measured: the query does not state the setup. Validate by: run the pattern with one pasted document. If wrong: move the retrieval step to first place.

Alternative considered: add retrieval (RAG) as the first step. It loses as a first move because the prompt and the claim check cost less and produce a baseline for the retrieval decision [judgment].

### End

I recommend that we run these steps in order. Test texts are written before the work in each step, per evaluation-first practice.

1. **Apply the grounding pattern to one task and measure.** Increment: one working session that adds the prompt and scores sample answers. Blocker removed: no way to know whether the prompt works on this task. Test (stochastic, written first): metric = share of answers with an untraceable claim; baseline = 10 answers without the prompt; pass = the share drops by half or more at a sample size of 20; stop condition = no reduction across 20 answers, then move on. Cynefin: Complex, because the effect shows only after trials, and the pattern could break on numeric claims [inference].

2. **Run a claim check after each answer.** Increment: a checklist that maps each claim to a source line or labels it [unverified]. Blocker removed: unsupported claims stay invisible. Test (deterministic, written first), in Gherkin form:
```gherkin
Given an answer with N claims
When the checker maps each claim to a source
Then each claim has a source line or the label [unverified]
```
Cynefin: Clear, because a known rule applies and the action is one step.

3. **Decide about retrieval with a rubric after Steps 1 and 2.** Increment: one scored comparison in a session. Blocker removed: a guess about whether new systems are worth the setup. Test (evaluative, written first): a Pugh matrix with the criteria cut in untraceable claims (weight 5), setup time (weight 3), cost per answer (weight 2); pass when retrieval beats the prompt-only setup by 3 weighted points; evidence = the numbers from Step 1 [inference]. Cynefin: Complicated, because analysis between two good practices picks the winner. Step 3 MUST NOT start before the Step 1 numbers exist.

If the task type is fiction or brainstorm, the source rules do not apply; replace Steps 1 and 2 with a fact check of only the stated facts.

### Follow-up

Conditions that change the recommendation: an attached document or a tool turns the Step 3 rubric into Step 1, because grounding data already exists.
