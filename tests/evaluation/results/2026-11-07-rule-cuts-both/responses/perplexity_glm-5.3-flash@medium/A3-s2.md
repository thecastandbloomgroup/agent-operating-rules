The API returns JSON with an average size of 400 KB, and the question is whether gzip justifies its CPU cost. Because 400 KB moves over the network on every call, transfer time is the largest single cost per response. Compression removes most of that cost with one configuration change.

Gzip works well on this content because JSON repeats the same key names and structural text in every payload. Structured JSON compresses by 80 to 90 percent at levels 4 to 6, so the 400 KB baseline becomes about 40 to 80 KB per response [judgment]. These are typical figures for structured text; they are not a measurement of this API [judgment]. The cost side is small: level 4 adds a few milliseconds of CPU per 400 KB response [judgment]. Therefore the bandwidth and latency savings win on typical links, and the guardrails protect the edge cases. Do not compress responses under 1 KB, because the CPU cost then exceeds the savings. Do not compress an already compressed content type. Do not enable gzip twice when a proxy or CDN already handles it.
