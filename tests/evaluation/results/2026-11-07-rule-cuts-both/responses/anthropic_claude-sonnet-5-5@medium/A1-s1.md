## Headline

Yes, pin every version, including indirect ones, and update the pins on a schedule.

- Unpinned installs pull the newest release on each build, so any upstream change can break the build.
- Exact pins make installs repeatable, so the same file gives the same packages [1].
- Pins alone go stale, so a weekly update pull request keeps them current.
- The setup cost is under one working day [judgment].

The file requirements.txt lists the Python packages that the project installs. No entry has a fixed version. Per the user's message, the build broke twice last month after a library update.

## Relevance

## Information

Evidence:
- A pin fixes a package to one exact version, for example `requests==2.32.3`. Pip documents pinned requirements as the way to get repeatable installs.

[1]

- The pip-tools program turns a short list of direct packages (requirements.in) into a full pinned file, including indirect packages.
