## Headline

Replace open-ended retrospectives with a short cycle: identify where actions stop, test one change, and review the result.

- Attendance does not show whether the team has authority, time, or a clear next step. [judgment]
- One small change makes ownership and progress easier to check than a long action list. [judgment]
- If people fear consequences for speaking, address that before asking for more feedback. [judgment]

## Background

Your team attends retrospectives, but you report no resulting change. [1] The missing detail is where progress stops: choosing actions, doing them, or checking their effect.

## Relevance

Another discussion format does not directly address those gaps. [judgment] Therefore, make the next retrospective produce one testable change, not another list of concerns.

## Information

First, distinguish four failure points:

| Failure point | Evidence to check | Response |
|---|---|---|
| No clear action | Notes contain themes such as “communicate better” | Define an observable change |
| No execution | Actions have no owner, time, or review date | Reserve capacity and name an owner |
| No authority | The same external blocker returns | Assign a decision-maker outside the team |
| No useful result | Actions finish, but the problem remains | Change the experiment |

These are diagnostic categories, not findings about your team. [judgment]

Check the discussion climate separately. Silence does not establish agreement or safety. [judgment] Offer a private route for concerns if public discussion carries personal risk.

**Assumption:** Recent retrospective notes exist. **Why not measured:** The material does not state it. **Validate by:** Check the last three records. **If wrong:** Reconstruct one recent example together.

**Assumption:** The team controls at least one small work practice. **Why not measured:** The material does not state it. **Validate by:** Name one reversible change. **If wrong:** Seek an external decision instead.

**Alternative considered:** Change the facilitator or meeting format first. That loses because it does not directly test whether actions receive time and authority. [judgment]

## End

I recommend that we take these three steps:

### 1. Trace the last three retrospectives, within 20 minutes

**Test first, deterministic:**

```text
Given the last three retrospective records
When the team traces each agreed action
Then each action shows its owner, status, and review result
```

Create a short table with those fields. Mark missing information as missing, rather than guessing.

This removes the blocker of not knowing where progress stops. If records do not exist, use one example that participants remember.

**Domain: Complicated.** Record analysis selects the response; the inference comes from comparing commitments with results.

### 2. Prepare one change, within 25 minutes

**Test first, deterministic:**

```text
Given one recurring problem from Step 1
When the team writes its experiment card
Then the card states one change, owner, measure, budget, and review date
```

Step 2 MUST NOT start until Step 1 passes.

Choose a change within the team’s control. Write the card in this form:

> For two weeks, [owner] helps us use [new practice] when [specific situation] occurs.  
> We reserve [time]. We check [observable result] on [date].

Also record how the current practice performs. Use existing records where possible.

This removes vague commitments and exposes missing capacity. The owner coordinates the change; the owner does not become solely responsible for a team problem.

**Domain: Complicated.** Analysis of scope, authority, and available time determines a feasible experiment.

### 3. Run a capped trial, then decide

**Acceptance test first, stochastic:** This test covers outcomes that vary between occasions.

- **Metric:** Occasions when the agreed target behavior occurs.
- **Baseline:** Its frequency under the current practice, recorded in Step 2.
- **Sample:** The next five relevant occasions.
- **Pass threshold:** At least four successes, exceeding the baseline.
- **Limit:** Two weeks and 60 minutes of extra team time.
- **Stop condition:** Harm, blame, or a breach of the time limit.

If the baseline already meets that threshold, choose a measure that reflects the actual problem before starting.

Step 3 MUST NOT start until Step 2 passes. Run the trial and record results without naming individual failures.

At the next retrospective, review this result **before collecting new topics**. Keep, adjust, or stop the change. Accept it only if the threshold passes.

This adds a check on whether the action changes work. **Domain: Complex.** The trial tests a pattern through observation; unusual workload can break that pattern. Its benefit remains unproven.

## Follow-up

If the blocker lies outside team control, replace the local experiment with a specific decision request to someone with authority.

If people report retaliation, stop the public experiment and use a protected route to address that risk.
