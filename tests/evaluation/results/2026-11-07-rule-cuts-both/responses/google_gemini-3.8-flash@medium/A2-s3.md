# Information

This section covers the database locking behavior and query compatibility risks.
Renaming a table column in PostgreSQL modifies the system catalogs [1].
PostgreSQL executes this catalog update without rewriting table rows [1].
However, the operation requires an ACCESS EXCLUSIVE lock on the table [1].
This lock blocks concurrent operations, for example, read and write queries [1].
If long-running transactions hold locks on the orders table, the rename statement waits in queue.
Therefore, subsequent queries queue behind the rename statement and exhaust the connection pool [judgment].
Furthermore, it is 95% likely that client applications fail if queries reference the old column name [judgment].
