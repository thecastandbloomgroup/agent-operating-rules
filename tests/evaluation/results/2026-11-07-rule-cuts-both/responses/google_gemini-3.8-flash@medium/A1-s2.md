# Headline

Pin exact dependency versions in a lockfile, but keep loose requirements in your source files.
Lockfiles guarantee repeatable builds and eliminate unexpected breakage [1].
Source requirement files without pins allow tools to resolve newer versions during maintenance.

# Information

This section covers dependency pin practices and trade-offs.
Unpinned dependencies cause nondeterministic builds because the package installer fetches the latest releases at build time [1].
For example, a minor release can introduce backward-incompatible changes without notice [judgment].
In contrast, pinned dependencies ensure that every build installs identical file versions [1].
However, manual maintenance of transitive dependencies creates excessive labor [judgment].
Therefore, standard engineering practice separates source requirements from a generated lockfile [1].
