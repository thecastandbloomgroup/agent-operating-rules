## Headline

Roll back the newest change made before 09:12 now, then send the executives a short fact-based update.

- Rollback is the fastest way to restore service when the cause is unknown.
- The executive update needs only four facts, and you can write it in two minutes.
- Log triage runs only if the rollback fails to clear the errors.

## Background

Checkout has returned HTTP 500 for every user since 09:12. You are the on-call engineer. The executive call starts in ten minutes.

## Relevance

Each minute of downtime blocks all checkout revenue. The executives need facts and a next-update time, not a root cause.

- It is likely (66 to 100%) that a deploy, config change, or dependency change at or before 09:12 caused this. [judgment]
- Cynefin sorts work by how cause and effect relate. Chaotic work needs stabilisation first [1].

**Assumption log**

A2. A rollback or feature-flag path exists for that change. Why not measured: the material does not state it. Validate by: run the rollback command in dry-run mode. If wrong: replace Step 1 with a maintenance page.

A3. You can read logs and error rates for the checkout service. Why not measured: no tool can reach your systems. Validate by: open the error dashboard. If wrong: ask a teammate to join the incident.

**Alternative considered**

Find the root cause first, then fix it. This loses because the time to find a root cause is unbounded. A rollback takes minutes. [judgment]
