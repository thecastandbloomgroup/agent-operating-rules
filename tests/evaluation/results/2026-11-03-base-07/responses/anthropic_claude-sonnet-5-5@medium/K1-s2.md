## Headline

Restore the database pool size first, because the pool limit explains most of the added latency.

- The pool wait (`db.pool.acquire`) grew from 3 ms to 690 ms at p95, which is 77% of the 900 ms total.
- The query time did not change, and the database CPU is at 41%, so the database is not the bottleneck.
- The shorter cache lifetime raised the miss rate and added load on the pool.
- The ORM change is an unlikely cause, and a check can confirm that.

## Background

The p95 latency of `GET /customers/{id}/orders` rose from 120 ms to 900 ms after release 2026.10.21. The release cut the pool size from 50 to 8 and the acquire timeout from 30 s to 5 s. It also cut the cache lifetime from 300 s to 60 s and added `selectinload` to the order query.

## Relevance

The error rate rose from 0.02% to 0.40%, and 96% of the errors are pool timeouts. Users now get 503 errors, so each hour of delay costs failed requests.
