# Background

Last week release 2026.10.21 altered the object-relational mapping code, cache settings, and database pool settings [3].
After deployment, API p95 latency increased from 120 ms to 900 ms, and the error rate reached 0.40% [1].
You asked for an action plan based on the attached logs, traces, and code diff [1], [2], [3].

# Relevance

The API currently fails user requests with 503 errors during traffic spikes [2].
Addressing the connection bottlenecks restores latency to baseline and stops request timeouts [1].

# Information

The trace data shows that database query execution times remained stable across releases [1].
The order query p95 changed from 52 ms to 58 ms [1].
The order lines query p95 decreased from 30 ms to 26 ms due to the eager loading change [1], [3].
Therefore, the object-relational mapping change did not cause the latency spike [judgment].

In contrast, connection acquisition p95 latency rose from 3 ms to 690 ms [1].
This acquisition delay accounts for 88% of the total latency increase [1].
Two configuration changes combined to create this delay [3]:
First, cache time-to-live dropped from 300 seconds to 60 seconds [3].
This change caused the cache miss rate to jump from 12% to 31% under identical request rates [1].
Second, pool maximum size decreased from 50 to 8, and acquisition timeout decreased from 30 seconds to 5 seconds [3].
Consequently, worker threads queued for database connections, which led to pool timeouts [2].
