## Headline

Adopt a SQL formatter with a fixed config and a CI gate. The debate ends because a tool makes the call, not a person. Three moves: commit one config, reject non-compliant SQL in CI, and move reviews to logic only. This has high confidence: it removes the step where people decide, which is the step where the friction lives [judgment].

## Background

Review disagreements about SQL format repeat in every pull request. The request is to fix this culture problem.

## Relevance

Every review now spends time on style instead of correctness. A rule that a machine enforces removes that cost from each future review [judgment].

## Information

**Claims behind the plan:**

1. Human-enforced style rules fail because each reviewer judges alone; a formatter gives the same output for the same input, every time [judgment]. This is a Clear problem: a best practice exists, so applying it is one path [18].
2. Rule changes need one owner: the config file in the repo. Then the standard is versioned like code [judgment].
3. Culture follows the gate: once reviews stop debating style, the debates stop, because there is nothing left to argue about [judgment]. This claim rests on behavior, not opinion. Treat it with a stop condition in Step 4.

**Assumption log:**

- `A1. The team uses one SQL dialect. Why not measured: the material does not state it. Validate by: check the file extensions and database type in the repo. If wrong: set the dialect flag per folder.`
- `A2. The repo has a CI system that runs on each pull request. Why not measured: the material does not state it. Validate by: look for a pipeline file at the repo root. If wrong: use a pre-commit hook as the gate.`
- `A3. The team accepts a machine decision faster than a person's decision. Why not measured: no tool can reach it. Validate by: watch review comments for two weeks after Step 2. If wrong: run a vote on the config before Step 1 lands.`

**Alternative considered:** a team vote on a written style guide. It loses because a document still needs each person to apply it in each review, and a parser applies it 100% of the time at zero review cost [judgment].

## End
