Headline
Build a measured loop before changing prompts or models.
First, define what “wrong” means with agent-labeled examples.
Next, score every summary against ground truth from the ticket thread.
Then change one variable at a time only after a baseline exists.

Background
The support tool has an LLM summariser. Agents report errors, but no metric exists. That blocks diagnosis because prompt, data, retrieval, and workflow causes can look identical.

Relevance
Without a baseline, each fix is a guess and regressions stay invisible. A small labeled set can turn agent complaints into rates, causes, and release gates.

Information
LLM summary quality is judged across faithfulness, coverage, and usefulness; treating it as one score hides the failure mode [judgment].
A perceived error rate from agents is not comparable to a sampled error rate from the same ticket population [judgment].
A change is safer when one input change maps to one measured output change; this is inference from test design, not a source [inference].

A1. Agent complaints reflect support-ticket summaries, not another part of the tool. Why not measured: the material does not state scope. Validate by: sample 30 complained-about tickets. If wrong: rebuild the eval set for the real surface.
A2. Ticket text plus final resolution is available as ground truth. Why not measured: the material does not state data access. Validate by: read one ticket record. If wrong: use agent correction as the label.
A3. The team can run 200 historical tickets within one week. Why not measured: volume is not stated. Validate by: count last week’s closed tickets. If wrong: reduce the study to 50 tickets and lower confidence.

Alternative considered: switch model or rewrite the prompt now. It loses because the failure class is unmeasured, so gains cannot be separated from noise [judgment].

End
I recommend that we run four steps and gate release on measured error rate.

1. Create a labeled error taxonomy and seed set.
   Increment: one working session to tag 100 past summaries against ticket text.
   Blocker removed: “sometimes wrong” has no shared meaning.
   Kind: evaluative.
   Test first: rubric weights faithfulness 50%, coverage 30%, usefulness 20%; pass needs inter-rater agreement at Cohen’s kappa at least 0.70 on 30 double-tagged items; evidence is ticket quote plus label.
   Cynefin: Complicated, because experts can deduce classes from repeated ticket patterns.

2. Add deterministic logging for inputs, outputs, and agent edits.
   Increment: one session to log prompt version, input hash, output text, and final agent edit.
   Blocker removed: failures cannot be replayed.
   Kind: deterministic.
   Test first:
   Given a closed ticket with summary enabled,
   When the agent saves or edits the summary,
   Then the store has input hash, output text, prompt version, edit distance, and agent final text.
   Cynefin: Clear, because event fields and replay rules are known by deduction.

3. Measure a stochastic baseline and set a release gate.
   Increment: one session to run 200 sampled tickets through the current summariser.
   Blocker removed: no baseline exists.
   Kind: stochastic.
   Test first: metric is unsupported-claim rate per 100 atomic facts; baseline is current run; pass threshold is under 2 unsupported claims per 100 facts; sample size is 200 tickets; accept only at n=200.
   Cynefin: Complex, because causes emerge after trials; cap cost at 200 tickets and stop if severe privacy exposure appears.

4. Probe one fix per hypothesis, capped by budget.
   Increment: one session per probe for retrieval citation, shorter output schema, or agent confirmation step.
   Blocker removed: fixes cannot be ranked.
   Kind: stochastic.
   Test first: same metric and n=200 as Step 3; pass needs unsupported-claim rate at least 30% lower than baseline and no rise in missing critical facts above 5%; stop after two negative trials per hypothesis.
   Cynefin: Complex, because model behavior is inductive and a prompt win can break on new ticket types.
   Dependency: Step 4 MUST NOT start until Step 3 passes and Step 2 replay is live.

Follow-up
If A2 is false, replace ground truth with agent final text and report faithfulness against agent corrections only. If A3 is false, use n=50, report uncertainty as low confidence, and delay release gates until n=200.
