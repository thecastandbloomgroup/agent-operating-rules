# Headline

Retrospectives stop producing change when action items lack owners, deadlines, and follow-through, so fix the backlog, not the meeting.

- First, limit each retrospective to two action items, each with a named owner and a date.
- Second, open each meeting with a review of the last actions, so commitments stay visible.
- Third, rotate the facilitator and vary the format, because repetition lowers engagement.
- Fourth, if nothing changes in two cycles, escalate blockers to management instead of repeating the same items.

# Background

The team holds retrospectives on schedule and attendance is fine, but the same problems repeat and behavior does not change. This pattern usually shows a broken action loop, not a broken meeting.

# Relevance

A retrospective that generates no change costs the team one to two hours per cycle and teaches people that speaking up is pointless. However, the fix is cheap, so the team can test it within one sprint.

# Information

## Evidence

Retrospectives without tracked action items are the most common reported failure mode in agile practice literature [1][2]. Follow-up on prior actions is the strongest differentiator between effective and ritual-only retrospectives [1][2]. [inference] These claims rest on secondary sources from practice guides, not controlled studies, so treat them as strong practice consensus, not measured fact.

## Assumptions

A1. The team works in short iterations (one to three weeks). Why not measured: the material does not state it. Validate by: ask the team lead. If wrong: adjust cadence but keep the action-loop fix.

A2. The team has a named facilitator or scrum master. Why not measured: the material does not state it. Validate by: ask who runs the meeting. If wrong: assign a rotating facilitator, which is Step 3 anyway.

A3. Retrospective items are not already recorded in a tracking tool. Why not measured: the material does not state it. Validate by: check the team's board for an actions column. If wrong: skip Step 1 setup and go to Step 2.

## Alternative considered

Stopping retrospectives entirely saves the time, but it loses the team's only forum for process feedback. It loses because it removes the signal instead of fixing the loop.

# End

I recommend that we run the following actions in this order.

1. **Create a visible action register.** Increment: add an "Improvement Actions" column to the board, cap it at two items, and give each an owner and a date. Blocker removed: commitments scattered in meeting notes. Test (deterministic):
   - Given a retrospective ends,
   - When the notes are saved,
   - Then at most two items appear in the register, each with an owner, a date, and a status field.
   Cynefin: Clear. Cause and effect are known: visible tracking is a standard best practice [1].

2. **Open the next retrospective with a five-minute review of open actions.** Increment: one standing agenda item. Blocker removed: no feedback loop between meetings. Step 2 MUST NOT start until Step 1 passes. Test (deterministic):
   - Given the meeting starts,
   - When the agenda runs,
   - Then every open action from Step 1 is marked done, carried, or dropped with a reason.
   Cynefin: Clear. The rule is a known practice, deduction applies [2].

3. **Rotate the facilitator and change the format monthly.** Increment: publish a three-month rotation list and pick one alternative format, for example start-stop-continue or a timeline retrospective. Blocker removed: habituation. Test (evaluative, since engagement is a judgment): use a rubric with criteria of participation breadth (40%), new topics raised (40%), and duration within timebox (20%). Pass at 70% after two sessions, scored from attendance and notes. Cynefin: Complicated. Analysis of two or more session records picks the format [2].

4. **Escalate blockers that repeat across two cycles.** Increment: a one-page note to the responsible manager naming the blocker, its cost, and a requested decision. Blocker removed: problems the team cannot fix alone. Test (stochastic): metric is percent of escalated items closed within one month, sample size three escalations, pass at 66% or higher. Cynefin: Complex. System response is only visible after the probe, so cap cost at one hour per note [3].

# Follow-up

Conditions that change the recommendation: if A3 is false and a register exists with zero completed items, the failure is authority, not process, so start at Step 4.

If after three cycles the team still repeats the same complaints, the problem is likely cultural, more than process [judgment], and an external facilitator is worth the cost.
