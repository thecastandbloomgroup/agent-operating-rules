Headline
Measure failure types on a fixed set before any summariser change.

Agents report errors, but the team has no score to compare fixes.
Several error types need different fixes, so one model swap can miss the cause.
A small labeled sample gives a baseline before a prompt or model change.
The next release should beat that baseline on the same set.

Background
The support tool now writes summaries with a large language model.
Agents say those summaries are sometimes wrong.
The team has no metrics and wants a better summariser.

Relevance
A wrong summary can send an agent to the wrong fix.
Without a score, the next change can add a new error.

Information
This section covers the evidence, the assumptions, and the alternative.

ROUGE, a word-overlap score, does not show whether a summary stays faithful to the source [1].
An automatic judge can rank outputs, but it can prefer its own style [2].
Therefore the acceptance score should be a human label on a fixed set [judgment].
A first sample of 40 summaries fits one session of labels [judgment].
Confidence is low, because the team has not shared logs or complaint text.

A1. Agents mean factual errors or omissions. Why not measured: the material does not state it. Validate by: tag 10 complaints. If wrong: change the rubric weights.

A2. Weekly volume is at least 100 summaries. Why not measured: the material does not state it. Validate by: count 7 days of logs. If wrong: use 20 items over a longer window.

A3. One agent can label 40 items in one session. Why not measured: no tool can reach agent time. Validate by: time 10 labels. If wrong: cut the set to 20.

A4. A human label beats a model judge. Why not measured: the material does not state a judge. Validate by: ask the support lead which label wins. If wrong: add a second rater.

The strongest alternative is a model swap this week.
It loses because no baseline exists, so a gain cannot be shown [judgment].

End

The criterion is a named error type.
The weight is 100 percent.
The pass threshold is a match on 14 of 20 items.
The evidence is the tagged sheet.
In one session, collect 20 complaints and tag each with one type.

Metric: severe error share.
Baseline: the first full run.
Pass threshold: a repeat run stays within 5 percentage points.
Sample size: 40.

Criteria are severe error cut, agent time, and leak risk.
Weights are 50, 30, and 20 percent.
Pass threshold: the winner leads by at least 10 points.
Evidence: Step 3 labels plus a 30 minute timing on 10 items.
Compare two fixes in one session and pick the winner.
This removes the unchosen fix.
Domain: Complicated.
Reason: The matrix analysis picks the practice.

Step 5. Write this acceptance test before the rerun.
Metric: severe error share.
Baseline: the share from Step 3.
Pass threshold: a drop of at least 10 percentage points.
Sample size: 40.
Apply only the winning fix and rerun the 40 rows.
This adds a measured quality gain.
Domain: Complex.
Reason: Induction from the rerun, which breaks if the prompt is not the cause.

If A1 is false, replace the Step 4 criteria with the measured complaint type.
