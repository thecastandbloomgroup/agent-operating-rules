## Headline

Add measurement before changing the summariser. A rated sample of real tickets turns "sometimes wrong" into an error rate, the rate's error classes pick the first fix, and a small probe verifies that fix.

- A rubric and a sample of about 100 summaries produce the baseline number in one week.
- Grouping the errors by theme ranks the failure modes, so effort goes to the largest class first.
- A safe-to-fail probe tests one change on 20 tickets before any wider rollout [18].
- In-tool feedback buttons extend the sample into a permanent data stream.

## Background

The support tool now generates an LLM summary for each ticket. Agents report that summaries are wrong at times. No metrics exist, so the team cannot rank the errors or verify any fix.

## Relevance

Without a baseline, every prompt change is unverifiable and agent trust keeps falling. Measurement is the cheapest next step [judgment].

## Information

**Evidence.** The available evidence is one qualitative source: agent statements, with one theme, "summary content is wrong". Thematic grouping needs counts, and one source gives no count, so the theme is unranked [3]. No numbers exist yet, so every effect claim below carries the label [judgment] or creates its own measurement in a step.

**Assumption log.**

- A1. "Wrong" means incorrect content (added facts, missing facts, or wrong emphasis), not speed or tone. Why not measured: the material does not state it. Validate by: read 10 flagged summaries with two agents. If wrong: re-write the rubric weights before Step 3.
- A2. Ticket volume supports a 100-ticket sample within one week. Why not measured: the material does not state volume. Validate by: count tickets in the tool log. If wrong: cut the sample to 50 and widen the reported interval.
- A3. Agents will spend about 15 minutes each to rate 10 summaries. Why not measured: the material does not state agent time budgets. Validate by: ask one agent to time one batch. If wrong: shrink the set or schedule the rating into quiet hours.

**Alternative considered.** Replace the summariser with a template that copies ticket fields. It removes content errors by construction, so it is the strongest alternative. It loses for now because the probe path is cheaper to test and keeps the compression benefit [judgment]. If the rated error rate stays above 30% after two probe rounds, re-evaluate this alternative (see Follow-up).

**Confidence.** Low confidence, basis: one qualitative source and no measurements.

Blocker removed: there is no target to optimise. Test (evaluative, rubric first): pilot on 10 summaries; two agents agree within one rubric level on at least 80% of criteria; revise the rubric until they do.
