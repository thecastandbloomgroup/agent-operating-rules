## Headline

Build a measurement loop first, then fix the summariser. Supporting points, each one sentence:

1. "Sometimes wrong" is a report, not a metric; defined error categories and counted samples come first.
2. Agent feedback captured inside the tool produces labels during normal work, at a low cost.
3. Every summariser change then runs against a labeled eval set with a pass threshold, so improvement is provable.
4. Fixes land as small probes, one error type at a time, because cause and effect in model output appear only after runs [18].

## Background

A team added a summariser, a component that runs a large language model (LLM) and returns a short text of a support ticket, to their tool. Agents report that some summaries are wrong. No metrics exist, so the error rate and the error types are unknown.

## Relevance

Without measurement, each prompt change is a guess and agents lose trust in the output. A measurement loop makes every later fix testable and cheap to accept or reject.
