## Headline

No prompt stops hallucination completely. A prompt can reduce it. The prompt that works best combines three rules (answer only from given text, cite a source line, verify before sending), and a measured probe decides if the rules work.

1. A grounding rule pins output to the text in the prompt, so a wrong claim has no anchor.
2. A citation rule makes each claim checkable, so a fabricated claim becomes visible.
3. A measured question set, not prompt wording, decides whether the change works.

## Background

The request asks for one prompt that stops a language model from inventing facts. No target model, task, or document source came with the request. This response gives a prompt pattern and a test for it.

## Relevance

A fabricated fact in a model reply can pass as true to a reader who does not check it. One prompt edit plus one test costs less than one hour, so the fix is cheap to try this week.

## Information

**Evidence**

1. A 2023 survey of hallucination in natural language generation reports that models produce content unfaithful to the source or not grounded in any source. The survey places the main causes in training data and decoding, not in prompt wording. Therefore, wording constrains the failure, it does not remove it [1].
2. [judgment] Grounding, citation, and verify rules target the visible failure modes: fabrication, wrong attribution, and unverifiable claims.
3. [judgment] A baseline must come from a measured run, because hallucination rate varies by task and prompt.

**Assumption log**

- A1. The target is a general chat model used with pasted text, not a fine-tuned pipeline. Why not measured: the user has not answered. Validate by: name the model and setup in a reply. If wrong: the wording in Steps 1 to 3 changes, the four steps stay.
- A2. Fabricated citations count as hallucination for this use. Why not measured: the material does not state it. Validate by: score fabricated references in the question set. If wrong: drop citation scoring from Step 4.

**Alternative considered**

A one-line warning such as "Do not invent facts" or "Be accurate" is the strongest alternative. It loses because it states a goal, but not a procedure or a test, and the survey links the cause to the model, not the wording [1].

## End

I recommend that we run these four steps.

**Step 1. Add a grounding rule to the system prompt.**
Increment: one revised prompt. Blocker removed: generation from prior knowledge with no source anchor. Rule text: "Answer only from the text below. If the text omits the answer, reply: not stated in the text."
Test (deterministic):
Given the revised prompt and a short document,
When the model gets a question that the document does not answer,
Then the reply is "not stated in the text" with no added facts.
Cynefin: Clear, because this is one known best-practice step.

**Step 2. Add a citation rule.**
Increment: one rule plus a reply template. Capability added: a reader checks any claim against its source line. Rule text: "End every factual sentence with a tag: the document line it rests on, or UNSUPPORTED."
Test (deterministic):
Given a reply in the new format,
When a reviewer reads each tag,
Then each tag maps to one document line or reads UNSUPPORTED.
Cynefin: Clear, because this is one known step.

**Step 3. Add a verify pass.**
Increment: a second prompt pass after the draft. Blocker removed: silent fabrication inside a fluent draft. Instruction: "List each factual sentence. Mark it supported or unsupported against the document. Remove or mark each unsupported line." The analysis that picks the form: run the pass inside the same reply first; move it to a separate pass if the model marks its own lines as supported too often [judgment].
Test (deterministic):
Given a draft reply,
When the verify pass runs,
Then every unsupported line is removed or marked.
Cynefin: Complicated, because more than one good practice exists (same-reply pass, separate pass) and the question set picks the form.

**Step 4. Measure with a probe.** Step 4 MUST NOT start before Steps 1 to 3 are in place, and it needs one baseline run with the old prompt.
Increment: one run on a fixed question set. Build 20 questions: 10 the document answers, 10 it does not. Metric: share of replies with at least one false or untagged factual claim. Baseline: the rate from the old-prompt run. Pass threshold: at most half the baseline. Sample size: 20 replies per run. Stop condition: two prompt revisions with no fall below the threshold, then stop. Budget: one session.
Cynefin: Complex, because the effect of a wording change shows only after a run, so the probe carries a measure, a stop condition, and a cap.

Condition that changes the recommendation: if A1 is false and the model can call a tool that fetches sources, add a retrieval step before Step 1.
