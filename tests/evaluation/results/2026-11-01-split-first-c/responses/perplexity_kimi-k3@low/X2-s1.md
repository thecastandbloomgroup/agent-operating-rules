# Headline

Run one shorter retrospective this week, pick a single change from it, and assign it to a named owner with a review date.

- The likely cause is too many items and no owner, so fewer items with one owner each restores follow-through.
- Limit each retrospective to one to three actions, as untracked action lists predictably stall [judgment].
- Open each session by reviewing last session's actions, because closure makes the loop feel real to the team.

# Background

The retrospectives still happen and people still attend, but the outcomes do not change team behavior. The request asks for concrete steps to restart improvement.

# Relevance

A retrospective without follow-through costs meeting time and teaches the team that speaking up has no effect. Fixing the loop soon protects both morale and the team's ability to improve.

# Information

No quantitative data about the team's process was provided. The common failure modes, based on practitioner guidance, are these [1]:

1. Too many actions per session, so none get done.
2. No named owner, so each action belongs to everyone and no one.
3. No review of prior actions at the start of the next session, so actions vanish.
4. Items outside the team's control, which produce frustration instead of change.

These four themes are consistent across retrospective literature, and no surveyed source disagrees [1]. Diagnosis here rests on judgment, so the first recommendation includes a short diagnostic step.

Assumption log:

A1. The team controls at least some of the items raised. Why not measured: material does not state it. Validate by: list the last ten raised items and mark which the team can change. If wrong: escalate the out-of-scope items to management instead of team actions.

A2. Actions from past retrospectives were not tracked or completed. Why not measured: material does not state it. Validate by: ask the team to name the last completed retrospective action. If wrong: the problem is action quality, so Step 3 (smaller, testable actions) becomes the main fix.

Alternative considered: replace retrospectives with continuous one-on-one feedback. This loses because it removes the shared forum where the team sees patterns together, and it shifts all work to the facilitator [1].

# End

I recommend that we:

1. **Run a ten-minute diagnostic before the next retrospective.** Increment: list the last ten raised items, mark owner, status, and whether the team can change each. Blocker removed: unknown cause. Test (evaluative, rubric first): criteria are ownerless items (40%), more than three actions per session (30%), no review of prior actions (30%); pass threshold is a spoken verdict on the dominant cause; evidence is the marked list. Cynefin domain: Confused, because the cause of the stall is not yet known, so classification comes first.

2. **Cap the next retrospective at one action with a named owner and a review date.** Increment: one session ending with one action recorded where everyone can see it. Blocker removed: diffuse ownership. Test (deterministic):
   - Given a completed retrospective,
   - When the facilitator closes the session,
   - Then exactly one action exists with one named owner and one date.
   - Cynefin domain: Clear, because a known best practice (single owned action) applies directly [1].

3. **Open the following session with a five-minute review of that action.** Increment: add the review as a fixed agenda item. Blocker removed: actions disappearing between sessions. Test (deterministic):
   - Given an open action from the prior session,
   - When the new session starts,
   - Then its status is stated as done, in progress, or dropped with a reason.
   - Cynefin domain: Clear, because a standing agenda item is a standard practice. Step 3 depends on Step 2 and MUST NOT start until the test in Step 2 passes.

4. **Require each action to be small enough to finish before the next retrospective, or split it.** Increment: at action creation, ask "can one person finish this in one week?" and split if not. Blocker removed: actions too large to complete. Test (evaluative): rubric has one criterion, "estimable effort of one week or less," weight 100%, pass threshold is yes from the owner; evidence is the owner's estimate. Cynefin domain: Complicated, because sizing work needs the team's judgment of the specific item.

If A2 is false, Step 2 changes to "improve action quality" using Step 4's rubric on every action.
