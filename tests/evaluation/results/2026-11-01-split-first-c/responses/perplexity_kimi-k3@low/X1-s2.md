# Headline

The right first move is to measure the failure rate before changing anything, because "sometimes wrong" tells us nothing about frequency or failure type. Three steps cover it: build a labelled test set, score the summariser against it, then fix the dominant failure mode. The fixes differ by failure mode, so measurement decides the fix.

# Background

The support tool now includes an LLM-based summariser. Agents report it is "sometimes wrong". No metrics exist, so the true error rate, the error types, and where changes help are all unknown.

# Relevance

Acting on anecdotes alone risks weeks of prompt work on the wrong failure. A small measurement effort turns agent complaints into a ranked list of errors with numbers attached.

# Information

A typical LLM summariser fails in four ways: hallucination (adding facts not in the ticket), omission (dropping key facts), stale context (mixing older tickets), and format drift (not matching the expected shape). [judgment]

These modes need different fixes. Hallucination responds to grounding and citation requirements. Omission responds to schema-constrained output. The report "sometimes wrong" cannot tell them apart. About as likely as not (33 to 66%), based on published patterns, hallucination and omission dominate [judgment, no source].

A2. The summariser input is the ticket thread text. Why not measured: the material does not state it. Validate by: inspect five sample calls. If wrong: the test set construction in Step 1 needs adjustment, not the overall plan.

A3. A hundred past tickets exist and can be labelled by agents. Why not measured: the material does not state the volume. Validate by: query the ticket store. If wrong: reduce the test set to 50 tickets, which still supports a first pass.

**Alternative considered**: rewrite the prompt immediately based on agent comments. It loses because there is no baseline, so no way to know whether the rewrite helped or hurt; without labels, each complaint gets equal weight regardless of frequency [judgment].

# End

I recommend that we proceed in four steps.

1. **Build a labelled test set of 100 recent tickets, each with a gold summary written or approved by an agent.** This removes the blocker that no ground truth exists. Domain: Clear; labelling is a known best practice. Test (stochastic): 100 tickets labelled, inter-annotator agreement on a 20-ticket overlap at 80% or higher, sampled randomly across the last 90 days.

2. **Score the current summariser on the test set and classify every error by the four failure modes.** This removes the blocker that the failure type is unknown. Step 2 MUST NOT start until the test in Step 1 passes. Domain: Complicated; analysis picks the right fix, and this step is that analysis. Test (stochastic): metric is error rate per failure mode, baseline is the current system, pass threshold is a full classification of all 100 outputs with zero outputs unclassified.

3. **Apply the fix matched to the dominant failure mode in a capped probe.** Budget: one working session per fix variant. Stop condition: error rate on that mode drops below 5% on the test set, or the budget is spent. Domain: Complex; the effect of prompt and schema changes on LLM output is visible only afterward, so this is a safe-to-fail probe, and the 5% leverage estimate is a guess. Test (stochastic): metric is failure-mode-specific error rate, baseline from Step 2, pass threshold of 5% or lower at a sample size of 100.

4. **Add a standing quality panel: sample 10 live summaries per week and score them against the rubric from Step 2.** This adds the capability to detect regressions after each change. Step 4 runs after Step 3 and continues weekly. Domain: Clear; monitoring is a standard practice. Test (stochastic): the panel produces a weekly error rate for four consecutive weeks, sample size 10 per week.

If A3 is false, replace Step 1 with a 50-ticket set and halve the probe sample sizes.

# Follow-up

**Question 1**: Can agents label 100 past tickets within one week? The answer sets whether Step 1 runs at full size or at 50 tickets.

Conditions: if Step 2 shows format drift is the dominant mode, fix that first because it is the cheapest fix and unblocks the others.
