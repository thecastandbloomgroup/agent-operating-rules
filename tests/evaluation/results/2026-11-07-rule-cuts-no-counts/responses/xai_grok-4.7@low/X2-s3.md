Score recent retrospective actions before you change the meeting format.

Background
The team still holds retrospectives, which are regular meetings to inspect work and select changes. People attend, but the work does not change afterward, and the request is what to do next.

Relevance
Meeting time has no return until one past change is finished and checked. Therefore the next step is evidence, not a new format.

Information
Derby and Larsen state that a retrospective closes with experiments, and the next meeting inspects them [1].

The 2020 Scrum Guide is the rule set for the Scrum method. It says the team selects the most useful changes to how it works [2].

The team can add those changes to the sprint backlog, that is, the work list for the next cycle [2].

Psychological safety is the shared belief that people can name problems without punishment. Edmondson found that this belief predicts learning in work teams, that is, people change how they work [3].

The request states that people attend and that work does not change. [judgment] The first gap to test is actions with no owner and no later check.

Confidence in the cause for this team is low, because the request has no meeting notes. High confidence applies only to the general practice, from the two method sources above.

Assumption: The team keeps notes from past retrospectives. Why not measured: The material does not state it. Validate by: Ask the meeting lead for the last four notes. If wrong: Replace the score with three short member interviews.

Assumption: The main gap is unfinished actions, not fear. Why not measured: The material does not state it. Validate by: Count concrete problems in those notes. If wrong: Run the safety trial before owner rules.

Assumption: No open incident or failed release needs action now. Why not measured: The material does not state it. Validate by: Ask whether an incident is open. If wrong: Stabilise that incident before these steps.

The strongest alternative is to replace the retrospective format at the next meeting. It loses because a new format does not show whether old actions had owners. [judgment] The cost is another meeting with the same gap.

End
I recommend that we do four steps in this order.

1. Use this rubric before the score session. Criteria and weights are: action written down, 25, evidence is the notes. One owner named, 25, evidence is the notes. A review date named, 25, evidence is the notes. Done or explicitly stopped, 25, evidence is the notes or the board. The pass threshold is a mean of at least 50 of 100. Below 50 means the team did not finish and check actions. This kind is evaluative. In one session, score the last four retrospectives. This removes the unknown failure mode. Domain: Confused. Cause and effect are not visible yet, so this step gathers the data that classifies the work. Deduction is not possible before that score.

2. Use this test before you edit the agenda. This kind is deterministic.
Given the last meeting recorded at least one action
When the next meeting starts
Then the lead reads each action and its status before a new topic
In one session, put the prior action list first on the agenda. This removes the gap where the team never looks back. Domain: Clear. Deduction from the known rule that the next meeting inspects experiments [1]. Step 2 MUST NOT start until Step 1 has a score.

3. Use this test before you change the template. This kind is deterministic.
Given the team records a new action
When the retrospective ends
Then that action has one owner and sits in the chosen place
First compare three places: the next-cycle work list, the team board, and the meeting opening. Use two criteria: people see it between meetings, and the next retrospective checks it. Pick the place that meets both. That comparison selects the practice, because more than one good practice exists. In one session, update the template with one owner per action. This removes shared ownership, which means no owner. Domain: Complicated. Deduction follows that comparison. Step 3 MUST NOT start until Step 1 shows a mean score below 50.

4. Use this acceptance test before the trial. This kind is stochastic. The metric is the count of distinct problems people write before talk. The baseline is that count in the prior notes. The pass threshold is at least two more problems than the baseline. The sample size is one meeting. Accept the result only at that sample size. [judgment] Leverage is a guess. Stop if two people leave or refuse to write. The budget is one meeting, with no lasting format change. A trial is a small test you can stop. In that one meeting, people write in silence for eight minutes before talk. [judgment] Eight minutes fits one session. This removes silence before talk. Domain: Complex. Cause and effect appear only after the trial. This is induction from one trial. The pattern breaks if a manager runs the meeting and people still stay silent. Step 4 MUST NOT start until Step 1 shows fewer than two concrete problems per meeting.

Follow-up
If an incident is open now, stabilise it before Step 1. If notes do not exist, use three interviews in Step 1 instead of a score.
