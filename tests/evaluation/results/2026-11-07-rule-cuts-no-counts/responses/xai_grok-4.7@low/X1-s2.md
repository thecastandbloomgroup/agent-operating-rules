Headline
Measure summary errors before you change the summariser.
- The tool has no error score, so a prompt edit cannot be judged.
- Wrong summaries are not one fault. They split into separate types.
- A labeled sample of 30 pairs sets a baseline and a pass test.
- Change only the error type that changes the next agent action.

Background
The support tool now adds a summary from a large language model. A large language model writes new text from a prompt. Agents say the summary is sometimes wrong, and no metric exists. The request is to make the summariser better.

Relevance
Agents use the summary to choose the next reply. Therefore a false line can cause the wrong action. A change with no score can cut one error and add another.

Information
The request states two facts. There is a model summariser, and there are no metrics. These facts come from the current request [2].

An abstractive summary writes new sentences. It does not only copy lines. Such summaries often add facts the source does not support. Maynez and co-authors report this pattern on news summaries [1]. Therefore the first score should separate invented facts from missing facts. The same split is the right start for support text [judgment].

The costly fault is the one that changes the next agent action [judgment]. A missing refund ask can matter more than a stiff tone [judgment]. Which of the three error types is largest is not known. Each type is about as likely as not to be the largest, basis is zero labels [2].

Assumption: the input is one ticket or one chat, and the output is one agent summary. Why not measured: the material does not state the input shape. Validate by: open one production example. If wrong: keep the rubric and change the sample unit.

Assumption: wrong means a fact error or a gap that changes the next agent action. Why not measured: no labels exist. Validate by: label 30 recent pairs with the Step 1 rubric. If wrong: change the rubric weights before Step 3.

Assumption: two agents can label in one working session. Why not measured: the material does not state capacity. Validate by: book one shared hour with the support lead. If wrong: label 15 pairs and treat the baseline as weak.

Alternative considered: rewrite the prompt this week and ask agents if it feels better. It loses because there is still no before score, so the team cannot show that errors fell [judgment].

End
I recommend that we do these four steps in order.

Step 1. Classify the errors. Domain: Confused. The cause is not known, so the first act gathers labels. That act classifies the work.

Rubric first. Name fit has weight 40. Evidence is one primary label from a fixed list: correct, invented fact, missing fact, or other. Agreement has weight 40. Evidence is two agents on 10 shared pairs. Recency has weight 20. Evidence is pairs from the last 14 days. The pass mark has two parts. At least 24 of 30 pairs have one primary label. Agents agree on at least 7 of 10 shared pairs.

Increment: one session to export 30 pairs and apply that rubric. Blocker removed: unknown error type.

Step 2 must not start until the Step 1 pass mark is met.

Step 2. Record a baseline score. Domain: Clear. Deduction: once labels exist, the count rule is known.

Test first.
Given 30 labeled pairs from Step 1.
When the scorer counts pairs whose primary label is not correct.
Then it stores three rates: invented fact, missing fact, and other.
Each rate uses the 30-pair sample as its denominator.

Increment: one session to store those three rates. Blocker removed: no metric.

Step 3 must not start until Step 2 stores the three rates.

Step 3. Probe one fix for the largest rate. Domain: Complex. Cause shows up only after the trial, so this is induction. A fix for invented facts can raise missing facts. That break ends the probe. Leverage is a guess.

Test first. Metric: share of pairs with the target error type. Baseline: the Step 2 rate for that type. Pass threshold: at least 10 percentage points lower on 20 new pairs. Sample size: 20 held-out pairs. Stop if the new rate is not lower. Also stop if another error type rises by 5 points or more. Budget: one prompt or one check, and no model change.

Increment: one session to run that probe on the held-out set. Blocker removed: untested fix.

Step 4 must not start until the Step 3 test passes.

Step 4. Ship the probe change. Domain: Clear. Deduction: the pass rule is already fixed, so apply it.

Test first.
Given the held-out result from Step 3.
When the pass threshold holds and the stop rule does not fire.
Then release the change and keep the same weekly score.

Increment: one session to release and schedule the weekly score. Capability added: a checked summary change.
