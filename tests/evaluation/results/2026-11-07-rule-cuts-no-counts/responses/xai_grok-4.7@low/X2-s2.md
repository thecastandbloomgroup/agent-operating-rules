Headline
Treat each retrospective as a change loop with one owned action, not as a meeting that ends when people leave.

People already attend, so presence is not the gap.
The gap is an action with no owner and no check at the next meeting.
One small action beats a long list that no one finishes.
A new meeting format comes after that loop exists, not before it.

Background
The team attends retrospectives, but the work does not change after them. A retrospective is a regular meeting where the team inspects how it works. The request is a next step that makes each meeting produce one real change.

Relevance
A meeting with no checked action teaches the team that talk has no effect. Therefore the same problems return in the next work cycle, and people stop bringing real issues.

Information
The Scrum Guide says the retrospective plans improvements and moves the top ones onto the Sprint Backlog as soon as possible.
A Sprint Backlog is the team's work list for the current short cycle.
[1]

Derby and Larsen split the meeting into five stages, and the fourth stage decides what to do.
[2]

A decision with no owner and no check date does not change the work.
[judgment]

Assumption: notes exist, but actions lack one owner and a done mark. Why not measured: the material does not state it. Validate by: read the last three notes and count owners and done marks. If wrong: skip the one-action rule and run the safety probe in Step 4 first.

Assumption: the main failure is follow-through, not fear. Why not measured: the material does not state it. Validate by: the rubric in Step 2. If wrong: replace Step 3 with the safety probe.

The strongest alternative is to change the format or the facilitator first. That option loses, because a new format still fails when no one checks the last action.
[judgment]

End
I recommend that we close the loop in four steps, in this order.

1. Clear, by deduction from the rule that each improvement needs an owner and a check.
Test first:
Given the notes from the last three retrospectives,
When a reviewer counts actions, owners, and done marks,
Then each row shows one owner and a done or not-done mark.
In one session, score those notes.
This removes the blocker of an unknown follow-through rate.

2. Complicated, by analysis that picks the practice. This step MUST NOT start until the test in Step 1 passes.
Test first, as a rubric. Completion rate weighs 50. Owner rate weighs 30. Share of notes that name a person, a decision, or a missed promise weighs 20. Evidence is the Step 1 table. Follow-through fails if completion is under 50% or any action has no owner. Safety fails if that share is 0%.
In one session, score the table and record which failure wins.
This removes the blocker of applying the wrong fix.

3. Clear, by deduction from the same ownership rule. Do this step when Step 2 says follow-through fails.
Test first:
Given one selected action,
When the team ends the retrospective,
Then the work list shows one owner, one due date before the next meeting, and a check as the first item next time.
In one meeting, adopt that rule and place the action on the work list.
This removes the blocker of talk that never enters the work.

4. Complex, because cause and effect show up only after a small probe. Leverage is a guess. Run this after Step 1, in parallel with Steps 2 and 3, with a cap of 20 minutes and one meeting.
Test first. Metric: count of issues not in the last notes. Baseline: 0. Pass threshold: 1. Sample size: 1 meeting.
Ask one direct question about a missed promise, then stop after two silent prompts or at 20 minutes.
This tests whether fear blocks honest topics.

If the Step 2 rubric says safety fails, replace Step 3 with a repeat of Step 4 before any format change.

Follow-up
If the last three notes already show owners and done marks above the rubric line, do not add the one-action rule. Replace Step 3 with the safety probe.
