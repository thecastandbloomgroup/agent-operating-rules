Yes, turn on gzip for the API, because it cuts a 400 KB JSON response to roughly 40 to 100 KB for a small CPU cost.
- Size: JSON is repetitive text, so gzip (a common compression format for HTTP) shrinks it by about 75 to 90% [judgment].
- Speed: on a 10 Mbps link, 400 KB takes about 0.32 s to send. At 60 KB it takes about 0.05 s.
- Cost: compression uses CPU, so a canary test must confirm the load stays within limits.
- Risk: compression can leak secrets that a response reflects from user input, so review that case first.

Background: the API returns JSON with an average size of 400 KB. The question is whether to enable gzip. The material does not say which server, proxy, or CDN (content delivery network) sits in front of the API.

Relevance: large responses slow clients on mobile networks and raise egress cost. Compression is a low-effort change that affects every request.

Information: HTTP lets a client announce the encodings it accepts with the Accept-Encoding header. The server then labels the body with Content-Encoding.

The gzip format itself is defined in its own specification.
