## Headline

Yes, pin every dependency, including indirect ones, and update the pins on a schedule.

- Unpinned versions let a new release enter the build without review, which matches both failures last month [1].
- Pinning direct dependencies alone is not enough, because their own dependencies still change.
- A weekly update routine keeps the pins from going stale.

## Background

The project lists its Python dependencies in requirements.txt with no version limits. Each install pulls the newest release of every package. The build broke twice last month after a library update [1].

## Relevance

Each unpinned build can differ from the last one. Until the versions are fixed, any release can break the build again without a change in your code.
