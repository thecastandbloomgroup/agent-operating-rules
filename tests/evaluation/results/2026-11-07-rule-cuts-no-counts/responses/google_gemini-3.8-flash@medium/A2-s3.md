### Information

PostgreSQL executes `ALTER TABLE ... RENAME COLUMN` as a metadata change [1].
Therefore, the command does not rewrite table data on disk [1].
However, the operation acquires an `ACCESS EXCLUSIVE` lock [1].
This lock blocks all concurrent reads and writes until the transaction finishes [1].
Any running application code that queries `user_id` will fail immediately after the rename [judgment].
For this reason, migration scripts must enforce a short lock timeout [judgment].
