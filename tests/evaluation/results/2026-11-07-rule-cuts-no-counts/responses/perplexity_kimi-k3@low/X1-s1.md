## Headline

You cannot improve the summariser until you measure its errors, so start with a small human-scored evaluation set before changing anything.

- "Sometimes wrong" is anecdote. You need an error rate and error types from sampled tickets.
- The summariser has three failure sources: bad input, bad prompt, or wrong agent expectations.
- Measurement first, then one prompt or input fix, then re-measure against the same baseline.

1. **Build the evaluation set (Confused domain).** The failure mode is unknown, so classify it first. Sample 100 past tickets, have two agents score each summary on a 0 to 5 rubric. Rubric first: correctness (weight 50), completeness (30), conciseness (20). Pass threshold: mean 4.0. Record the error type on each failure. Kind: evaluative. Test: the rubric and scores exist per summary before any change. This removes the blocker of not knowing what "wrong" means.
