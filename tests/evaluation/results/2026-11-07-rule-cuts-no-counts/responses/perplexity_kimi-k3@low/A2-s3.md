Headline

Rename the column with one statement: `ALTER TABLE orders RENAME COLUMN user_id TO account_id;`.

- This is a metadata-only change, so it takes milliseconds, but it holds a short table lock.
- Code and views that reference `user_id` will fail until updated.

Background

You need to rename `orders.user_id` to `account_id` in Postgres before boarding a plane. The rename itself is simple; the risk is dependent objects and application code.

Relevance

A rename done in a hurry can break running queries and app code at deployment time. The points below prevent that.

Information

Run this exact statement (deterministic task):

```sql
ALTER TABLE orders RENAME COLUMN user_id TO account_id;
```

Key facts, from the Postgres documentation [1]:

- `RENAME COLUMN` rewrites only the catalog; it does not rewrite table data. Downtime is near zero.
- It requires an ACCESS EXCLUSIVE lock. It waits behind current transactions, and they wait behind it. On a busy table, run it in a low-traffic window.
- Views, functions, and triggers that mention `user_id` do not update automatically. Find them before the rename:

```sql
SELECT DISTINCT dependent_ns.nspname AS schema, dependent_view.relname AS view
FROM pg_depend
JOIN pg_rewrite ON pg_depend.objid = pg_rewrite.oid
JOIN pg_class dependent_view ON pg_rewrite.ev_class = dependent_view.oid
JOIN pg_namespace dependent_ns ON dependent_view.relnamespace = dependent_ns.oid
JOIN pg_class source_table ON pg_rewrite.ev_class <> dependent_view.oid
WHERE source_table.relname = 'orders';
```

Alternative considered: `CREATE VIEW orders AS SELECT ..., user_id AS account_id FROM orders_old` for zero-downtime migration. It loses here because you need a quick single rename, not a multi-step compatibility rollout [judgment].

Assumption: nothing else (indexes, foreign keys, app code) is being renamed or changed in this step. Why not measured: the material does not state it. Validate by: run `SELECT column_name FROM information_schema.columns WHERE table_schema = 'public';` after the rename. If wrong: your app may still reference `user_id` and error.
