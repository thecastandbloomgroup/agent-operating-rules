## Headline

Make the summariser better by measuring specific errors, testing one targeted fix, and keeping agents in control.

- First, turn “sometimes wrong” into a reviewed set of cases.
- Next, compare the current version with one candidate on the same unseen cases.

## Background

Agents report errors, but you have no metrics. [1] Therefore, the current evidence does not identify which errors occur or which change would help.

## Relevance

A fluent summary can hide a false claim or omit the customer’s main need. [judgment] Therefore, measure factual accuracy and useful coverage separately from agent satisfaction. [judgment]

## Information

**Evidence available:** one report of agent concerns, with no measured error rate or examples. [1]

**Confidence:** low confidence in any specific technical fix, because no reviewed failures exist yet.

Use these error categories:

| Category | What the reviewer checks |
|---|---|
| Unsupported claim | The summary states something the source does not support. |
| Wrong attribution | The summary assigns a statement or action to the wrong person. |
| Missing information | The summary omits information needed for the next support action. |
| Wrong status | The summary misstates the current problem, commitment, or next step. |
| Unsafe disclosure | The summary reveals information the agent should not receive. |

A summary can have several errors. Count it once in the overall defective-summary rate, but record every error category.

**Proposed primary metric:** summaries with at least one material error divided by summaries reviewed. [judgment] A material error changes the agent’s understanding or next action.

Also measure required-fact coverage, median agent correction time, and severe-error count. [judgment] Define a severe error as one that can cause unsafe disclosure, an incorrect customer commitment, or harmful action.

**Assumption:** Authorized staff can review source conversations and generated summaries. **Why not measured:** The material does not state it. **Validate by:** Check access with the support owner. **If wrong:** Use approved, redacted cases first.

**Alternative considered:** replace the model immediately. This loses because no evidence identifies the model as the cause rather than missing context or instructions. [judgment]

All sample sizes and thresholds below are proposed pilot settings, not measured results. [judgment]
