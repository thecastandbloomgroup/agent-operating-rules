## Headline

Replace opinion with an automated formatter that decides style, then measure whether review friction falls.

- A tool ends the debate because no person has to win it.
- A short written rule stops style comments in review.
- A four-week trial shows whether the culture changed.

## Background

The team disagrees on SQL format. Every code review (a peer check of a change) carries style comments. The request asks for a fix to the cause, not a style guide that nobody follows.

## Relevance

Each style comment costs review time and adds no correctness value [judgment]. The cost repeats on every pull request (PR, a proposed change). The friction grows as the team grows.

## Information

First, the cause. The disagreement is about preference, not correctness [judgment]. Preferences do not converge through discussion. A rule that a machine applies removes the need to converge.

Next, the evidence. Large teams scale style rules by enforcing them with tools, per Chapter 8 of the book below.

Winters, Manshreck, and Wright, *Software Engineering at Google* [1]

The formatter SQLFluff supports a configurable rule set and an automatic fix command.

SQLFluff documentation [2]

Both sources are enough to support the approach. Neither measures the effect on this team. Confidence that style comments fall by at least half is likely (66 to 100%), based on two sources and [judgment].

A3. One person can settle a tie. Why not measured: the material does not state it. Validate by: ask the team lead. If wrong: settle ties by a vote that is final for 90 days.

Alternative considered: write a long style guide and enforce it in review. It loses because humans apply it unevenly, so the friction stays [judgment]. A formatter applies it the same way each time.
