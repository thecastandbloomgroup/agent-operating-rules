## Headline

Use a grounding prompt that limits the model to supplied sources, allows "Not in the sources", and requires a quote for each claim.

- The prompt text is in the End section, Step 1.
- The prompt lowers the error rate, but no prompt removes all errors.
- The prompt works only when you supply the source text.
- Measure the result on your own questions before you trust it.

## Background

You asked for one prompt that stops a language model from stating false facts (hallucination). The material gives no model name, task, or source documents. The answer therefore targets a general chat model.

## Relevance

A false answer that sounds sure costs more than a refusal. A tested prompt gives you a known error rate instead of a guess.

## Information

## End

I recommend that we take these steps in order.

1. **Add the grounding prompt to the system message.** Increment: one paste, under 10 minutes. Blocker removed: the model answers from memory. Kind: deterministic. Domain: Clear, because one known practice exists: restrict answers to given text.

   Prompt text:

   ```text
   Use only the sources below. Do not use outside knowledge.
   If the sources do not answer the question, reply: "Not in the sources."
   Support each claim with a short quote from the sources.
   Before you answer, check each claim against its quote.
   Delete any claim that has no quote.
   If you are unsure, say "unsure" and give a confidence in percent.
   ```

   Test:

   ```gherkin
   Given the system message holds the grounding prompt
   When the user asks a question that the sources do not answer
   Then the reply is "Not in the sources."
   ```

2. **Attach the source text to every question.** Increment: one template with a source slot, built in one session. Blocker removed: no sources means no grounding. Kind: deterministic. Domain: Clear, because the template has one known form. Step 3 MUST NOT start until this test passes.

   Test:

   ```gherkin
   Given a question and a source file
   When the prompt is built
   Then the prompt contains the full source text and the grounding rule
   ```

3. **Measure the unsupported-claim rate.** Increment: 50 real questions, scored in one session. Blocker removed: no known error rate. Kind: stochastic. Domain: Complicated, because a reviewer can check each claim against its quote. Acceptance test, written first:
   - Metric: share of claims with no matching quote.
   - Baseline: the rate with no grounding prompt, measured on the same 50 questions.
   - Threshold: at least 50% lower than baseline [judgment].
   - Sample size: 50 questions.

   Accept the prompt only when the threshold is met.

4. **Run a probe: add a second call that checks the claims.** Run it in parallel with Step 3. Increment: 20 questions, one hour budget. Blocker removed: claims that pass the first check but fail the second. Kind: stochastic. Domain: Complex, because the effect shows only after a trial. Leverage is a guess. Stop if latency doubles or the unsupported-claim rate does not fall. Acceptance test, written first:
   - Metric: unsupported-claim rate.
   - Baseline: the Step 3 result.
   - Threshold: a further 25% drop [judgment].
   - Sample size: 20 questions.
