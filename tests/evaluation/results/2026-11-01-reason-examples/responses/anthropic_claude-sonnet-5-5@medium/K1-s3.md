## Headline

Raise the connection pool size, because the pool limit of 8 causes most of the added latency.

- The wait for a database connection explains 139 ms of the 162 ms rise in median latency [3].
- The slower cache adds load, but it is a smaller cause.
- The ORM change shows no cost in the query timings.
- The limit in ticket OPS-412 sets the safe pool size, so confirm it first.

## Background

p95 latency is the time under which 95% of requests finish. It rose from 120 ms to 900 ms after release 2026.10.21. The release cut the connection pool (a set of reusable database connections) from 50 to 8. It cut the cache lifetime from 300 s to 60 s. It also added an ORM (object-relational mapper) change that loads order lines with a second query.

## Relevance

The error rate rose from 0.02% to 0.40%. Of those errors, 96% are pool timeouts [3]. Customers see failed requests (HTTP 503) now.
