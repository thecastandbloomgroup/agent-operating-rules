## Headline

Use a module logger with an INFO threshold, and replace every `print` call with a logging call.

- Keep normal service and request messages at INFO.
- Use WARNING for invalid status values and ERROR for GET exceptions.
- Preserve database operations, routes, and HTTP responses.

## Background

The attached `service.py` uses `print` for service events and request logs. Its GET exception handler sends errors to standard error. [1]

## Relevance

The patch below replaces those calls and configures logging when the service starts. It also routes HTTP access messages through the same logger.

## Information

**Scope:** The patch changes log output, not service behavior. GET errors also include a traceback through `logger.exception`. All configured log output uses standard error.

**Assumption log**

A1. INFO means the minimum log level, not the level of every message. Why not measured: The material does not state it. Validate by: Review the WARNING and ERROR calls below. If wrong: Change those calls to `logger.info`.

**Alternative considered:** Set every message to INFO. This follows a literal reading, but loses the existing warning and error distinction. [judgment]

**Verification:** The scenarios below define acceptance checks. They have not been executed because this chat has no execution tool.
