## Headline

Separate the JWT migration from sign-up improvements, and define security and conversion checks before changing production. [judgment]

- The migration needs explicit rules for token storage, expiry, logout, and rollback. [judgment]
- Sign-up changes need a measured baseline rather than an assumed link between token format and conversion. [judgment]

## Background

The request combines a move from sessions to JSON Web Tokens (JWTs) with better sign-up conversion. [1] No source code, service configuration, or conversion data accompanies the request.

## Relevance

Authentication changes affect account access, while sign-up changes affect how users complete registration. Therefore, use separate acceptance checks for these two outcomes. [judgment]

## Information

**Scope:** First establish the current behavior and acceptance checks. The steps below produce reviewable documents, not a claim that code has changed.

**Assumption log**

A1. Conversion means completed sign-ups divided by sign-up starts. Why not measured: The material does not state it. Validate by: Confirm the funnel definition. If wrong: Change the conversion measure.

**Alternative considered:** Combine the token migration and sign-up redesign in one release. This loses because failures become harder to trace and reverse separately. [judgment]
