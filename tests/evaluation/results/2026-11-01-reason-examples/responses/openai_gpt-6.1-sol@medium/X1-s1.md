## Background

Agents report that the summariser is “sometimes wrong,” but no metrics show the frequency or type of error. [1]  
That report identifies a problem, but it does not establish its cause. [judgment]

## Relevance

A prompt change without a baseline prevents a fair comparison with the current version. [judgment]

**What the evidence supports**

- Agent reports establish that users perceive errors, not how often errors occur. [1]
- No metrics currently distinguish factual errors from omissions or unwanted style. [1]

**Define the measures before collecting results.** These definitions and thresholds are proposed starting points, not measured results. [judgment]

| Measure | Definition | Initial acceptance threshold |
|---|---|---|
| Material-error rate | Share of summaries with a wrong or missing fact that changes the agent’s next action | At least 25% below baseline, with two fewer affected summaries |

| Agent correction time | Median time agents need to make each summary usable | No increase from baseline |
| Response time | Median time from request to completed summary | No more than 20% above baseline |

Use tickets as the unit of comparison. Count a summary once for material-error rate, even when it contains several errors. [judgment]
