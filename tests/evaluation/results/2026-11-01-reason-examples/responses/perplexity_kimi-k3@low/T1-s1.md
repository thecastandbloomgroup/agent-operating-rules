## Headline

Adopt an automatic SQL formatter with a checked-in config file, and remove formatting from human review entirely. The friction is a tooling gap, not a culture gap. Four steps fix it: pick one formatter, encode one config, enforce it in the pipeline, and reformat the codebase once.

## Background

The team disagrees on SQL formatting, and the disagreement surfaces in every code review. The request is to fix the conflict, not to pick the "best" style.

## Relevance

Every review that debates formatting costs review time and damages trust. A formatter ends the debate permanently because the tool decides, not a person.

## Information

**Evidence.** Style disputes in review disappear when an automated formatter owns the decision; this is the standard outcome reported for gofmt, Black, and Prettier adoptions [judgment]. No team data on formatter use was provided, so current tooling is unknown.

I recommend that we:

1. **Pick the formatter.** Run sqlfluff and sqlfmt against five existing SQL files. Compare outputs in one session. Deterministic. Test: Given the config file, When the formatter runs on the five sample files, Then output matches the config rules with zero manual edits. Clear domain, the tool documentation defines each rule.

3. **Reformat the codebase once.** Run the formatter on all SQL files in one commit. Do it on a quiet day to limit merge conflicts. Deterministic.
