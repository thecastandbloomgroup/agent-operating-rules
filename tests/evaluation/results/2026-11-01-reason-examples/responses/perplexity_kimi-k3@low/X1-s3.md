## Headline

The fix is to build a measurement harness before changing any prompt, because "sometimes wrong" cannot be improved without a baseline. First, define what "wrong" means with agents. Next, grade 100 to 200 real summaries against that rubric. Then change one variable at a time and re-test.

## Background

The support tool has an LLM summariser. Agents report errors, but no metrics exist, so there is no way to know error rate, error type, or whether a change helps. The request is to improve quality.

## Relevance

Quality work on LLM output without a baseline produces churn, not improvement. A small eval set turns anecdote into a number, and each later change becomes testable.

1. **Define the error rubric (Evaluative, Clear domain, because one rubric per error type is standard practice).** Meet 3 agents for one hour.
