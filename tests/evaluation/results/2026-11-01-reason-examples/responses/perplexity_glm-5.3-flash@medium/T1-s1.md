## Headline

Stop the debate by making a tool own the format: pin one formatter config, reformat once, and enforce it in CI so reviews only discuss logic.

- A deterministic formatter removes style discussion because the tool, not a person, writes the final file shape.
- One reformat pull request clears old debt, so no reviewer edits format again by hand.
- A one sprint trial with a measured baseline confirms the friction drops before the team treats the change as settled.
- The config stays pinned in the repo, so future format fights end at config time, not review time.

## Background

The team disagrees on SQL formatting and the disagreement surfaces as repeated review comments. The request calls this a culture problem and asks for a fix.

## Relevance

Review friction costs attention on every change, so the fix should reduce reviewer effort from today, not after a long agreement process.

## Information

Evidence and analysis:

- Format debates between humans are a known waste source; one tool's stated design goal is to end style discussions by reformatting everything to one shape, with the tool as the single authority on style [1].
- A configurable SQL linter and formatter exists and supports fixed rules checked by a command [2].
- Friction from style comments, like reviewer disagreement on spacing and casing, is visible to reviewers with no tool in place. The size of this friction in the specific team is unknown [inference].
- The plan depends on the assumption that formatting, not something deeper, drives most comments. Uncertainty: likely (66 to 100%), based on the request statement, not on data [inference].

Assumption log:

- A1. Formatting causes most review friction, not deeper design disagreement. Why not measured: the material does not state it. Validate by: classify the review comments from the last 20 pull requests into format, design, and correctness. If wrong: shift effort from tooling to a written convention document for SQL design and naming.
- A2. SQL lives in files in one repo and uses one main dialect. Why not measured: the material does not state it. Validate by: search the repos for SQL files and their engines. If wrong: editors and BI tool settings replace some CI enforcement, and the config must cover more dialects.
- A3. The team uses pull request review with a CI system that can run checks. Why not measured: the material does not state it. Validate by: check one recent pull request for a CI run. If wrong: replace the CI gate with a pre-commit hook or a merge script check.

Alternative considered: a written style guide with reviewers as enforcers. It loses because human reviewers apply rules unevenly and slowly, while a formatter applies one shape with zero reviewer effort [judgment].
