## Headline

No prompt can stop hallucination, so the answer is a prompt pattern plus a check step. The pattern does three things: it restricts answers to given material, it permits the answer "not in the material", and it requires a quote for each claim. Prompting lowers the error rate; prompt safety is not the same as correctness [1]

Sources:

- [1] A. Kalai et al., "Why Language Models Hallucinate," OpenAI, 2025, arXiv:2509.04644.

## Background

The request asks for one prompt that removes false model output. The user gave no model name, no workflow, and no attached documents.

## Relevance

Hallucination is a default behavior of language models, not a prompt bug. Without grounding and a check step, a prompt alone keeps an error rate above zero [1] [2]

## Information

**Why a prompt alone fails.** Models guess when they lack facts because known answers are rewarded and unknown answers are punished in the same way, so the training pressure produces errors [1]. Models are also weak at knowing when they do not know, so the instruction "say you don't know" has a limited effect [2] [3]

Sources:

- [1] A. Kalai et al., "Why Language Models Hallucinate," OpenAI, 2025, arXiv:2509.04644. [S]
- [2] Z. Ji et al., "Survey of Hallucination in Natural Language Generation," ACM Computing Surveys, 2023. [S]
- [3] Zhang et al., "Do Large Language Models Know What They Don't Know?," Findings of ACL 2023. [S]

**The prompt pattern.** Use this template. It follows the restrict-and-cite approach [judgment]:

```text
Answer only from the attached material.
If the answer is not in the material, write exactly: not in the material.
After each claim, name the section you used and quote at most one sentence from it.
Do not use outside knowledge.
Do not guess numbers, names, or dates.
```

**Evidence for the pattern.** Quality improves when the model is grounded in retrieved material instead of memory alone [1] Citation demands make the check step possible, because a claim without a section name fails fast [judgment]

Sources:

- [1] P. Lewis et al., "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks," NeurIPS, 2020. [S]

Confidence: high confidence, because two independent analyses agree on the cause and the mitigation [1] [2]

**Alternative considered.** The alternative is a prompt that only adds "if you are unsure, say so". It loses because models score weakly at self-knowledge [1], so the effective fix is to remove the need to rely on memory, not to ask the model to detect its own gaps.

## End

I recommend that we adopt the template, ground it in documents, and add a check step. First, measure the current unsupported-claim rate, because the baseline sets the pass threshold for every later test.

1. **Measure the baseline.** Run 20 questions with known answers against the current prompt and count answers with an unsupported claim. Blocker removed: no threshold can be set without a number. Test (stochastic): metric is the unsupported-claim rate, sample size 20, baseline from this run. Domain: Clear, because the count of bad answers is known from the output. Step 2 waits for this run.

2. **Adopt the template and attach material.** Use the prompt above and give the model the source documents in each request. Blocker removed: reliance on model memory, which is the main error source [1]. Test (deterministic):
   ```gherkin
   Given a document with 10 planted facts,
   When the model answers 10 questions about them,
   Then each claim cites a section and a quote, and each gap answers "not in the material".
   ```
   Domain: Clear, because the vendor prompt guides give one known practice per gap.

3. **Add a check pass as a probe.** After the answer, run a second prompt that verifies each claim against the material and deletes claims without a quote. Blocker removed: the residual prompt-level error rate that steps 1 and 2 leave. Test (stochastic): sample 10 documents, metric is the unsupported-claim rate after the check. Stop condition: discard the step if the rate does not fall below one half of the baseline from step 1. Budget: one working session. Domain: Complex, because the effect shows only after a trial, so this is a safe-to-fail probe, not a commitment. Run steps 2 and 3 in parallel; step 3 uses the baseline from step 1.
