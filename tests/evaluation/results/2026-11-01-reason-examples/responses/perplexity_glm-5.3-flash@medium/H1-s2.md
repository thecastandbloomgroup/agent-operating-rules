Background

Checkout returns HTTP 500 to every user since 09:12 today. The user is the on-call engineer with ten minutes before an executive call.

Relevance

Every minute of outage blocks orders, so the recovery action must come before analysis. The exec call needs facts, not blame.

Evidence

One of these shared causes fits the pattern: a deploy, a config change, an expired certificate, or a saturated resource such as a database connection pool. [judgment]

A total failure with a fixed 09:12 start is a step change, not drift, so a timeline check in the deploy log is the fastest discriminator. [judgment]
