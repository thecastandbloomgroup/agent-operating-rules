## Headline

Measure the errors before you change anything: audit 100 real summaries, build a small golden test set, and gate every fix on a re-run score. The work divides into four parts: a one-week error audit, a golden set of 30 conversations, a baseline score run, and a capped fix-and-retest cycle.

## Background

The support tool now uses an LLM to write summaries of support conversations. Agents judge some summaries as wrong, but no metrics exist. So "wrong" has no definition and no count.

## Relevance

Each failed summary costs agents time to re-read the full ticket. Measurement is the precondition for any prompt or model change, because a re-run needs a score to compare against.

## Information

**Evidence.**
Theme: agent reports state that errors exist but name no error type. Only one source supports this theme: the agent reports in this request. That single source still matters, because it names the failure but not its type.

Claim: abstractive LLM summaries produce factual errors at measurable rates, and the error types include added facts, dropped facts, and wrong entities [19]. This source is a survey, so it is tertiary. It supports the schema for the audit, not the decision to run one.

Claim: automated fact checking of generated text is a workable method. RAGAS computes a faithfulness score by checking each claim in the output against the source text [21]. A judge LLM agreed with human raters on quality scores over 80% of the time in one large comparison [20].

Confidence: high, three independent methods (human tags, automated claims check, judge model) [judgment].

- A2. The tool stores conversations and summaries in a queryable store. Why not measured: the request does not state it. Validate by: pull one week of data before Step 1. If wrong: sample by hand from agent screens, cost of one extra session.

**Alternative considered.** Direct prompt fixes, for example "use only ticket facts and cite turns", with no baseline. It loses: without a baseline score, a real drop in errors is not distinguishable from run-to-run noise [inference].

## End

1. **Audit 100 recent conversations.** Tag each summary error with a fixed list: added fact, dropped fact, wrong entity, wrong tone, too long, other. Increment: one prep session, one tagging week. Blocker removed: "wrong" has no definition. Kind: evaluative. Rubric first: tag coverage of the full sample, weight 0.3; two taggers agree with kappa of 0.6 or higher (a common threshold [inference]), weight 0.4; each tag cites the exact transcript line it fails, weight 0.3; pass at 0.85 total.
