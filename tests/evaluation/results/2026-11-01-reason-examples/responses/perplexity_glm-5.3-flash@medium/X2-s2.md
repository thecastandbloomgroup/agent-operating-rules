## Headline

Restart the link between retrospectives and work: audit past action items, end every retrospective with one owned experiment, and cap a trial to verify the fix. Supporting points:

1. An audit shows where the chain breaks, because nobody has checked what old action items became.
2. One owner and one check date per action makes completion visible, because unowned actions do not get done [1].
3. A small capped trial tests whether the new format actually changes team behavior [3].

## Background

A team holds retrospectives. Attendance continues, but no work practice changes afterward. The request asks what to do.

## Relevance

A retrospective that produces no change costs the team about one hour each cycle [inference]. Fixing it restores the team's main feedback loop.

## Information

Reviewer questions and answers from the material: the query says attendance stays but outputs stop. The query does not say the retro format, team size, tooling, or whether action items exist in writing.

Evidence:

1. Derby and Larsen define the retrospective as ending with committed action items, chosen by the team, with owners [1].
2. Edmondson found that teams raise and act on problems only when members feel safe to report them [2].
3. Snowden and Boone describe the Complex domain: the effect of a process change shows only after a small trial, so the trial needs a measure, a stop condition, and a budget [3].

Assumption log:

1. `A1. Retrospectives end with written action items. Why not measured: the query does not state it. Validate by: the audit in Step 1. If wrong: build the log first, because Step 2 needs one.`
2. `A2. Action items lack owners and check dates. Why not measured: no tool access; the audit will confirm. Validate by: the audit in Step 1. If wrong: the format alone is not the cause, so look at workload.`
3. `A3. Members feel safe to raise problems. Why not measured: a poll costs one meeting minute. Validate by: the poll in Step 4. If wrong: add a facilitation change before Step 3.`

Alternative considered: cancel retrospectives and switch to an async survey. It loses because a survey still needs a follow-up step with an owner, so the same gap reappears [judgment].

## End

I recommend that we do the following, in this order.

1. **Audit the last three retrospectives.** Increment: list each past action item and mark it done, not done, or missing an owner. This is Confused work, because the audit output decides the rest. Classification: deterministic. Test, written first:
   ```gherkin
   Given the notes of the last three retrospectives
   When the audit session ends
   Then every action item carries a status and an owner or "none"
   ```
2. **Change the format so each retro ends with exactly one experiment.** Wait for Step 1's output. Increment: one session; the facilitator ends each retro with one named owner, one measure, and one check date, as the practice prescribes [1]. This is Clear work, because one known practice exists. Classification: deterministic. Test:
   ```gherkin
   Given a retro with_retro_notes in the shared doc
   When the session ends
   Then the doc holds one experiment with an owner, a measure, and a check date
   ```
   The experiment MUST be small enough to finish in one working session, because large actions hide the cause and effect again.
3. **Run one experiment as a capped probe.** Run this in parallel with Step 2 after Step 1 ends. Increment: one experiment over one sprint, capped at two hours of work and one measure: count of completed action items per retro. This is Complex work, because the effect on the team shows only after a trial [3]. Classification: stochastic. Acceptance test, written first: metric = completed actions per retro, baseline = 0 from the Step 1 audit, pass threshold = 1 or more, sample size = 3 retros. Stop condition: after 3 retros below threshold, revert the format change. Leverage here is a guess until the sample is complete.
4. **Poll safety once, anonymously.** Run it in parallel with Step 2, capped at 10 minutes and one question. Increment: one question: "Can you raise a problem in a retro without risk?" on a 1 to 5 scale. This is Complex work, because the effect of safety on speaking up shows only after a trial [2]. Classification: stochastic. Acceptance test, written first: metric = mean score, baseline = the first poll, pass threshold = any rise, sample size = all attendees. Stop condition: mean score falls for one poll, so revert to no poll and review facilitation.

Steps 3 and 4 MUST NOT run their acceptance check until Step 2 has produced three retros.
