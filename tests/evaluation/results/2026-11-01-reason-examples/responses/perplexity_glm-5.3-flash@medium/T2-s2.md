## Headline

No prompt eliminates hallucination. The best pattern binds the model to given context, requires a quote for each claim, allows an abstain reply, and measures the error rate on a fixed test set.

- A permission to abstain cuts invented facts more than an instruction such as "do not hallucinate" [2], [3].
- Residual error stays above zero on open-world questions. The model's own report states this limitation [1].
- Stated confidence from the model is weakly calibrated, so treat it as a rough signal [2].

## Background

The request asks for one prompt that stops a model from producing false content. The setup is assumed to be a general-purpose chat model with no file context supplied.

## Relevance

False answers read as polished text and pass a casual check. A measured setup reduces that risk in daily use, starting this week.

## Information

**Cause analysis.** Four causes, with no overlap:

1. The model predicts likely text. It does not verify text against a source. [inference]
2. The needed fact is absent from the model's knowledge or from the context.
3. Models rate poorly at separating known from unknown facts, so they fill gaps [2].
4. No measurement exists, so a reader judges output by style alone. [judgment]

**Evidence.**

OpenAI lists hallucination as an open limitation of its model [1].

Abstention options and verification loops lower false claims in published experiments [2], [3].

Theme: "give a source or abstain" reduces invented facts. Two of two sources support it. None disagree in the cited work [2], [3]. Confidence: likely (66 to 100%).

For a taxonomy of hallucination types, see the survey by Ji et al. [4].

**The prompt.** Install this as the system prompt:

```text
You answer only from the context provided in each request.
If the context lacks the answer, reply exactly: "Not in the context."
Quote the supporting line next to every factual claim. No quote, no claim.
If outside knowledge is needed, say which parts are outside knowledge and tag them [low confidence 50%].
Do not soften an abstention. "Not in the context" is a full answer.
```

**Assumption log.**

A1. The model is a general-purpose LLM used in chat, with no retrieval tool. Why not measured: the material does not state the model or stack. Validate by: check the model name in the session. If wrong: edit the abstain line; the test design still holds.

A2. The task type is open factual问答... the task type is open factual question and answer. Why not measured: the material does not state the task. Validate by: read the user's next five live prompts. If wrong: for code tasks, add a compile-and-run check to Step 2.

**Alternative considered.** The strongest alternative is the instruction "never invent facts" with no context rule. It loses because it adds no source of truth and gives no path to abstain. Instruction-only changes show partial and unreliable gains [2] [inference].

## End

I recommend that we run a measured, seven-day trial.

**Step 1.** Build the answer key: 20 in-context questions and 5 out-of-context questions, each with a verified answer. Blocker removed: no baseline exists. Test (deterministic), written first:

```gherkin
Given the answer key with 25 entries
When each entry is checked against a named source
Then every entry has a recorded truth value
```

Domain: Clear, because one known practice applies and cause and effect are known to all.

**Step 2.** Run the current prompt on all 25 questions and count false claims. Blocker removed: unknown starting rate. Kind: stochastic. Acceptance test, written first: metric is false-claim count; baseline is this run; sample size is 25 questions, one trial each. Domain: Clear, because counting fixed inputs is one step. Step 3 MUST NOT start until the count in Step 2 is recorded.

**Step 3.** Swap in the prompt above and run the same 25 questions. Blocker removed: unsourced and gap-filling replies. Kind: stochastic. Acceptance test, written first: false-claim count drops by half or more versus Step 2, at n = 25, one trial per question. Domain: Complex, because the effect shows only after the trial; this is a safe-to-fail probe, capped at 2 working sessions. If the count rises or stays flat, stop and switch to supplying real documents in the context.

**Step 4.** After Step 3 passes, review 5 quoted claims by hand each week. Blocker removed: silent drift in daily use. Kind: evaluative. Rubric, written first: criterion "quote matches the quoted text", weight 5; criterion "claim stays within the quote's scope", weight 3; pass threshold: 8 of 8 points per checked claim; evidence: the source line named in the quote. Domain: Clear, because the check is one known practice.

## Follow-up

- Conditions that change the recommendation: if the task is code or math, add a compile-and-run check to Step 2. If the model has a retrieval tool, fold tool output into the context line of the prompt.
- Open questions: none. A wrong guess about the stack is cheap to reverse, so A1 and A2 cover it.
