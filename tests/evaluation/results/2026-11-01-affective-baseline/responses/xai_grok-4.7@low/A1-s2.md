Pin every dependency to the last set that built.

- Two library updates broke the build last month, so the cause is an open install.
- An exact pin makes the same file install the same versions.
- A lock file also fixes packages that other packages need.
- A planned upgrade still takes fixes on purpose.

Background

The requirements file names libraries and gives no versions. The build broke twice last month after a library update. The request is whether to pin those versions.

Relevance

The next install can change with no project edit. A pin holds the last good set until an upgrade is chosen.

Information

First, the request states that nothing is pinned. Next, the build broke twice last month after a library update [1]. Therefore the install changed without a project edit [judgment]. An exact match, written as ==, selects one version [2]. A lock file is a generated list of exact versions, including packages that other packages need [judgment].
