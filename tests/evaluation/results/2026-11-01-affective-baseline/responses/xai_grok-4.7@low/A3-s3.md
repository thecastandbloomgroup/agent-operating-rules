The API returns JSON bodies. The average size is 400 KB. The request is whether gzip belongs on those responses.

Each full response moves 400 KB before compression. A cut in that size lowers latency and egress cost on accepting clients. [judgment]

HTTP defines Content-Encoding and Accept-Encoding for this negotiation.
[1]
A 400 KB JSON body sits well above the point where gzip overhead pays back. [judgment] Repeated keys drive that result. [judgment] This API has no measured ratio in the material. The confidence level is medium, with the basis that size is known and the ratio is not.

Brotli alone is the strongest alternative. It can make a smaller JSON body than gzip. [judgment] It loses because many API clients accept gzip and do not accept Brotli. [judgment]

A compression attack can leak a secret that shares a body with attacker-chosen text.
[2]
