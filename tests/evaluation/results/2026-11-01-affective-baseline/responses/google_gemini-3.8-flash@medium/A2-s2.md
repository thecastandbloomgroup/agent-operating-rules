# Information

PostgreSQL executes column renames through table metadata updates [1].
The operation completes in less than ten milliseconds under normal conditions [1].
However, the statement requires an ACCESS EXCLUSIVE lock on the target table [1].
This lock blocks concurrent reads and writes until the transaction finishes [1].
If other transactions hold locks on the orders table, the rename statement queues behind them [1].
Subsequent queries then queue behind the rename statement [1].

A lock timeout prevents this queue buildup [1].
Setting lock_timeout to two seconds aborts the rename if the lock is not available immediately [1].
The SQL command is:

```sql
BEGIN;
SET LOCAL lock_timeout = '2s';
ALTER TABLE orders RENAME COLUMN user_id TO account_id;
COMMIT;
```
