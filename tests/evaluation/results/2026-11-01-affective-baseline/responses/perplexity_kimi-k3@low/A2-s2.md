# Headline

Run one ALTER TABLE command to rename the column, but check views and code that reference `user_id` first.

1. The SQL is `ALTER TABLE orders RENAME COLUMN user_id TO account_id;`.
2. The rename takes a brief exclusive lock, so run it during low traffic.
3. Views, functions, and app code that use `user_id` will break until updated.

## Background

A column rename in a Postgres `orders` table is needed before the user boards a plane. The operation itself is one statement.

## Relevance

A failed or partial rename can break queries while the user is offline. Checking dependents first prevents outage during the flight.

## Information

The command [judgment, standard Postgres DDL]:

```sql
ALTER TABLE orders RENAME COLUMN user_id TO account_id;
```

Find dependent objects first [judgment]:

```sql
SELECT DISTINCT dependent_ns.nspname || '.' || dependent_view.relname AS object
FROM pg_depend
JOIN pg_rewrite ON pg_depend.objid = pg_rewrite.oid
JOIN pg_class AS dependent_view ON pg_rewrite.ev_class = dependent_view.oid
JOIN pg_namespace AS dependent_ns ON dependent_view.relnamespace = dependent_ns.oid
JOIN pg_class AS source_table ON pg_depend.refobjid = source_table.oid
JOIN pg_attribute ON pg_depend.refobjid = pg_attribute.attrelid
  AND pg_depend.refobjsubid = pg_attribute.attnum
WHERE source_table.relname = 'orders' AND pg_attribute.attname = 'user_id';
```
