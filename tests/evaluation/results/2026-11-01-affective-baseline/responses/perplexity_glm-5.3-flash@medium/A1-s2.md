## Background

The project keeps dependencies in requirements.txt with no version pins. Two builds broke last month after a library update. The request asks whether to pin.

## Relevance

Every new library release threatens the next build until pins exist. A one-session file change removes the threat, so the change pays for itself before the next release cycle.

## Information

Baseline: zero pins in the file, and two build failures in one month. The target baseline is zero failures from version drift.

A requirement without a version marker resolves to the newest package version that satisfies it at install time [1]. That is, the same requirements.txt produces different builds across days. Pin means an exact marker, for example "requests==2.31.0". Transitive dependencies are the packages that your direct packages need.

1. Pin every direct dependency with "==". Increment: edit requirements.txt and run one install, in one session. Blocker removed: builds stop depending on remote releases. Test, deterministic, written first:
