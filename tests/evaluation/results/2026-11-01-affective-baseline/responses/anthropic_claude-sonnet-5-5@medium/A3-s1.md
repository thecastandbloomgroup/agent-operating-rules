Yes, turn on gzip for the API, because it cuts the bytes sent per response and costs little CPU.

- Size: JSON text compresses well, so a 400 KB response likely drops to about 40 to 80 KB [judgment].
- Compatibility: HTTP clients that send `Accept-Encoding: gzip` get compressed bodies, and others get plain bodies.
- Cost: gzip at level 5 or 6 adds a few milliseconds of CPU per response [judgment].
- Risk: a canary rollout limits the harm if the CPU cost is higher than expected.

Background: the API returns JSON responses of 400 KB on average. The question is whether to enable gzip compression (a method that shrinks data before it is sent). The material does not say whether a proxy or CDN already compresses responses.

Relevance: large responses raise transfer time and bandwidth cost on every call. Compression is a one-line setting in most servers, so the decision is cheap to act on.

Evidence: HTTP defines `Content-Encoding` and `Accept-Encoding` for this purpose, and servers MUST NOT compress for clients that do not accept it.

The gzip format itself is a stable, public specification.
