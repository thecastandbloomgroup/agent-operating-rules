## Headline

Replace all 14 `print` calls in `service.py` with calls to one module logger, and set the root level to INFO in `main`.

- The file has 14 `print` calls and no logger, so the change is mechanical and stays inside one file.
- Lazy `%s` arguments keep the message text the same and add time and level to each line.
- Two calls carry severity words (`WARNING`, `ERROR`), so they map to `warning` and `error`, and both pass an INFO threshold.
- The `sys` import becomes unused and must go.

## Background

`service.py` is a 129-line HTTP service over an SQLite orders database. It logs with `print`. The request is to use the standard `logging` module at INFO level.

## Relevance

`print` gives no timestamp and no level. It also cannot be filtered. The `logging` module adds all three without a new dependency.

## Information

**Evidence.** The file has 14 `print` calls: 3 in `main`, 2 each in `init_db`, `update_status` and `do_GET`, and 1 each in `connect`, `get_order`, `list_orders`, `do_POST` and `log_message` (counted in service.py). One `print` writes to `sys.stderr`. The `logging` module sends output to stderr by default and supports `%s` lazy arguments [1].

**Replacement map.** Add `import logging` and `logger = logging.getLogger("order_service")` at module level.
