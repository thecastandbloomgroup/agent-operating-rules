## Headline

Measure the flake rate first, then group failures by cause, then quarantine the worst tests.

- The request gives no data, so the first need is a baseline flake rate.
- Published studies show that a few causes explain most flaky tests, so grouping failures finds them fast.
- Quarantine stops the harm to the team while the fixes happen.

## Background

The build gives different results on some runs. The request does not say which job, which tool, or how often. This response treats "flaky" as: the same commit both passes and fails.

## Relevance

A flaky build teaches the team to ignore red results. Real defects then reach the main branch.
