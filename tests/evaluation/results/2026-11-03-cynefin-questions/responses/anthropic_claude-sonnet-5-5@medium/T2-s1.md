## Headline

No single prompt stops hallucination, but a grounding prompt plus supplied source text cuts it most.

- Models guess when they lack facts, so give them the facts in the prompt.
- Permission to say "not in the sources" removes the pressure to guess.
- A measured test on your own questions shows whether it works.

## Background

You ask for one prompt that stops a model from inventing facts (hallucination). Research treats hallucination as a built-in property of text generators, not a switch [1]. A prompt lowers the rate. It does not set it to zero.

## Relevance

A wrong fact stated with confidence costs you trust and rework. A cheap prompt change plus source text reduces that risk today.

## Information

Evidence:

- Hallucination comes from gaps in training data and from the pressure to always produce an answer. Source: survey of the field [1].
- Retrieval-augmented generation (adding source text to the prompt) gave more factual output than a model using memory alone on open-domain questions [2].
- It is very likely (90 to 100%) that a prompt alone cannot remove all errors [judgment].
- The prompt below has no published score. Its effect on your tasks is unknown until you test it [no source].

Assumption log:

A1. You use a chat model without web search or tools. Why not measured: the material does not state it. Validate by: check the tool settings. If wrong: skip Step 1 and adapt the prompt to the tool.

A2. Your tasks are factual questions with source documents. Why not measured: the user has not answered. Validate by: list your five most common questions. If wrong: Step 3 needs a new metric.

The prompt:

```text
Answer only from the text in <sources>.
If the sources do not contain the answer, reply: "Not in the sources."
Quote the exact text that supports each claim.
Do not use outside knowledge.
Do not guess names, numbers, dates, or links.
If the question is unclear, ask one question first.
```

Alternative considered: ask the model to "be accurate" or "do not hallucinate". This loses because the instruction gives no source and no safe exit, so the model still guesses [judgment].

## End

I recommend that we take these steps in order:

1. Put the source text inside `<sources>` tags in every request. This removes the largest blocker: the model has no facts to use.
   - Kind: deterministic.
   - Cynefin: Complicated. An expert can pick the right documents from the data (deduction by analysis).
   - Increment: one working session for one document set.
   - Test:
     - Given a question and a source file
     - When the request is built
     - Then the request contains the full source text inside the `<sources>` tags

2. Install the prompt above as the system message. Step 2 MUST NOT start until the test in Step 1 passes. It adds a safe exit for missing answers.
   - Kind: deterministic.
   - Cynefin: Clear. One known practice applies (deduction from a known rule).
   - Increment: one configuration change.
   - Test:
     - Given the configuration file
     - When the application loads it
     - Then the system message equals the prompt text exactly

3. Run a safe-to-fail probe on 50 real questions. Step 3 MUST NOT start until Step 2 passes. It shows whether the prompt works on your tasks.
   - Kind: stochastic.
   - Cynefin: Complex. The result shows only after a trial (induction from trials). Gaps in source coverage could break the pattern. Leverage is a guess.
   - Metric: share of answers with a claim not found in the sources.
   - Baseline: the same 50 questions without the prompt.
   - Pass threshold: at most half the baseline rate.
   - Sample size: 50 questions.
   - Budget: one working session. Stop and revise the prompt if the rate does not fall after 50 questions.
