## Headline

Configure standard logging at `INFO` level and replace every `print` call.

- Use `INFO` for normal events, `WARNING` for invalid input, and `ERROR` for failed requests.
- Route HTTP access messages through the same logger.
- Leave database operations, HTTP responses, and service control flow unchanged.

## Background

The supplied `service.py` uses `print` for service events and HTTP access messages. Its GET error handler writes directly to standard error. [1]

## Relevance

A shared logger gives these messages consistent levels and formatting without changing the API behavior. [judgment]

## Information

The patch uses deferred formatting, such as `logger.info("opening database %s", DB_PATH)`. The GET error handler uses `logger.exception` to include the traceback. [judgment]
