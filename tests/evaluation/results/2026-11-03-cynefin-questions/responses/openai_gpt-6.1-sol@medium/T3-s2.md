## Headline

Define the security requirements and conversion baseline before changing production authentication. [judgment]

- JSON Web Tokens (JWTs) specify a token format, not a complete session management or logout design. [1]
- Treat conversion as a separate measured change, so security and product changes have distinct acceptance tests. [judgment]

## Background

The request combines an authentication migration with a sign-up conversion goal. No code, current authentication design, or conversion baseline accompanies the request. [2]

## Relevance

An immediate implementation would require guesses about access controls, active sessions, and the intended sign-up outcome. These guesses create avoidable security and measurement risks. [judgment]

## Information

**Authentication scope.** First, establish why JWTs are needed and which clients must use them. Preserve explicit requirements for logout, token revocation, account suspension, and active sessions. [judgment]

**Conversion scope.** Next, define conversion as a specific completed event divided by eligible sign-up starts. Keep security and abuse controls within the acceptance criteria. [judgment]

**Alternative considered:** Replace sessions immediately and simplify sign-up in the same release. This loses because the supplied request provides neither security acceptance criteria nor a conversion baseline. [judgment]

No implementation assumptions are adopted yet.
