Headline
Each retrospective must close with one owned experiment that the next retrospective checks before any new topic.

Unchecked actions leave the same work in place after people attend.
Lists that exceed one cycle finish nothing, so the output must shrink to one experiment.
Notes that never name a real constraint need a separate small probe.

Background
The team still holds a retrospective, a regular meeting to inspect how the team works. People attend, but the work does not shift after it. This request asks for a next step that makes the retrospective produce a shift.

Relevance
The next retrospective is the cheapest test of a fix. Another cycle without a checked experiment spends the same time and keeps the same blocker.

Information
The Scrum Guide requires the team to address the most impactful improvements as soon as possible [1].

Therefore those improvements belong in the Sprint Backlog, the plan for the next work cycle [1].

Derby and Larsen describe the retrospective as a meeting that ends in experiments the team will try [2].

So two sources support follow-through as the change mechanism.
[1]

[2]

No source in this session disagrees. This pattern is likely (66 to 100%), because those two sources describe the mechanism and the request names no other cause.

[judgment] Attendance without a plan change cannot shift the work.

A1. The team already holds a recurring retrospective. Why not measured: the material does not state cadence. Validate by: check the calendar for the last four events. If wrong: schedule one retrospective before any format change.

A2. "Nothing shifts" means no completed experiment and no measured outcome shift in the last three cycles. Why not measured: the material does not state it. Validate by: read the last three retrospective notes. If wrong: show those measures instead of changing the format.

A3. No open incident requires stopping delivery today. Why not measured: the material does not state harm. Validate by: ask the facilitator if a safety or delivery incident is open. If wrong: stabilise that incident before this list.

A4. The team can place one experiment into its current work plan. Why not measured: the material does not name the planning tool. Validate by: open the plan and add one card. If wrong: keep the experiment in the retrospective record until a plan tool exists.

The strongest alternative is to cancel retrospectives and track ideas on a board. It loses because the team then has no shared time to check an experiment [judgment]. The board can hold the one experiment after the loop exists.

End
I recommend that we

1. Clear. Deduction from the known rule that improvements enter the next plan [1]. Cause and effect are known to anyone who applies that rule.
Test:
Given the last retrospective listed experiments,
When the facilitator opens the next retrospective,
Then each experiment shows done or not done before any new topic starts.
Increment: edit the agenda template in one working session so the first 10 minutes are that status check.
Blocker removed: experiments vanish between retrospectives.

2. Complicated. An expert can pick one experiment from the status data, and more than one good practice exists. The inference is analysis, not a single universal rule.
Rubric, scored in the close, before any new experiment is accepted:
- Still open: weight 50. Evidence is the Step 1 status. Pass when status is not done.
- Fits one cycle: weight 30. Evidence is the owner's statement that it finishes before the next retrospective. Pass when that statement is yes.
- Team controls it: weight 20. Evidence is the absence of an owner outside the team. Pass when no outside owner exists.
Threshold: keep the highest score at or above 70. If none reach 70, write one new experiment and score it the same way before close.
Increment: run that score once, in the close, for at most 20 minutes.
Blocker removed: a list too large to finish.
Step 2 starts in the same retrospective, after the Step 1 check.

3. Clear. Deduction from the same plan rule [1].
Test:
Given one experiment card exists from Step 2,
When planning starts,
Then that card is visible in the current plan before new feature work fills the plan.
Increment: add the card in one planning session.
Blocker removed: the experiment has no time.
Step 3 MUST NOT start until the Step 2 score produces one card.

4. Complex. The result shows only after a trial. The inference is induction from one probe. The pattern breaks if people fear notes will leave the team.
Acceptance test, written before the probe:
Metric: share of attendees who name one constraint the team controls.
Baseline: 0 documented constraints, per A2, until the notes confirm a different count.
Pass threshold: at least 50% of attendees.
Sample size: all attendees at one retrospective.
Stop condition: below 50%, stop the form and add no second tool.
Budget: one retrospective, no new tool spend.
Increment: ask one anonymous question in that retrospective, then count the replies.
Blocker probed: silence about the real constraint.
Run Step 4 in parallel with Steps 2 and 3. Do not order it by claimed leverage. Its leverage is a guess.

Follow-up
If A2 is false and outcomes already shifted, replace Step 2 with a readout of those measures.
If A3 is false, stop this list and stabilise the open incident first.
If A4 is false, Step 3 uses the retrospective record as the plan until a tool exists.
