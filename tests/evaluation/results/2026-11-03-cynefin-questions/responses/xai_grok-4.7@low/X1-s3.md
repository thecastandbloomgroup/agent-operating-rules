Headline
Measure what "wrong" means, then change only the top error.
A shared rubric turns agent complaints into scores.
A sample of real tickets sets the baseline.
One change targets the most common error.
A release gate accepts that change only if a new sample beats the baseline.

Background
The support tool now writes summaries with a large language model (LLM).
Agents say those summaries are sometimes wrong, and the team has no metrics.
The request is to make the summariser better.

Relevance
Without a baseline, a prompt change can add cost and still fail agents.
A scored sample this week shows which error to fix first.

Information
Abstractive summaries often state facts that are not in the source [1].
Common automatic scores agree poorly with human judgments of summary quality [2].
Therefore the first measure is a human rubric on real tickets. [judgment]

A1. Wrong means a false fact, a missing required fact, or a wrong owner or status. Why not measured: the material does not state the error types. Validate by: three agents mark five bad summaries. If wrong: change the rubric categories before any score.

A2. Each summary links to a source thread. Why not measured: the material does not state the data model. Validate by: open one ticket and its summary. If wrong: stop scoring until the link exists.

A3. Thirty recent summaries can set a first baseline. Why not measured: no tool can reach production data. Validate by: count summaries from the last 14 days. If wrong: score every summary you have when the count is under 30.

Alternative considered
Rewrite the prompt now and ask if it feels better.
This loses because there is no baseline and no pass threshold. [judgment]

End
I recommend that we do four steps.

1. Write the rubric before any scoring.
Kind: evaluative.
Rubric: faithfulness 40%, required facts 30%, owner and status 20%, harmful omission 10%.
A harmful omission is a missing fact that sends the wrong next action.
Pass threshold: mean at least 80 of 100, and faithfulness at least 3 of 4 on every item.
Evidence: the source thread and the summary text.
This step is Complicated, because an expert can set categories from known failure types [1].
The inference is deduction from that known pattern.
Increment: one rubric page in one session.
Blocker removed: no shared meaning of wrong.
Step 2 MUST NOT start until this rubric is agreed.

2. Score 30 summaries with the Step 1 rubric.
Kind: evaluative.
Use the Step 1 weights, threshold, and evidence rule.
A claim counts only when the scorer can point to a span in the thread.
Two people score each item and note each disagreement.
This step is Clear, because anyone applies the written practice.
Increment: one scored sheet in one session.
Blocker removed: no baseline number.
Step 3 MUST NOT start until this sheet names the top category.

3. Change only the top error from Step 2.
Kind: stochastic.
Acceptance test: the metric is mean faithfulness on a 4-point scale.
The baseline is the Step 2 mean.
The pass threshold is a gain of at least 0.5 points. [judgment]
The sample size is 30.
This step is Complex, because the result shows only after a trial.
The inference is induction from that trial.
A shift in ticket mix can break the pattern.
Probe budget: one prompt or input change, 30 new summaries, and stop if the mean falls below the baseline.
Increment: one change in one session.
Blocker removed: the most common error.
Step 4 MUST NOT start until this sample is scored.

4. Release only when Step 3 meets its threshold.
Kind: deterministic.
Given a scored sample of 30.
When its mean faithfulness is compared with the baseline.
Then release only if the gain is at least 0.5 points.
This step is Clear, because the gate is a known rule.
Increment: one release decision in one session.
Blocker removed: untested changes reaching agents.

Follow-up
If A1 is false, replace the rubric weights before Step 2.
If A2 is false, replace Step 2 with a task to store the source link.
If the Step 2 top error is not faithfulness, keep the same gate but score that category instead.
