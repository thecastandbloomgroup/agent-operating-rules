## Headline

Automate SQL formatting with a committed formatter config, CI checks, and a pre-commit hook; this removes the debate instead of winning it.

- A tool enforces one style, so reviewers stop enforcing style by hand.
- A committed config makes the style a shared artifact, not a person's preference.
- A two-week trial measures whether review friction actually drops.

## Background

The team disagrees on SQL style. Every code review reopens the arguments. The request is to remove the friction, not to settle the style debate by discussion.

## Relevance

The cost repeats on every review. Each unformatted file reopens a debate that produces no value, so the fix pays off from the next pull request.

## Information

The mechanism is to move enforcement from people to software. Then the review debates logic, not commas.

Fallback rule if a formatter is missing: keep the debate out of review by parking it in one config file and one tool. The recommendation below states how.

Evidence for the tool candidates:

Formatter criteria that matter per the sqlfluff documentation: dialect coverage, CI use, and config control [1].

- sqlfluff supports many SQL dialects and lint rules [1].
- sqlfmt formats dbt and Jinja SQL with few options by design [2].

Confidence: high, because the friction source is enforcement at review time, which a tool removes [judgment].

Alternative considered (strongest):

- A written style guide that reviewers enforce by hand. It loses because it keeps enforcement with humans at review time, which is where the friction happens. Adoption also fades without automation [judgment].

Assumption log:

A1. The team reviews code through pull requests on a git host with CI. Why not measured: the material does not state it. Validate by: check the repository for a CI config file. If wrong: replace the CI check with a local check script in the review checklist.

A2. The team writes most SQL in one dialect. Why not measured: no tool can reach the code from this session. Validate by: scan three files for dialect markers. If wrong: choose sqlfluff with a per-file dialect setting [1].

A3. The team can adopt a formatter config without sign-off from another group. Why not measured: measuring costs more than the decision is worth. Validate by: ask the repository owner once. If wrong: add one approval step before rollout.
