## Headline

Migrate to short-lived access JWTs with revocable refresh tokens, and cut over in parallel with the current sessions.

- The refresh token keeps server-side revocation, which pure stateless auth removes.
- A dual-accept layer lets existing sessions expire naturally, so the cutover has no downtime.
- Conversion work starts with funnel measurement, because no baseline exists in the material.

## Background

The request has two parts: replace session-based auth with JWT, and raise sign-up conversion. The material contains no code, no traffic profile, no compliance rules, and no metrics.

## Relevance

Token lifetimes and revocation rules are hard to change after clients depend on them. Conversion fixes without a baseline are guesses, so measurement comes first.

## Information

**Evidence**

- RFC 7519 defines a token with claims that any verifier can check without a store lookup [1]. So access checks avoid one database query per request.
- RFC 8725 requires algorithm pinning and short token lifetimes [2].
- The OWASP Session Management Cheat Sheet specifies expiry and renewal requirements for session tokens [3].
- Wroblewski reports that shorter forms raise completion, because fewer fields lower user anxiety [4].
- Theme: sign-up form length drives completion. One source supports it [4]. No disagreeing source found. Confidence stays low: one secondary source only, plus [judgment].
- Baseline conversion is 20% to 50% of sign-up page views for typical web products [judgment].
- Choose a 15-minute access lifetime and a 30-day refresh lifetime, with rotation on use [judgment], per RFC 8725 guidance [2].

**Assumption log**

A1. Auth is a web app with a server-side session store, and browser clients only. Why not measured: the material does not state the stack. Validate by: inspect the repo config. If wrong: mobile clients need token storage and refresh guidance added.
A2. 15-minute access and 30-day refresh lifetimes meet your security policy. Why not measured: no policy in the material. Validate by: read the security policy or ask a reviewer. If wrong: change two constants before launch.
A3. Compliance does not require instant kill of every user token today. Why not measured: no compliance doc in the material. Validate by: search policies for "account termination". If wrong: add a revocation list in Step 2.
A4. Current sign-up completion falls between 20% and 50% of page views. Why not measured: no analytics access in this session. Validate by: the funnel export in Step 1. If wrong: set the A/B threshold from the real baseline.

**Alternative considered**

Keep sessions and harden them, or use stateless JWT with no refresh token. The first loses because token auth removes a store lookup per request and scales without shared session state [judgment]. The second loses because it removes instant revocation, which contradicts OWASP guidance [3].
