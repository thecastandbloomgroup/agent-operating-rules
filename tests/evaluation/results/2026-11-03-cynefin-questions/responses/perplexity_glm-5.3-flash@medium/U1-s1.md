1. **Classify the failures.** Increment: collect logs from the last 20 runs, tag each failure as test flake, infra, or timeout, and count each tag. Blocker: the unknown cause blocks every fix. Test, deterministic [14]:

2. **Quarantine the tagged test flakes.** Increment: move tagged tests to a separate job, capped at one session. Blocker: broken green state blocks merging. Test, deterministic [14]:

   ```gherkin

   When the main suite runs
   Then the build result does not depend on that test
   ```

   Cynefin: Clear [18], one known practice, applied by deduction.

3. **Probe the top cause, in parallel with Step 2.** Increment: pick the tag with the highest count, isolate one suspect test, and run it 10 times with and without the suspected factor, for example a shared database. Budget: one session, then stop. Metric: reproduction count. Baseline: the result of Step 1. Pass threshold: at least 3 reproductions in 10 runs. Sample size: 10. Stop condition: if the suspect does not reproduce, drop it and take the next tag or test. Cynefin: Complex [18], because the effect shows only after the trial, and this is a safe-to-fail probe.

4. **Fix and verify.** This step waits until Step 3 reproduces a cause. Increment: apply one fix, then run the suspect test 10 times and the main suite twice. Blocker: the highest-count failure tag. Test, deterministic [14]:

   ```gherkin
   Given the applied fix
   When the suspect test runs 10 times and the main suite runs twice
   Then all 12 runs pass
   ```

   Cynefin: Complicated [18], because the Step 3 data plus a cause analysis pick the fix, and the fix is checked by deduction.

Conditions that change this plan:

- If the diff test in A2 shows that failures follow code changes, skip Steps 2 to 4 and treat the newest commit as the suspect.
- If Step 1 finds no repeatable tag, the cause is infra; move to the timeout tag or vendor status page next.
