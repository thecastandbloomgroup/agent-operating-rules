# Information

Correction 1: the earlier headline said Postgres renames the column "everywhere at once, including inside views and functions". That overstates the case. Dependent views keep working, because a stored view query references columns by internal position, not by name [1]. However, a view's output column names do not change until the view is recreated [judgment]. Function bodies are worse: the stored source text of a function keeps the old name, so a function that reads `user_id` fails at call time until it is edited [judgment]. Validate both by the catalog queries in Steps 1 and 4.

Correction 2: the earlier assumption log said to fix views with `ALTER VIEW ... ALTER COLUMN`. That command does not exist. Postgres `ALTER VIEW` handles the view name, schema, and options only [2]. The correct fix is `CREATE OR REPLACE VIEW` with the new column name in its query [3].

Correction 3: the rename statement itself, the preflight query in Step 1, and the Gherkin check are correct and unchanged.
