# Information

PostgreSQL documentation specifies the exact syntax for column renames [1].
The command ALTER TABLE table_name RENAME COLUMN old_name TO new_name is standard across all supported PostgreSQL versions [1].
The command updates the system catalog table pg_attribute directly [1].
Therefore, the database engine does not rewrite table data files on disk [1].
The execution takes less than five milliseconds once the lock is acquired [1].

However, PostgreSQL requires an ACCESS EXCLUSIVE lock for all ALTER TABLE variants unless explicitly exempted [1].
This lock level blocks concurrent SELECT, INSERT, UPDATE, and DELETE operations [1].
If an uncommitted transaction holds a lock on the table, the rename statement waits [1].
All subsequent queries on that table then queue behind the rename statement [1].
Therefore, a lock timeout remains necessary to prevent connection exhaustion [1].
