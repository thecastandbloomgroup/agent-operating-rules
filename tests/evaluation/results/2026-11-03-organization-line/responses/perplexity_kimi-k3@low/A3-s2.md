Background: the API returns JSON averaging 400 KB per response, and the open question is whether to enable gzip compression on responses.

Relevance: this choice affects client latency, egress bandwidth cost, and server CPU use on every request, so it is worth deciding explicitly rather than leaving the default off.

Information: gzip is a mature, universally supported coding defined in RFC 1952, and HTTP content negotiation via Accept-Encoding and Content-Encoding is standardized behavior, so clients that cannot decompress simply receive the plain body [1][2].
