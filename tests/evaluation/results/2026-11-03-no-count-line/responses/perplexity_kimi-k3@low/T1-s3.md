## Background

The team disagrees on SQL formatting and this causes friction in code reviews. The request asks to fix the underlying culture problem.

## Relevance

Style arguments in reviews consume reviewer time and erode trust. A tool-enforced standard ends the arguments at the source, so reviews cover logic instead of layout [judgment].

## Information

Evidence and reasoning:

- Teams that automate style enforcement report that review comments shift from style to substance [1]. This is a secondary source and is the strongest source available; no team-internal data exists.
- Formatting disputes persist when the standard lives in a document, and fade when a tool applies it [judgment]. Linters format on save, so the disagreement has no surface to attach to.
- The word "culture" here names a symptom: no agreed arbiter. The culture fix is to move the arbiter from "whoever comments first" to "the checked-in config" [judgment].
