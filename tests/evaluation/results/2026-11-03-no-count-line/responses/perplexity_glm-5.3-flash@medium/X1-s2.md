## Headline

Measure the errors first: label real summaries, build a baseline, then edit the prompt and add feedback tags.

1. "Sometimes wrong" is undefined, so the first action sorts 100 real summaries into error types.
2. A golden set of key facts from 50 ticket threads gives a baseline for factual consistency.
3. Prompt rules that force grounding in the ticket messages target the top error types after measurement.

## Background

The support tool uses an LLM-based summariser for ticket threads. Agents report that it is "sometimes wrong". No metrics exist for quality or error type. The request is to make the summariser better.

## Relevance

Without a baseline, a prompt change cannot show a gain, so the team risks fixes that do not help. Measurement is also cheap here: labels come from agents on tickets they already handle.
