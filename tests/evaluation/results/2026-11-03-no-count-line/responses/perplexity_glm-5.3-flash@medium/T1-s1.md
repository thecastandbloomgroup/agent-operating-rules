## Headline

The dispute is a tooling gap, not a culture problem. Fix it with one formatter, one config file, and CI enforcement. Reviews then test logic, not whitespace.

1. Style debates move from people to a config file, so persuasion stops being the job.
2. Enforcement moves from reviewers to CI, so conformance no longer depends on anyone's mood.
3. Rules changes go through pull requests to the config, so the debate happens once, in code.

## Background

The team disagrees on SQL format. The friction appears in every review and costs review time and trust per pull request. The request asks for a culture fix. The evidence points to a mechanical fix instead. See A2 for the risk in that read.

## Relevance

Each PR that sparks a style debate adds minutes of review time and one unit of resentment. Two tool actions remove the cause within one week [inference]. So the cost of inaction grows with every PR.

## Information

### Evidence

- Disputes over trivial, visible choices persist once everyone can see the choice. Parkinson named this the law of triviality: people give more debate time to topics anyone can argue [3].
- A configurable SQL linter and formatter exists. SQLFluff supports many dialects and reads rules from a config file in the repo [1]. The sqlfmt tool exists as a plainer alternative for a narrow [judgment] style set [2].
- Pre-commit hooks run checks before each commit and are a standard enforcement point [4].
- The claim that a linter plus CI removes most style review comments is my assessment, not a measured result: [judgment].

### Assumption log

A1. The SQL lives in a repo with CI available, not only in ad-hoc queries. Why not measured: the material does not state the workflow. Validate by: check the repo for .sql files and a CI config. If wrong: enforce with editor defaults and a shared config file instead.

A2. Formatting, not deeper disagreement on SQL practice, causes the friction. Why not measured: the user report says "format" but the sources of each dispute are unknown. Validate by: tag review comments in the last five PRs as style or substance and count each kind. If wrong: run a norms review on naming and query structure before the tooling.

A3. The team runs one SQL dialect, or few. Why not measured: the dialect is unknown. Validate by: read the connection config or the file headers. If wrong: set the dialect rules per directory in the config, because SQLFluff supports that [1].

### Alternative considered

Publish a written style guide with no tool. It loses because enforcement stays human and retries on every PR. Parkinson's law predicts the guide becomes the new subject of debate [3].
