# Headline

Establish an evaluation baseline and an agent feedback loop to eliminate factual errors in summaries.

First, label 50 recent ticket summaries to identify specific failure modes.
Second, add a structured feedback capture directly into the agent interface.
Third, update the summarisation prompt with explicit grounding constraints.

# Background

Support agents report that the new summariser produces incorrect output during ticket reviews. The engineering team currently lacks performance metrics, error categorisation, and systematic logs to measure summarisation accuracy [judgment]. Therefore, the team cannot pinpoint whether hallucinations, omissions, or formatting flaws cause the reported errors.

# Relevance

Unreliable summaries increase ticket handling time and risk customer dissatisfaction [judgment]. Resolving this issue now prevents agents from abandoning the tool entirely.

# Information

The primary reason for perceived failure in text summarisation is factual inconsistency [1]. In support operations, hallucination rates in unconstrained zero-shot generation often reach 15% to 30% [2]. Therefore, measuring accuracy requires an explicit baseline.

Assumption log:
Assumption: Agents handle text-based support tickets in English. Why not measured: The material does not state it. Validate by: Review 20 recent ticket logs. If wrong: Translation or multi-lingual evaluation steps become necessary.

Alternative considered:
Fine-tuning an open-source model immediately was considered, but it loses because fine-tuning without an established benchmark wastes engineering time [judgment].

# End

I recommend that we complete the following actions:

1. Classify 50 recent summarisation failures into an error taxonomy.
   - Increment: Sample 50 bad summaries and assign error types in a spreadsheet during one two-hour session.
   - Capability added: A clear baseline of error categories to target prompt fixes.
