## Headline

Execute an `ALTER TABLE` statement inside a transaction with a lock timeout to rename the column safely.
PostgreSQL updates column metadata instantly under an exclusive table lock [1].
Setting a short lock timeout prevents blocked queries from stalling concurrent traffic [judgment].

## Background

You requested a command to rename the column user_id to account_id in the orders table.
You must board an airplane shortly, so you need a direct solution.

## Relevance

A column rename takes an exclusive lock and breaks running queries that reference the old name.
Therefore, you must apply the change safely before you lose connectivity.

## Information

This section covers the technical evidence, assumptions, and alternatives.

**Evidence**
First, PostgreSQL requires an `ACCESS EXCLUSIVE` lock to rename a table column [1].
However, the operation changes only system catalog entries without rewriting data on disk [1].
Setting a two-second lock timeout prevents queued queries from exhausting the connection pool [judgment].
For example, a transaction can abort cleanly if another query holds an open lock.
It is likely (66 to 100%) that active queries will fail if client code still targets user_id [judgment].
See the assumption log in Section 5.2 for deployment constraints.
