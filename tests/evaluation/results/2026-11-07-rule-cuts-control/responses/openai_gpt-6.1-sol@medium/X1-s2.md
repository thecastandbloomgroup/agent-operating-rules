### 3. Measure the current summariser

**Acceptance test first, stochastic**

### 4. Test one targeted fix without live rollout

**Acceptance test first, stochastic**

- **Metrics:** The same four quality measures.
- **Baseline:** Step 3 results.
- **Sample:** One candidate output for each of the same 50 held-out tickets.
- **Pass threshold:** At least 20% fewer summaries with the targeted error, no severe errors, and no lower useful summary rate.
- **Constraint:** No other quality measure worsens.
- **Scope:** These are proposed pilot thresholds, not proof of production reliability. [judgment]

**Work:** Use the development tickets to choose one fix from the observed error pattern:

- For unsupported claims, require source support and explicit statements of missing information.
- For omissions, require fields matching the agent’s next action.
- For incorrect source content, correct source selection before changing the prompt.

Choose only one intervention for this trial. Score baseline and candidate outputs without showing reviewers which system produced them.

**Increment and blocker:** Deliver one candidate comparison and an accept-or-reject decision.

**Domain: Complex.** Use induction from a safe trial because a fix can improve one ticket type and worsen another. [judgment]

**Budget:** Cap the probe at one work session, four reviewer-hours, and US$25 in model costs. [judgment] Stop at the cap or after any severe candidate error.

Do not enable the candidate automatically after this small trial.
