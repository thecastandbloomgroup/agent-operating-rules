## Headline

Yes, pin every version in a lock file, and update the pins on a schedule.

- An unpinned install takes the newest release, so a library update can break the build without any change in your code.
- A pinned install gives the same packages on every build, so a failure points to your change.
- Pins age, so a weekly update job keeps you current without surprise breaks.

## Background

Your requirements.txt has no pinned versions. The build broke twice last month after a library update. You ask whether to pin.

## Relevance
