## End

I recommend that we add the prompt below, then measure its effect before trusting it.

Grounding prompt, first block of the system prompt:

```text
Answer every factual claim with a source tag.
A tag is [context], [tool], [document: name], or [no source].
Use [context] for text from this conversation and [tool] for tool output.
Use [no source] when you cannot verify. State there what you would need.
Do not add plausible detail to fill a gap. State the gap instead.
Give a probability for every claim that carries [no source].
```

Optional request prefix, for hard questions:

```text
First list the facts you can verify. Then list what you cannot. Then answer.
```


2. Step 2: run a 50-question eval before and after the edit, on the same fixed set, and count claims that carry a tag. Increment: two runs, one question set. Blocker removed: the guess that the prompt works. Test (stochastic): metric is the share of tagged claims; baseline is the run without the prompt; pass threshold is at least 90% at 50 samples; stop condition is a gain below 10 points. Cynefin: Complex, induction from trials, because the pattern could be model specific; budget is capped at the two runs.

3. Step 3: connect one retrieval source and require tags that point into it. Increment: one tool wired in, one session. Blocker removed: the pressure to answer from memory [2]. Test (evaluative): score two candidate tools on accuracy of returned text, setup cost, and latency, with weights 0.5, 0.3, 0.2; pass when the top score exceeds the next by at least 0.2. Cynefin: Complicated, deduction from documented tool behavior.

Sequencing: Step 2 runs after Step 1, because it measures Step 1's output. Step 3 waits on a failed Step 2 threshold. If a retrieval tool already runs in the setup, replace all three with Step 3 alone.
