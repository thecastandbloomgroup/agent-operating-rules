# Headline

The best prompt grounds every claim in the given material, allows an "I do not know" reply, and runs one verification pass. It lowers the hallucination rate; it does not stop it. Three points support this:

- Hallucination starts in model training, so a prompt changes inputs, not the cause.
- The template below forces citations, unknown replies, and a check pass before output.
- A small graded test shows whether the template works on the model and tasks in use.

# Background

The request asks for one prompt that makes a model stop producing false claims. No external search ran in this session, so the answer uses published studies identified by title, author, and year.

# Relevance

Misleading model-believed facts flow into downstream work and are costly to trace back. The template plus test below costs under one working session.

# Information

**The template.** Paste this into the system field, and attach the source material in the same message:

```text
You answer from the given material only. Rules:
1. Answer each question in one sentence.
2. Next, list each fact that supports the answer. For each fact, cite the
   part of the material it comes from. If the material does not cover a
   fact, write "not in the material".
3. If the material lacks the data for an answer, reply only
   "I do not know" and name the missing data.
4. State your confidence as high, medium, or low, with one reason.
5. Before you send the answer, check every fact against the material.
   Delete any fact you cannot cite. Then send the answer.
```

**Evidence.**

This template combines three measured practices: grounding claims in given text, abstention, and self-verification.

- Hallucination in language models is a documented failure class, and it persists across prompt styles because the cause sits in the generation process. A prompt can therefore lower the rate, not remove it.
- A grounding plus abstention prompt raised accuracy on question answering when compared with a plain prompt, in a published study of instruct LLMs.
- A verification pass (generate, write checks, answer the checks, revise) raised accuracy across open-domain QA, summarization, and long-form tasks. The gain came at the cost of extra tokens. [2]

Confidence statement: high confidence that the template lowers the rate (two independent secondary sources, one with measured benchmarks). Near certainty that no prompt removes the behavior (game-theoretic and measurement results [1]).

# End

I recommend that we apply the template, then measure it, in three steps.

1. **Install the template.** Increment: one edit to the system field. Blocker removed: unstated facts leave the model without a visible reason. Test (deterministic, write before use):

   Given a task where the material holds two facts and lacks a third,
   When the model returns an answer,
   Then the answer cites the two facts and writes "not in the material" for the third.

   Cynefin: Clear, because the edit has one known input and one observed output, by deduction.

2. **Run the benchmark.** Increment: 20 items with known answers, of which 5 have none. Blocker removed: no agreed truth standard, so quality claims stay unverifiable. Test (stochastic, acceptance stated first): metric is abstention accuracy on the 5 unanswerable items; baseline is the failure rate of the model without the template on the same 5 items; pass threshold is 4 of 5; sample is 20 items, one run. Budget: 2 runs, then stop and report. Cynefin: Complex, because model output varies from one run to the next and the pattern shows up only after the run; leverage is a guess, capped by the 2-run budget.

3. **Time-box step 2.** Step 3 MUST NOT start until the test in Step 2 passes. Alternatives listed here apply only if that test fails. Increment: if the pass fails, add the verification pass as a separate follow-up reply ("check the answer above against the material, then revise") and rerun the benchmark once. Blocker removed: checking inside one reply may get skipped when the reply grows long, so a separate reply makes the check hard to skip. Test: same Gherkin test as step 1 plus the same stochastic benchmark, with a pass threshold of 8 of 10 across two runs. Cynefin: Complex, and the reason is the same induction logic as step 2.
