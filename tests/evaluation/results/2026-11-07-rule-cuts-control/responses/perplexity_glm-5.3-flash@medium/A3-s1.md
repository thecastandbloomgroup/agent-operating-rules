Turn on gzip compression for the API. A 400 KB JSON body compresses to roughly 40 to 80 KB, a 5 to 10x size cut [judgment]. The CPU cost per response is small next to the network saving [judgment]. Two guards belong in the answer: a minimum body size of 2 KB, and an exclusion list for endpoints that reflect secrets [1].

Background: The API returns JSON, with an average body of 400 KB per the request. The question is whether gzip compression gives a net benefit. Gzip is a standard HTTP content encoding, so a server-side change is enough.

Relevance: Transfer time and egress cost scale with every request at 400 KB. Compression cuts both, with no client change, so each call benefits from day one [judgment].

Information: JSON repeats field names once per record in an array. Gzip removes those repeats, so machine-generated JSON reaches ratios near 5 to 10x [judgment]. One risk exists. The BREACH attack reads a compressed response byte by byte and recovers a secret mixed into the same body [1]. It applies only when one response contains both a secret and attacker-controlled text. Therefore gzip stays safe over TLS for ordinary API responses [1].
