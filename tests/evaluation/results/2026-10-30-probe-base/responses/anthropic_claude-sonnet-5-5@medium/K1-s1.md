## Headline

I recommend that we resize the database connection pool first, because the pool change explains most of the added latency.

- The pool wait (`db.pool.acquire`) grew from 3 ms to 690 ms at p95, which is 687 of the 780 ms rise (88%).

  Source: traces.txt, span table [3]

- The release cut `max_size` from 50 to 8 per pod, while each pod runs 8 worker threads.

  Source: release.diff, config/db.yaml [2]

- The cache TTL cut from 300 s to 60 s raised the miss rate from 12% to 31%, so more requests need a connection.

  Source: traces.txt, cache miss row [3]

- The ORM change is not the cause: query spans stayed flat (orders p95 52 to 58 ms).

  Source: traces.txt, query rows [3]

## Background

Release 2026.10.21 changed the pool size, the pool timeout, the cache TTL, and one ORM query. After it, p95 latency rose from 120 ms to 900 ms. The error rate rose from 0.02% to 0.40%.

## Relevance

The pool errors now return 503 responses. In window B, 96% of errors are `PoolTimeout`, so users see failures, not only slow pages.
