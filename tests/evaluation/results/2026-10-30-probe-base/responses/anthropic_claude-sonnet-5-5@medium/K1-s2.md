## Headline

Raise the database connection pool size again, because the pool change of 50 to 8 causes most of the latency rise.

- The wait for a pool connection explains 687 ms of the 780 ms p95 rise (p95 is the latency that 95% of requests beat).
- The database itself is not slower, so the ORM change is not the main cause.
- The shorter cache lifetime is a smaller, second cause.
- A full rollback is not needed.

## Background

The API p95 latency rose from 120 ms to 900 ms after release 2026.10.21. The release cut the pool size (the maximum open database connections per pod) from 50 to 8. It also cut the pool wait limit from 30 s to 5 s, cut the cache lifetime (TTL) from 300 s to 60 s, and added `selectinload` to an ORM (object-relational mapper) query.

## Relevance

Error rate rose from 0.02% to 0.40%. Users now get 503 errors after a 5 s wait.
