## Headline

No single prompt stops hallucination, but a grounded-answer prompt cuts it most, and you can test that on your own questions.

- The prompt must tie every claim to a supplied source and allow the answer "I don't know".
- Source text works better than prompt wording, because the model then copies facts instead of recalling them.
- A second check pass catches claims that have no support.
- A test on your own questions shows whether the prompt works.

## Background

You asked for the best prompt to stop a model from stating false facts (hallucination). Models produce fluent text, and they guess when they lack the fact [1]. A prompt changes the guess rate. It does not remove it.

## Relevance

You will rely on the output, so one wrong claim costs you. A tested prompt gives you a measured error rate. A prompt chosen by feel does not.

## Information

**Evidence**

1. Survey work classes hallucination as output that is unfaithful to the source or not verifiable [1].

2. Retrieval of source text before the answer improves factual output on knowledge tasks [2].

3. A draft, verify, and revise sequence reduced hallucinated facts in the tested tasks [3].

4. A prompt alone cannot remove all errors: very unlikely (0 to 10%) [judgment].

5. Confidence in the prompt below: medium confidence, three papers, none run on your model or task.

**The prompt**

```text
Answer only from the SOURCES below.
Do not use outside knowledge.
After each claim, add a short quote from the SOURCES that supports it.
If you cannot find a quote, delete the claim.
If the SOURCES do not answer the question, reply: "I don't know."
Do not guess. Do not fill gaps.
Last, list any claim that you could not support.

SOURCES:
<paste text here>

QUESTION:
<paste question here>
```

**Assumption log**

A1. You use a text chat model and can paste source text. Why not measured: the user has not answered. Validate by: check that your task has source documents. If wrong: use Step 4 only, and expect a higher error rate.

A2. Your task is factual Q&A, not creative writing. Why not measured: the material does not state it. Validate by: read five of your usual requests. If wrong: drop the "I don't know" rule.

**Alternative considered**

Fine-tuning the model on refusal examples. It loses because it costs more than one working session and needs training access [judgment].

## End

1. Build a test set of 30 questions, 10 of which the sources cannot answer. This removes the blocker of having no baseline. Kind: deterministic. Domain: Clear.
   - Test: Given a question list, When we check each row, Then every row has an expected answer or the label "unanswerable".

2. Run the model on the test set with no special prompt, three runs per question. This sets the baseline error rate. Step 3 MUST NOT start until Step 2 is logged. Kind: stochastic. Domain: Complex, so run it as a capped probe: 90 runs, stop at one working session.

3. Run the same set with the prompt above. Kind: stochastic. Domain: Complex, same cap.
   - Test: accept only if the unsupported-claim rate is at most half of the baseline at 90 runs, and the model says "I don't know" on at least 9 of the 10 unanswerable questions. The half-baseline threshold is [judgment].

4. Add a second pass that asks the model to check each claim against the sources and delete the unsupported ones [3]. Step 4 MUST NOT start until Step 3 passes or fails. Kind: stochastic. Domain: Complex.
   - Test: same metric, same 90 runs. Keep the pass only if the rate falls below the Step 3 result.
