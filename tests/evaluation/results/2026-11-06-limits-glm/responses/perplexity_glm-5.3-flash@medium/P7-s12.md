```text
# Procedure: fix banned words and long sentences in one notes file

Goal: a notes file with zero banned words and zero sentences over 25 words,
with the meaning kept.

Tools: read_file, write_file, check_file, list_files.

Steps:

1. List the files, to see path names and sizes: run list_files.
2. Read the target file, to know its full content: run read_file.
3. Baseline the defects: run check_file. Write down each reported banned
   word and each reported sentence over 25 words. Do not change the file yet.
4. Plan the minimallyviewport-preserving edits: For each defect, choose the
   smallest edit that removes it and keeps the meaning.
   - Banned word: delete it, or replace it with a plain word of the same
     meaning. Do not introduce another banned word.
   - Sentence over 25 words: split it at a clause boundary into two or more
     sentences. Keep every fact. Keep the order of the facts.
5. Write the edits, and nothing else, into the file: run write_file. Rule:
   the file must change only at the edit sites found in Step 4.
6. Verify: run check_file again.
   - If the verdict is zero defects, go to Step 7, DONE.
   - If a defect remains or a new one appears, log it, then loop back to
     Step 4 for that defect only. Re-check after every edit.
   - Stop the loop if three rounds fail: report the file as blocked, with
     the defect list, and do not write again.
7. DONE: report the file as fixed, with the before and after defect counts.

Edge case: a key word or quoted text that the fix would change. Keep it,
log it in the DONE report, and leave the defect if the fix would change
the meaning.
```

At Step 5, run check_file as soon as the system allows the write, because the next edit must build on a verified file.
