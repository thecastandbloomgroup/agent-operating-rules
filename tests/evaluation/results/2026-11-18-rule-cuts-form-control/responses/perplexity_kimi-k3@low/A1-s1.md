## Information

Two breakages in one month trace to upstream library updates [no source]. Pinning exact versions makes builds reproducible, which is the stated purpose of a requirements file per the pip documentation [1]. The recommended pattern is: keep loose direct dependencies in requirements.txt, and generate a fully pinned lock file with pip-tools (pip-compile) [2].

The strongest alternative is to pin only upper bounds, such as `flask<3.0`. It loses because an upper bound does not stop a new minor release from breaking the build, which is the failure mode that occurred twice [judgment].

The risk of pinning is stale dependencies and missed security fixes. The mitigation is a scheduled update step, not staying unpinned. High confidence: the failure cause is directly observed, and the fix is a standard practice [1], [2].
