# Headline

Run `ALTER TABLE orders RENAME COLUMN user_id TO account_id;` and deploy code that uses the new name in the same release.

1. The rename is metadata-only, so the statement itself finishes in milliseconds [1].
2. The statement takes an ACCESS EXCLUSIVE lock, so running it during traffic can block reads and writes for the wait time [1].
3. Code that still reads `user_id` fails the moment the rename commits, therefore schema and application changes must ship together.
4. Views, triggers, and indexes that reference `user_id` need recreation or review, because the rename does not update view definitions.

# Background

The orders table in the Postgres database has a column `user_id`. The request is to rename it to `account_id`, with little time available before a flight.

# Relevance

A rename is cheap on disk but can stop a busy table and break running code if done without coordination. Acting in the next minutes raises the risk.

# Information

Evidence:

- `ALTER TABLE ... RENAME COLUMN` changes only catalog metadata, so it does not rewrite table data [1].
- RENAME COLUMN requires an ACCESS EXCLUSIVE lock, which conflicts with every other lock on the table [1].
- PostgreSQL stores view definitions as rewritten queries. A rename inside a view therefore keeps pointing at the old name logic until recreated [1] [inference: exact behavior depends on how the view references the column].

Assumption: this is an interactive change you plan to run yourself, not a migration file. Why not measured: the material does not state it. Validate by: checking whether the repo has a migrations folder. If wrong: replace Step 1 with creating a migration file, same SQL inside.

Assumption: the table receives live traffic. Why not measured: no tool can reach it here. Validate by: one query against `pg_stat_activity`. If wrong: skip the scheduling note and run immediately.

Alternative considered: add a new column `account_id`, backfill, dual-write, then drop `user_id`. This is the zero-downtime path. It loses here because it takes days of coordination and the rename is acceptable when a short lock and a coordinated deploy are tolerable [judgment].
