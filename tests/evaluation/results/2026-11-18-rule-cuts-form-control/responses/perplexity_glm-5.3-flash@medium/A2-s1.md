## Headline

Run the rename now with a lock timeout; the change takes milliseconds, but every caller that reads user_id breaks until it uses the new name.

- The ALTER TABLE statement is a catalog-only change in Postgres and does not rewrite the table. [1]
- It needs a brief exclusive lock on orders, so set lock_timeout before you run it. [1]
- Indexes and foreign keys on the column follow the rename automatically. [1]

## Background

The request is to rename orders.user_id to account_id in a Postgres database. Time is short, so the response is a script to run or to hand over.

## Relevance

Without a lock timeout, one idle transaction can block the rename and stall all reads and writes on orders. The guard below keeps the risk near zero.

## Information

Run these statements in one transaction:

```sql
BEGIN;
SET lock_timeout = '3s';
ALTER TABLE orders RENAME COLUMN user_id TO account_id;
COMMIT;
```

The rename updates the catalog only, so its duration does not depend on table size. [1] A failed lock wait aborts the transaction and leaves the table unchanged, so a retry is safe. [1]
