## Background

## Relevance

## Information

A rename is stored as metadata only [1]. It holds an ACCESS EXCLUSIVE lock for milliseconds and then releases it [1]. Foreign keys that reference the column follow the new name automatically [1]. A view or generated column that uses the column raises an error instead of renaming, so test for them first [1].

Run this before the rename and expect zero rows:

```sql
SELECT DISTINCT dep.objid::regclass AS blocking_object
FROM pg_depend dep
JOIN pg_attribute att
  ON att.attrelid = dep.refobjid
 AND att.attname = 'user_id'
WHERE dep.refobjid = 'orders'::regclass
  AND dep.classid = 'pg_rewrite'::regclass;
```

Then run the rename:

```sql
BEGIN;
ALTER TABLE orders RENAME COLUMN user_id TO account_id;
COMMIT;
```
