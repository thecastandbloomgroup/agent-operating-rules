### Information

PostgreSQL supports direct column renaming through a single statement [1]:

```sql
ALTER TABLE orders RENAME COLUMN user_id TO account_id;
```

However, this statement requires an `ACCESS EXCLUSIVE` lock on the `orders` table [1].
That lock blocks all concurrent select, insert, update, and delete operations until the transaction ends [1].
Furthermore, active application instances will fail because their queries still reference `user_id` [inference].
The safe database pattern therefore uses three phases: add the new column, sync data, and drop the old column [2].
