## Headline

Yes, pin every version, including transitive dependencies (libraries that your libraries install).

- Cause: unpinned entries let pip install the newest release at each build, so a new release can break the build without any change on our side.
- Cost: pinning takes one working session, while the two breaks last month already cost build time.
- Control: pins move upgrades to a planned step with a test, so we choose when a new version enters.

## Background

The project has a requirements.txt with no pinned versions. The build broke twice last month after a library update (per the user message). The question is whether to pin.

Each unpinned build can break again at any time. A pin file makes builds repeatable, and it makes a break easy to trace.
