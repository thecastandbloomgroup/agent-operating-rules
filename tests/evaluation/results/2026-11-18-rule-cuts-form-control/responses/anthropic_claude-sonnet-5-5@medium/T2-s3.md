## Headline

No prompt removes hallucination, but a grounding prompt cuts it, and a small test shows by how much.

- Hallucination is false output stated as fact, and it comes from how models generate text.
- A prompt that limits answers to given sources, allows "Not in the sources," and requires quotes cuts it.
- Prompt wording is the weakest control, so source supply and a check pass add more.
- A test set with a baseline proves whether the prompt works for your task.

## Background

You asked for the best prompt to stop a model from hallucinating. Hallucination means the model states false or unsupported content as if it were true. The material gives no task, model, or tool setup, so the answer must work for factual question answering.

## Relevance

A wrong answer that sounds sure costs more than a refusal. A prompt is the cheapest control to apply today, so start there and measure it.

## Information

Evidence on the cause and the limit:

- Surveys report that hallucination persists across tasks and model types, so a prompt alone cannot remove it [1].

Evidence on the controls:

- Grounding means tying answers to supplied documents. Retrieval of documents improved factual output in knowledge tasks [2].
- Models can often estimate whether they know an answer, so asking for confidence is useful [3].
- The size of the gain from any prompt depends on the task and the model [judgment].

Confidence that no prompt reaches zero errors: 90% likely, based on the survey above [1].

Use this prompt. Replace the bracketed parts.

```text
Answer only from the text in the SOURCES block.
If the SOURCES block does not contain the answer, write: "Not in the sources."
Do not guess. Do not use outside knowledge.
Quote the sentence that supports each claim.
Mark any claim without a quote as [unsupported].
End with your confidence as a percentage.
If the question is unclear, ask one question first.

SOURCES:
[paste documents here]

QUESTION:
[your question]
```

## End

I recommend that we take these four steps in order.

1. Build a test set of 30 questions with known answers. Blocker removed: no way to tell if the prompt works. Domain: Clear, because deduction from a known rule fixes the set. Kind: deterministic. Write the test first:

   ```text
   Given a file of 30 questions with answers
   When the file is checked
   Then 10 questions have the answer "Not in the sources"
   ```

2. Run the baseline and the grounding prompt on the test set. Step 2 MUST NOT start until the test in Step 1 passes. Blocker removed: unknown effect of the prompt. Domain: Complex, because induction from trials is the only guide, and a new model version could break the pattern. This is a probe with a budget of 180 model calls (30 questions, 3 runs, 2 prompts). Stop after two prompt edits with no gain. Kind: stochastic. Test: the metric is the share of answers with an unsupported claim. The baseline is the rate of your current prompt. The pass threshold is half the baseline or lower. The sample size is 90 answers per prompt.

3. Add source supply if Step 2 fails the threshold. Paste the relevant documents, or connect retrieval. Step 3 MUST NOT start until Step 2 reports a result. Blocker removed: the model has nothing to ground on. Domain: Complicated, because deduction from the grounding result [2] picks the practice. Kind: stochastic. Test: the same metric, baseline, threshold, and sample size as Step 2.

4. Add a check pass that asks the model to verify each quoted claim against the sources. Run it as a parallel probe after Step 1. Blocker removed: wrong claims that pass the first prompt. Domain: Complex, because induction from trials applies, and long documents could break the pattern. Budget: 90 extra calls. Stop if the unsupported rate does not fall. Kind: stochastic. Test: the same metric and threshold, 90 answers.
