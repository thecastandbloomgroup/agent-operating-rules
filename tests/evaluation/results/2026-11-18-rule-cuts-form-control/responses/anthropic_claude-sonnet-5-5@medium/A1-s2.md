## Headline

Yes, pin every version, including indirect ones, and add a routine to update the pins.

- Unpinned installs take the newest release, so each build can change without a code change.
- Exact pins make each build repeat, which removes the cause of both breaks.
- Pins go stale without a routine, so a scheduled update must replace the silent updates.
- This applies to an application. A library for other users needs ranges instead (see Follow-up).

## Background

The build broke twice last month after a library update, per the user's message. Nothing in requirements.txt is pinned. A pin fixes a package to one exact version, for example `requests==2.32.3`.

## Relevance

Each unpinned build is a new test of the whole dependency set. The next release can break the build again.
