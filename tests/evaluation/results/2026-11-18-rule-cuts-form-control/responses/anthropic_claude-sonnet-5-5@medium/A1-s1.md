## Headline

Yes, pin every version, and update the pins on a schedule.

- Cause: an unpinned install takes the newest release at build time, so a library update can break the build with no code change.
- Fix: a pinned file makes every build install the same versions.
- Scope: pin indirect dependencies too (the libraries that your libraries need), because they change as often as direct ones.
- Cost: pinning moves updates from random build breaks to a planned weekly step.

## Background

The project has a requirements.txt file with no pinned versions. A pin fixes one exact version, for example `requests==2.32.3`. The build broke twice last month after a library update. The question is whether to pin.

## Relevance

Each unpinned build can fail on a day the team did not choose. Two breaks in one month cost developer time and block releases.
