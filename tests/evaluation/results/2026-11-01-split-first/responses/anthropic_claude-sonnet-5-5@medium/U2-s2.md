- The request names no report, figure, or symptom, so the first job is to collect them.
- Most number errors in reports come from a few causes: wrong period, wrong definition, or a broken total [judgment].
- A repeatable tie-out check fixes the current error and catches the next one.

## End

I recommend that we take these four steps in order.

1. **Collect and list the doubtful figures.**
   - Increment: in one session, gather the Q3 report, its source data, and the Q2 report. List each figure that looks wrong, with the value you expected.
   - Blocker removed: nobody has said which numbers are off.
   - Domain: Confused, because the problem is not yet defined. This step gathers what we need to classify it.
   - Kind: deterministic. Test, in Gherkin form [2]:

     Given the Q3 report, its source data, and the Q2 report are in one folder

     When the doubtful figures are listed

     Then each figure has a reported value, an expected value, and a stated reason for doubt

2. **Recompute each listed total from source rows.**
   - Increment: one script or spreadsheet that rebuilds each total and shows the gap.
   - Blocker removed: we cannot tell a source error from a report error.
   - Domain: Complicated, because analysis of the data finds the cause.
   - Kind: deterministic. Test:

     Given the source rows for the listed figures

     When each total is recomputed

     Then each gap against the reported value is shown in the report's units

   - Step 2 MUST NOT start until the Step 1 test passes.

3. **Rank the likely causes of each gap.**
   - Increment: one Pugh matrix [3] of candidate causes: period cut-off, definition change, currency, filter, duplicate rows, formula range.
   - Blocker removed: we do not know which fix to apply.
   - Domain: Complicated, because expertise and the gap data narrow the causes.
   - Kind: evaluative. Rubric:
     - Criteria and weights: fit to the gap size (40%), fit to the timing of the gap (30%), ease of test (30%).
     - Evidence each criterion needs: the Step 2 gap values, and a one-row test per cause.
     - Pass threshold: one cause scores at least 70 of 100 and explains the full gap.
   - Step 3 MUST NOT start until the Step 2 test passes.

4. **Correct the report and add a tie-out check.**
   - Increment: fix the confirmed cause. Add a check that compares each total with its source.
   - Blocker removed: the error returns each quarter without a check.
   - Domain: Clear, because a tie-out check is a known best practice.
   - Kind: deterministic. Test:

     Given the corrected Q3 report and its source data

     When the tie-out check runs

     Then every total matches its source within zero difference in the report's units

   - Step 4 MUST NOT start until the Step 3 threshold is met.
   - If A3 is false, stop after Step 3 and send the cause analysis only.
