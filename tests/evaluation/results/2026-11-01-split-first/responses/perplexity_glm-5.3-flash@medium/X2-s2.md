Headline

Run shorter, sharper retrospectives: end each one with a single owned action, test the change as a one-sprint experiment, and review the completion rate after three sprints.

1. Most no-change retros fail at follow-through: actions lack an owner and a date, so they never reach a sprint [1], [judgment].
2. Repeat topics need one root-cause analysis before the team writes a new action [1].
3. A change works as one measured experiment with a stop condition, not as a task list [3].
4. A completion-rate metric shows within three sprints whether the fix works.

Background

The team holds retrospectives. Attendees produce no lasting changes. The request asks what to do to make retros drive change.

Relevance

A retro costs about 12 person-hours per sprint at 8 people and 90 minutes [judgment]. Therefore the same cost repeats every sprint with zero output, and the payback from the steps below arrives within three sprints.

Information

Evidence and themes

- Theme 1: actions without an owner and a due date die [1]. One source supports it in this session, plus practitioner reports from sprint hygiene checklists [judgment]. No disagreeing source appeared.
- Theme 2: repeat topics signal missing insight work. Derby and Larsen place "gather data" and "generate insights" before "decide what to do" [1].
- Theme 3: low psychological safety hides real causes [2]. One source supports it. It matters because, when true, it changes which step comes first (see A3).

Assumption log

A1. Retros output action items, and the items lack owners or tracking. Why not measured: the material does not state the current format. Validate by: read the last three retro notes. If wrong: replace Step 1 with a format diagnosis first.
A2. The team holds the authority to change its own process. Why not measured: the material does not state the decision rights. Validate by: ask one team member how the last process change won approval. If wrong: record the sponsor's approval before Step 1.
A3. Low psychological safety is not the primary cause. Why not measured: measuring costs more than the first decision is worth. Validate by: one anonymous poll with two questions, per [2]. If wrong: run an anonymous input round before Steps 2 and 3.

Alternative considered

Cancel retros and move to a continuous feedback channel [inference]. It loses because Step 1 is a smaller and reversible change, and a channel without a review point fails the same way as an unowned action [judgment].

End

I recommend that we run the change as four steps, in this order:

Step 1. Change the format (Clear, deterministic). Clear because a documented practice applies [1]. Blocker: actions lack ownership and tracking [A1]. Track at most one action per retro, each with one named owner and one due date. Test first:
Given a retro closes this sprint
When the facilitator ends the meeting
Then the board shows one open action with an owner name and a due date

Step 2. Run one root-cause analysis at the next retro (Complicated, evaluative). Complicated because analysis must pick between several practices. Blocker: repeat topics show current actions treat symptoms [1]. Rubric first: evidence in the notes supports the cause, weight 0.6, based on the last three retro notes; every attendee states agreement, weight 0.4; pass threshold is 4.0 of 5.0 weighted.

Step 3. Run one safe-to-fail experiment for one sprint (Complex). Complex because cause and effect appear only after the run [3]. Probe, not a commitment. Budget: one owner, one sprint. Blocker: the root cause has no tested fix. Test before running: metric, one behavioral measure tied to the cause, for example defects reopened per week; baseline, the current value from the tracker; threshold, 20% below baseline; sample size, 4 weekly readings.
Given one baseline value from the tracker before the sprint
When 4 weekly readings are recorded
Then at least 3 of 4 readings sit 20% below the baseline
Or otherwise the stop condition fires: 2 consecutive readings above baseline

Order: Step 3 must run in parallel with Steps 1 and 2, and it MUST NOT start before Step 2 produces one root cause. Leverage is a guess until the first result [3].

Step 4. Review the completion rate (Clear, deterministic). Clear because counting and comparing are known steps. Dependency: Step 4 MUST NOT start before Step 1 ran in 3 consecutive sprints. Blocker: without a metric, the format drifts back to the old one. Test first:
Given Steps 1 to 3 ran in 3 consecutive sprints
When the fourth retro starts
Then the facilitator presents the completion rate per sprint
And the team records one of: keep, change, stop

Condition that changes this recommendation: if Step 4 shows a completion rate below 50%, replace Steps 2 and 3 with facilitator retraining before a new format cycle [judgment].

Follow-up

Open questions: none.
Conditions that change the recommendation: see A3 and the condition after Step 4.
