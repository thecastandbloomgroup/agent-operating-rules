## End

I recommend that we act in this order:

1. **Enable capped retries with a flake marker.** Increment: one CI config change, done in one session. Blocker removed: merges blocked by red runs with no known cause. Test (deterministic):
```gherkin
Given a job that fails on attempt one and passes on attempt two
When the pipeline runs with the retry config
Then the job reports pass with a flake note and the pipeline turns green
```
Domain: Chaotic, because no cause is visible yet, so stabilization comes first.

2. **Record each failure with its signature.** Increment: a CI summary with test id, error class, and timestamp, run for the next 20 runs, in one session. Blocker removed: no dataset exists, so the cause cannot be classified. Test (deterministic):
```gherkin
Given a failed job in the 20-run window
When the summary is generated
Then each failure shows a test id, an error class, and a timestamp
```
Domain: Clear, because the practice of logging failure signatures is known and applied directly.

3. **Run two probes in parallel, each capped.** Probe A: rerun the suite in random order. Probe B: rerun the suite with network calls stubbed. Budget: 10 CI runs per probe or one session. Metric: suite failure count against the Step 2 baseline of 20 runs. Pass threshold: a probe cuts the failure count by half or more at 10 runs. Stop condition: stop the losing probe when its budget is spent. Blocker removed: separation of order pollution from network dependence. Domain: Complex, because cause and effect are visible only after each run, so this is a safe-to-fail probe, not a commit.

4. **Pick and ship one fix.** This step waits until Step 2 has 20 logged runs and Step 3 has results. Increment: one fix (isolation, retry within the test, or stubbing), one session. Blocker removed: the dominant error class still fails. Test (evaluative, Kepner-Tregoe [S]): criteria are recurrence in the logs (weight 0.4), repair scope (weight 0.3, smaller ranks higher), and regression risk (weight 0.3); pass threshold is 70% of the maximum weighted score against the Step 2 and Step 3 evidence. Domain: Complicated, because expertise and the data pick among more than one good practice.
