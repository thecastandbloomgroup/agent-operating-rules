## Headline

Stop generating more ideas and start owning one change per retro cycle. Three supporting points:
1. The loop breaks at execution, so first measure how many retro items get done.
2. End each retro with exactly one owned, measurable action, and check it at the start of the next retro.
3. If completion is high and outcomes still stay flat, the topics are wrong, not the process.

## Background

The team runs retrospectives. People attend, items get discussed, and no change reaches the work. The request asks for a way to restart the loop.

## Relevance

Every retro without a shipped change lowers trust in the practice. The next retro is the cheapest place to fix the loop.

## Information

Evidence for the diagnosis and plan:
- A retrospective works only when its outcome has an owner, a deadline, and a check at the next session, because ideas without these three fields do not reach the work [1].
- The common failure mode is not a lack of ideas. It is item overload and diffuse ownership [1].

Assumption log:
- A1. The retros produce action items, but the team completes few of them. Why not measured: the material does not state where the process breaks. Validate by: the audit in Step 1. If wrong: the break sits upstream in topic selection, and Step 4 replaces Steps 2 and 3.
- A2. Cadence is weekly or close to it. Why not measured: the material does not state the calendar. Validate by: count retros over the last month. If wrong: extend the probe window in Step 3 to four cycles.

Uncertainty: A1 holds with about 70% likelihood, based on the pattern in [1] and the description that people attend but "nothing shifts" [judgment].

Alternative considered: change the format or hire a facilitator. This loses because no format fixes items that lack an owner; the audit must come first, and a format change does not remove that blocker [judgment].

## End

I recommend that we repair the loop with the four steps below, in this order.

1. **Audit the last three retros.** Increment: record items raised and items done, in one session. Blocker: the break point is unknown, and this output decides the rest. The domain is Confused, because the audit classifies where cause and effect break down. Test, written first (deterministic):
   - Given the logs of the last three retros
   - When the counters tabulate items raised and items done
   - Then the board shows one completion rate per retro
2. **End each retro with one action.** Increment: one owner, one change, one metric, and a check slot at the start of the next retro. Blocker: diffuse ownership and item overload, the causes named in [1]. The domain is Clear, because a best practice exists and the team applies it. Test, written first (deterministic):
   - Given a finished retrospective
   - When the team writes the action record
   - Then it shows one owner, one change, one metric, and zero extra items
3. **Run a two week probe.** Increment: carry the single action as a ticket with a definition of done, capped at 2 hours per person per week. Blocker: no evidence yet that one item per cycle moves an outcome. The domain is Complex, because cause and effect appear only after the cycles run, so this stays a capped probe with a stop condition [2]. Test, written first (stochastic): metric = completion rate of the single action; baseline = the Step 1 rate; pass threshold = 2 of 3 cycles complete; sample size = 3 cycles. Stop condition: if two consecutive cycles produce no completion, stop and re-diagnose. This step MUST NOT start until the Step 1 output exists.
4. **Shift topic selection to data, only if Step 1 shows a completion rate above 80% with flat outcomes.** Increment: pick retro topics from team metrics, one metric at a time. Blocker: the team then lacks topics, not follow-through. The domain is Complicated, because the analysis that picks each metric needs expertise and the result is knowable. Test, written first (evaluative): rubric with criteria = size of metric gap (weight 3), team control over the cause (weight 2), fixable in one cycle (weight 2); pass = the top score wins and must exceed 3 of 5; evidence = the metric from the team dashboard. Use a Pugh matrix for the scoring [2].

## Follow-up

Conditions that change this recommendation: if A1 is false and the audit finds zero items raised, replace Steps 2 and 3 with a silent writing exercise for topic generation. If the cadence is monthly, extend the Step 3 probe to four cycles.
