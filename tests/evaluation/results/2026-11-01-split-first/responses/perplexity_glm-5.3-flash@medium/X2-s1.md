# Headline

Drive one committed change to done each cycle instead of collecting more findings.

- Cap each retro at one action, with one owner and one due date.
- Open the next retro with the status of that action, before any new topic.
- Track the completion rate for four cycles, and probe a new format in parallel.

# Background

Retrospectives still happen, but the outputs do not change how the team works. Attendance continues, so the meeting form is alive. The value is gone.

# Relevance

A retro without completed actions trains the team to expect no change, so the next retro gets less honesty and less energy. Fixing the loop now costs little.

# Information

The purpose of a retro is to end with a committed improvement, not with a list of observations [1]. A long list of open items works like an unbounded queue: work in progress above the limit slows all items, and finishing rate falls when a team starts many items at once [2]. So the first fix is a work in progress limit of one on retro actions, not a new meeting format.

- The limit is a known practice in flow control [2].
- The completion rate is the measure that shows whether the limit works. Baseline: unknown today, so Step 3 measures it.

Assumptions:

- A1. Retros still produce action items, but nobody completes them. Why not measured: the material does not state it. Validate by: read the last three retro notes. If wrong: the team generates no items, so the fix is facilitation, not follow-through.
- A2. No external gate, such as manager approval, blocks the chosen actions. Why not measured: the user has not answered. Validate by: check who must approve a change to the team's work. If wrong: agree a decision rule with that approver first, and put it before Step 1.

Alternative considered: cancel the retro and handle improvements in normal work. It loses because the team still needs a fixed time to inspect how it works [1], and the problem here is the loop from finding to done, not the meeting itself [judgment].

# End

I recommend that we run the following steps.

1. Set the action limit at one item per retro. Increment: add the limit to the facilitator checklist this week. Blocker removed: a long list with no single owner. Test (deterministic, Clear, because one known practice applies):

```gherkin
Given a retro that ends
When the facilitator records the action list
Then the list holds at most one item, with one owner and one due date
```

2. Open each retro with the status of the previous action. Increment: change the agenda template. Blocker removed: actions with no review get dropped. Test (deterministic, Clear): Step 2 starts at the next retro, after Step 1 sets the limit.

```gherkin
Given the next retro starts
When the facilitator opens the agenda
Then the first item is the previous action, marked done, dropped, or moved
```

3. Record the completion rate after each retro for four cycles. Increment: one line in the retro notes. Blocker removed: there is no data on whether the limit works. Test (deterministic, Clear):

```gherkin
Given four completed retro notes
When a reviewer counts done items against committed items
Then the rate is written as "done of committed" for each cycle
```

4. Probe a new format in parallel with Steps 1 to 3. Every other retro, replace free-form discussion with a single topic deep dive, for example five whys on one issue. Domain: Complex, because the effect on team engagement becomes visible only after runs [judgment]. Leverage here is a guess. Budget: the existing meeting time, no new meetings. Stop condition: stop the probe if the completion rate is two of four or lower after four runs. Acceptance test (stochastic): metric = completion rate under the new format, baseline = the rate from Step 3, pass threshold = three of four or better, sample size = four retros.

# Follow-up

Conditions that change this recommendation: if A2 is false and an approver blocks the actions, put the decision rule with that approver before Step 1. If people stop raising issues at all, the cause is safety, not follow-through, and the first step becomes one anonymous written input per member before the next retro [judgment].
