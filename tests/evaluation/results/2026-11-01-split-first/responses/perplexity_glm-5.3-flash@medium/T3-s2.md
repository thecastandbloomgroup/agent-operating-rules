## Information

Evidence used by this plan:

- JWT is a standard for signed, self-contained claims; it carries no revocation signal by itself [2].
- Bearer token usage requires TLS and adds replay risk once a token leaks [3].
- Server-side session termination requires checking session state at request time; a stateless token removes this check, so immediate revocation needs a server-side mechanism such as a denylist [1]. The same source recommends secure cookie handling over browser storage because of script-reading attacks.

Qualitative theme from these sources: three sources support the theme "stateless tokens trade revocation and storage-safety for per-request lookup cost", and no source read here disagrees [1] [2] [3].
