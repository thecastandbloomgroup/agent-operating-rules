## Headline

Run a four-step reconciliation, that is, recomputing totals from line items, to find and fix the wrong Q3 numbers.

- Report errors come from a short list of causes: broken sum ranges, wrong units or periods, and values typed over formulas [judgment].
- Recomputation from totals down finds such errors in minutes; a full rebuild from source data costs hours [judgment].
- Three questions in the Follow-up set only the starting point of the trace, not the method.

## Background

You report that some numbers in the Q3 report look wrong. The message names no file, no line items, and no baseline, that is, no value to compare against. The defect is therefore not localized.

## Relevance

Audits summarized by Panko found errors in nearly all large spreadsheets they checked [1]. A wrong figure in a circulated quarterly report can drive bad decisions, so a verified fix matters now.

## Information

Evidence:

- About 70% likely, the cause sits in a short list [judgment]. The list: a sum range that misses rows, mixed units or currencies, a wrong data period, or a value typed over a formula.
- Recomputation finds such causes in minutes; a rebuild from source data takes hours to days [judgment].

Assumption log:

- A1. The report is a spreadsheet or a table that can be copied. Why not measured: no file came with the message. Validate by: the answer to Question 1. If wrong: add a table-extraction step before Step 1.
- A2. A baseline exists, and it is the prior quarter. Why not measured: the material does not state it. Validate by: the answer to Question 2. If wrong: replace the baseline comparison in Step 2 with internal consistency checks.
- A3. The gap exceeds rounding, so a real defect exists. Why not measured: no numbers came with the message. Validate by: Step 1 measures the gap size. If wrong: document the rounding rule and stop.
- A4. You can edit the report or reach its owner. Why not measured: the material does not state it. Validate by: the answer to Question 3. If wrong: Step 4 becomes a change request to the owner.

Alternative considered: rebuild the report end to end from source data. It loses on cost, hours to days versus minutes, and because most faults sit in a few cells [judgment]. However, it stays as a fallback if Step 3 finds broken source queries.

## End

I recommend that we run these four steps in order. Write each test before the work.

**Step 1. Recompute every subtotal from its line items in a copy of the report.**

- Increment: one pass over all report tables in one working session.
- Blocker removed: unknown scope of the error.
- Test, deterministic (same input, same output), written first:
  - Given the Q3 report tables
  - When each subtotal is recomputed as the sum of its line items
  - Then each subtotal matches within half of the smallest displayed unit, or the cell goes on the differ list
- Cynefin domain, that is, how cause relates to effect here: Complicated, because reconciliation is analysis with knowable cause and effect.

**Step 2. Classify each differing cell against the baseline. Step 2 MUST NOT start until Step 1 lists the differing cells.**

- Increment: one comparison pass in one session.
- Blocker removed: unknown error type.
- Test, deterministic:
  - Given the differ list and the baseline values
  - When each cell is compared with its baseline value
  - Then each cell gets one label: sign flip, scale factor, constant offset, period shift, or unclassified
- Cynefin: Complicated, because pattern classification against a baseline is analysis.

**Step 3. Trace the formula chain and source query of the largest differing cell. Step 3 MUST NOT start until Step 2 labels the cells.**

- Increment: one cell traced in one session. Record hardcoded values and the data refresh date.
- Blocker removed: unknown root cause.
- Test, deterministic:
  - Given a differing cell from Step 2
  - When its formula chain and source data are inspected
  - Then the record names one root cause: range, unit, period, overwrite, or source
- Cynefin: Complicated, because precedent tracing is expert analysis with knowable results.

**Step 4. Fix the cause and add a checksum row, that is, a row that recomputes subtotals and flags gaps. Step 4 MUST NOT start until Step 3 names the root cause.**

- Increment: one fix plus one checksum row, verified in one session.
- Blocker removed: recurrence risk after the fix.
- Test, deterministic:
  - Given the corrected report with the checksum row
  - When the report refreshes with new data
  - Then the checksum row recomputes every subtotal and flags any gap above half a unit
- Cynefin: Clear, because a reconciliation checksum is an accepted best practice.
