# Headline

Use the prompt below, but expect it to reduce hallucination, not stop it. A hallucination is a confident answer that is false or has no support.

- The prompt gives the model three behaviors: it may say "I do not know," it quotes before it claims, and it names a source for each claim.
- Source text gives the model facts to quote. Without source text, the prompt can only make the model refuse more often.
- A 30-question test shows whether the rate fell and whether the model now refuses too often.

# Background

You asked for one prompt that stops a model from hallucinating. The prompt is below, followed by the steps that make it work and show that it works.

```text
Answer only from the text inside the <documents> tags.
Before you answer, copy the exact sentences that support your answer into <quotes> tags.
If no sentence in the documents supports an answer, write "I do not know" and stop.
Do not use facts from outside the documents.
After each claim, give the document name and section that support it.
Check each claim against your quotes. Delete any claim that no quote supports.
Do not guess names, numbers, dates, citations, or web addresses.
"I do not know" is a correct answer. A wrong answer is worse than no answer.
```

If you cannot give the model documents, use this shorter version:

```text
If you do not know a fact, write "I do not know".
Do not guess names, numbers, dates, citations, or web addresses.
Mark each claim as "checked" or "unchecked".
"I do not know" is a correct answer. A wrong answer is worse than no answer.
```

# Relevance

A prompt that you paste in without a test can fail in two ways, and you see neither. First, false answers can continue. Second, the model can refuse questions that it can answer.

**Assumption log.**

# End

I recommend that we take these four steps.

1. **Build a test set.**
   - Increment: write 30 questions from your domain. Give each question a reference answer and its source section. Write 10 of the questions so that the documents do not answer them.
   - Blocker removed: you have no way to measure the hallucination rate.
   - Kind: deterministic. Test, written first in Gherkin form (Given, When, Then): *Given* the source documents, *When* the set is complete, *Then* it holds 30 questions, *and* each answerable question names a section, *and* 10 questions have no answer in the documents.
   - Cynefin domain (how cause and effect relate in the work): Clear.

2. **Choose how the model gets the source text.**
   - Increment: score two options in a Pugh matrix. Option one pastes the documents into the prompt. Option two uses retrieval.
   - Blocker removed: without source text, the prompt has nothing to quote.
   - Kind: evaluative. Write the rubric first, with three criteria:
     - Coverage of the 20 answerable questions, weight 50%. Evidence: a count of the questions that the text answers.
     - Fit in the model's input limit, weight 30%. Evidence: a word count of the text.
     - Setup in one session, weight 20%. Evidence: a list of the setup steps.
   - Pass threshold: 70 of 100.
   - Cynefin domain: Complicated.
   - Step 2 MUST NOT start until the test in Step 1 passes.

3. **Run the prompt as a probe.**
   - Increment: run the 30 questions three times with your current prompt. Then run them three times with the new prompt.
   - Capability added: you see whether the prompt lowers the rate.
   - Kind: stochastic. Write the acceptance test first:
     - Metric: the share of answers that contain at least one claim without support.
     - Baseline: that share with the current prompt.
     - Pass: at least 50% below the baseline [judgment], and "I do not know" on at least 24 of the 30 runs of unanswerable questions.
     - Sample size: 90 answers for each prompt.
   - Stop condition: correct answers on answerable questions fall by more than 10 percentage points.
   - Budget: one session.
   - Cynefin domain: Complex. The leverage of this step is a guess.
   - Step 3 MUST NOT start until Steps 1 and 2 pass.

4. **Add a verification pass as a second probe.**
   - Increment: add a second model call. It checks each claim against the quotes and deletes claims without support.
   - Capability added: the second call catches errors that the first call missed.
   - Kind: stochastic. Write the acceptance test first:
     - Metric: the same as in Step 3.
     - Baseline: the result of Step 3.
     - Pass: at least 25% below that baseline [judgment].
     - Sample size: 90 answers.
   - Stop condition: the cost for each answer more than doubles before the probe meets its threshold.
   - Budget: one session.
   - Cynefin domain: Complex.
   - Step 4 MUST NOT start until Step 3 ends, because Step 4 uses the Step 3 result as its baseline.
