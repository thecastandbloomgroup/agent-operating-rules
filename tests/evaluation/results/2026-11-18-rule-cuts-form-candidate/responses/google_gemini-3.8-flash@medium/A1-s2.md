### Headline

You must pin exact dependency versions for your application build.

First, unpinned builds cause nondeterministic failures when upstream packages release breaking changes [1].
Second, exact version pins or lockfiles guarantee reproducible builds across all development and production environments [2].
Third, automated dependency update tools let you test and adopt new library releases safely [judgment].

### Background

Your team builds software using Python packages listed in a requirements.txt file without version pins.
Last month, upstream library updates broke the build twice.
You asked whether you should pin library versions in that file to prevent future failures.

### Relevance

Broken builds stop team deployments and cost developer hours to diagnose unexpected changes.
Pinning dependency versions restores build reliability immediately.

### Information

First, this section covers the evidence behind dependency pinning.
Python packaging standards distinguish abstract dependencies from concrete dependencies [1].
An application requires concrete dependencies with exact versions to ensure repeatable installations [1].
In contrast, unpinned requirements download the newest compatible releases from the package index during each build [2].
Consequently, a breaking change in an upstream package breaks your build without warning [judgment].
