## Headline

You must record exact package version numbers in your deployment file to stop unexpected build failures.
- Pinned package versions deliver reproducible builds across every execution environment [judgment].
- Unpinned direct dependencies remain in a separate source file to allow deliberate upgrades [judgment].
- Regular automated dependency audits protect pinned software against newly disclosed security flaws [judgment].

## Background

Your project currently lists dependencies without version numbers in requirements.txt.
Last month, upstream library updates broke your build twice.
Therefore, you ask if you should fix specific version numbers in your requirements file.

## Relevance

Unpinned dependencies introduce untested code into your deployment pipeline without warning.
Therefore, fixed package versions immediately stop unexpected breakage and restore build reliability.

The Python Packaging Authority advises application maintainers to pin exact versions in deployment requirements files [1].
That is, exact version pins lock direct and indirect dependencies to known working releases [judgment].
Because builds without version pins fetch the latest release at install time, external releases can break existing code [judgment].
