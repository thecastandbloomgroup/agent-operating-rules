# Headline

You should pin exact package versions in requirements.txt to secure reproducible software builds.
First, exact version pins prevent unexpected upstream releases from breaking your automated deployments.
Second, pinned files let developers test dependency upgrades in isolated branches before production release.
Third, explicit constraints protect the environment from breaking changes introduced by transitive dependencies.

# Background

Your automated build failed twice last month because an upstream library published an incompatible release.
Currently, your requirements.txt file lists package names without version constraints.
Therefore, the package installer downloads the newest published package versions on every build run.

# Relevance

Unpinned dependencies halt team delivery and consume developer time on urgent repairs.
Therefore, you must establish deterministic builds now to keep your deployment pipeline stable.

# Information

This section covers the dependency analysis, the assumption log, and the alternative considered.
Python package guidelines state that application requirements files must record exact versions for reproducible deployments [1].
When files omit version numbers, the installer selects the latest package versions [1].
Consequently, breaking changes in transitive libraries cause immediate build failures [judgment].
Pinning versions is virtually certain (99 to 100%) to eliminate build breakages caused by unpinned upstream library updates [judgment].
To manage updates safely, developers use tools, for example pip-tools, to compile lockfiles from direct requirements [1].
