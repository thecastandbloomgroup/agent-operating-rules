`user_id` → `account_id` rename plan

Run the rename in one short transaction, after a pre-flight check for references to `user_id`.

- The rename is a catalog change in Postgres, so it is fast and reversible.
- It takes an ACCESS EXCLUSIVE lock on `orders` [1], so keep the transaction short and set a lock timeout.

## Background
The request is to rename one column in one table in Postgres. The user is about to board a plane, so the plan favors one safe command over a long migration.

## Relevance
A rename that runs before the code deploys breaks live queries. The check below takes less than five minutes and removes that risk.

## Information
Per the Postgres documentation, `ALTER TABLE ... RENAME` changes the catalog only and takes an ACCESS EXCLUSIVE lock [1]. Concurrent writes to `orders` wait behind the lock until the commit [1]. A `lock_timeout` of five seconds makes a blocked rename fail cleanly instead of queueing.

Write the test before the work. Run this check first, against a staging copy or with care in production:

```gherkin
Given the orders table has a column named user_id
When I query information_schema.columns for table orders
Then exactly one column account_id is listed and no column user_id is listed
```

The dependency check before the rename:

```sql
SELECT DISTINCT dependent.relname
FROM pg_depend d
JOIN pg_rewrite r ON r.oid = d.objid
JOIN pg_class dependent ON dependent.oid = r.ev_class
JOIN pg_class source ON source.oid = d.refobjid
WHERE source.relname = 'orders';
```

Because the rename is reversible, the rollback test is one command away. [judgment]

```gherkin
Given the rename has committed
When I run ALTER TABLE orders RENAME COLUMN account_id TO user_id
Then information_schema.columns lists user_id again for table orders
```

## End
I recommend that we do this in three steps:

1. **Step 1, pre-flight check.** Search the codebase and the output of the dependency query for `user_id`, and update any live references first. Blocker removed: unknown breakage after the commit. Cynefin domain: Complicated, because analysis of the catalog and the code output picks the path before the rename. Test: the first Gherkin block above, written first.

2. **Step 2, the rename.** Run it in one transaction with `lock_timeout = '5s'`:

```sql

BEGIN;
ALTER TABLE orders RENAME COLUMN user_id TO account_id;
COMMIT;
```

3. **Step 3, verify and keep the rollback ready.** Run a smoke query that selects from `orders` by `account_id`, and keep the rename-back command ready. Blocker removed: silent failure after the commit. Cynefin domain: Clear, one known step. Test: the last Gherkin block above.
