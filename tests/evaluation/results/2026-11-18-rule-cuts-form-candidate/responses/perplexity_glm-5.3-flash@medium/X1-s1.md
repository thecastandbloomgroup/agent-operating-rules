**Headline**

Build a measured error baseline first, then fix the summarizer against it, and give agents a check and a feedback channel.

- Agent reports of "sometimes wrong" do not name an error type, so no fix can be chosen from them yet [inference].
- 50 to 100 annotated summaries give an error rate and an error taxonomy within one week [judgment].
- A citation to the transcript line after each summary sentence turns an unverifiable summary into a checkable one [judgment].
- Logged agent edits supply a continuous quality signal after the baseline week [judgment].

## Background

The support tool now includes an LLM summarizer. Agents report that summaries are sometimes wrong. The tool has no quality metrics, so the defect rate and the error types are unknown.

## Relevance

Without a baseline, any prompt or model change is unmeasured and can add errors. A one week annotation effort replaces "sometimes wrong" with numbers and a target.

## Information

First, LLM summary errors on support tickets fall into a small known set [inference]: factual error, missing key fact, extra content, and wrong format or tone. Second, human labels are the ground truth, because no field in the transcript computes summary correctness by itself [judgment]. Therefore the plan annotates first, computes metrics second, and changes the output third.

Assumption log:

- Assumption: "wrong" means factual errors or missing key facts, not style. Why not measured: the material does not state the error type. Validate by: read 30 flagged summaries against the rubric. If wrong: the rubric weights change, the later steps do not.
- Assumption: ticket transcripts are stored and machine readable. Why not measured: the material does not describe the tool's data. Validate by: export one transcript with line IDs. If wrong: replace the citation step with weekly quote checks by the annotators.
- Assumption: agents can give 30 minutes each in week one. Why not measured: agent time is outside the material and no tool can reach it. Validate by: ask the team lead to name three agents. If wrong: the sample drops to 30 summaries, and stated error rates get wider intervals.

Alternative considered: ship an improved prompt now and measure later. That loses because a change without a baseline cannot show whether the error rate fell [judgment].

## End

I recommend that we run five steps. Steps 1 and 2 run in order. Step 3 can start at once. Step 4 waits on Steps 1 and 2. Step 5 runs in parallel with Steps 2 to 4, capped by its budget.

1. **Write the rubric and annotate 50 summaries** (evaluative, Complicated).
   Increment: a one page rubric with four error types (factual error, missing key fact, extra content, wrong format or tone), then two agents label 50 summaries in one 30 minute session each.
   Blocker removed: the unknown error taxonomy and the missing ground truth labels.
   Test, written first: the rubric states the four criteria, a weight of 1 for each, a pass threshold of 80 percent annotator agreement, and transcript text as the evidence per label. Annotation stops when 80 percent agreement is met.
   Domain: Complicated, because the correct taxonomy is deduced from analysis of the sample, not assumed [judgment].

2. **Compute the baseline metrics** (deterministic, Clear).
   Increment: a short script that reads the rubric labels and prints the error count per type and the total error rate per 100 summaries.
   Blocker removed: "no metrics".
   Test, written first, in Gherkin form:
   ```
   Given 50 labeled summaries
   When the script runs on the labels
   Then it prints four per type counts and one total error rate
       And a second run on the same labels prints the same numbers
   ```
   Domain: Clear, because the computation is a known rule applied to recorded labels.

3. **Require a transcript citation on every summary sentence** (deterministic, Clear).
   Increment: a prompt change and a format check, so each summary sentence ends with a transcript line ID that opens in one click.
   Blocker removed: agents cannot verify summary claims against the ticket today.
   Test, written first, in Gherkin form:
   ```
   Given a generated summary
   When the format check runs
   Then it rejects any summary where a sentence lacks a line ID
       And each cited line opens to the correct transcript text
   ```
   Domain: Clear, because grounded generation with per claim citations is a known practice; it is expected to cut factual errors, at 70% likely [judgment].

4. **Calibrate an LLM judge against the human labels** (stochastic, Complicated).
   Increment: a second LLM scores new summaries on the rubric types, validated against the 50 human labels.
   Blocker removed: annotation does not scale past week one, so ongoing checks need an automated judge.
   Acceptance test, written first: metric is judge to human agreement on error type; baseline is the 80 percent human agreement from Step 1; pass threshold is agreement within 10 percentage points of that baseline; sample size is 100 summaries.
   Domain: Complicated, because analysis of the agreement data decides whether the judge is usable [judgment].

5. **Log agent edits as a quality signal** (stochastic, Complex probe).
   Increment: record which summaries an agent rewrites, and diff each rewrite against its summary, capped at two developer days.
   Blocker: after week one, new summaries have no human labels, so edits are the only continuous signal.
   Measure: edit rate per 100 summaries, and the rubric type inferred from each diff.
   Stop condition: stop the probe if the edit rate falls below 5 per 100 summaries over two weeks, because the signal is then too sparse.
   Budget: two developer days.
   Domain: Complex, because the link between the edit rate and the true error rate becomes visible only after the probe runs [judgment]. What could break the pattern: agents may rewrite for style alone, so each diff needs a type label, not a count alone.

Sequencing: Step 2 MUST NOT start until Step 1 reaches 80 percent agreement. Step 4 MUST NOT start until Steps 1 and 2 finish. If the transcript assumption is false, replace Step 3 with weekly manual quote checks by the annotators.
