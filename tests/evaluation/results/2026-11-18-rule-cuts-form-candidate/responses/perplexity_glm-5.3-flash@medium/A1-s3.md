## Headline

Pin every direct dependency to an exact version in requirements.txt. Support:

1. Unpinned versions let pip resolve a newer release on each install, so builds that worked on Monday fail on Tuesday.
2. The two breakages last month are consistent with this failure mode; pinning makes the dependency set reproducible.
3. Pin only direct dependencies and generate the lock of the full tree with pip-tools, so upgrades stay deliberate.

## Background

The project has a requirements.txt with no pinned versions. Two builds broke last month after a library update. The request: decide whether to pin.

## Relevance

Reproducible builds are the base for reliable deployment and for rolling back a bad release. The next unpinned install can reintroduce the failure on any machine.

## Information

What happened: the build depends on packages whose versions float. Pip resolves the newest version that satisfies each range at install time [1]. A new release upstream then silently changes the dependency tree. The two breakages last month are a source statement from this conversation; they give a 100% failure rate over two observed upstream updates [2]. Therefore the floating resolution is the main suspect. Full reproducibility also needs the transitive tree, not only top-level lines [1].
