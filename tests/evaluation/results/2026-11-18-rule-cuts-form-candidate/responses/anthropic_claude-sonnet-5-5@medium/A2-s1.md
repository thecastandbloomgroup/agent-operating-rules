## Headline

Run `ALTER TABLE orders RENAME COLUMN user_id TO account_id;` inside a transaction, but only after you check what depends on the old name.

- The rename changes metadata only, so it runs fast [1].
- Code that still uses `user_id` breaks the moment the rename commits.
- Do not start this deployment from the plane, because you cannot watch it or roll back.

## Background

The orders table in your Postgres database has a column named `user_id`. You want the name `account_id`. The material does not show the schema, the Postgres version, or the code that reads this column.

## Relevance

## Information

Evidence:
- Postgres renames the column in place. Indexes, constraints, and foreign keys that use the column follow the new name [1].
- The command takes a short exclusive lock on the table [1].
- Views keep working after a rename, because Postgres tracks columns by number, not name [1].
- Application queries, SQL functions written as text, and ORM (object-relational mapper) mappings do not update. Breakage is very likely (90 to 100%) if any code names the column [judgment].
