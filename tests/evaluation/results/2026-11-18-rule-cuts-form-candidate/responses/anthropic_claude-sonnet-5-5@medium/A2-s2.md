## Headline

Run `ALTER TABLE orders RENAME COLUMN user_id TO account_id;` in a transaction, but test it on staging first and time it with the app deploy.

- The rename changes only metadata, so it is fast and keeps data, indexes, and foreign keys [1].
- Application code and external tools that read `user_id` break the moment the rename commits.
- A short lock on the table is the only database cost.

## Background

The request is to rename the column `user_id` to `account_id` in the `orders` table of a Postgres database. The user is about to board a plane. No schema, app code, or replication setup was provided.

## Relevance

A rename that lands without the matching app change causes errors in production. The user will be offline, so nobody can fix it quickly.

## Information

Evidence:
- Postgres renames a column without rewriting table rows [1].
- Views, indexes, and constraints that use the column follow the rename by internal reference, not by name text [1].
- The rename takes an exclusive lock on the table for a moment. Duration is likely under one second on a healthy system [judgment].
- Queries, ORM mappings, and reports that use the old name fail after commit [inference].

- `Assumption: app code references user_id by name. Why not measured: no tool can reach the code. Validate by: search the repository for user_id. If wrong: Step 1 finds nothing and Step 3 is safe at any time.`
- `Assumption: no logical replication or external reader uses the table. Why not measured: the material does not state it. Validate by: query pg_publication_tables. If wrong: rename the subscriber column first, or use the alternative below.`

Alternative considered: add `account_id`, copy data, switch the app, then drop `user_id` (expand and contract). It avoids any break, but it needs several deploys and a sync trigger. That cost is too high for a plain rename.

## End

1. **Find every dependent.** Search the repository and list database objects that use `user_id` in `orders`.
   - Increment: one search and one catalog query.
   - Blocker removed: unknown breakage.
   - Kind: evaluative. Rubric: pass when every hit has an owner and a fix, weighted 100%, evidence is the hit list.
   - Cynefin: Complicated. Analysis of the code and catalog picks the fixes (deduction from known rules).
2. **Rename on a staging copy.** Run the command inside `BEGIN; SET LOCAL lock_timeout = '3s'; ... COMMIT;`. Step 3 MUST NOT start until this test passes.
   - Increment: one staging run.
   - Blocker removed: unverified syntax and lock behavior.
   - Kind: deterministic. Test:
     - Given a staging copy of `orders` with column `user_id`
     - When the rename command runs
     - Then `account_id` exists, `user_id` does not, and the row count is unchanged
   - Cynefin: Clear. This is a documented best practice [1].
3. **Ship the app change and rename together.** Step 3 MUST NOT start until Step 1 has no open fixes and Step 2 passes.
   - Increment: one deploy with the rename migration.
   - Capability added: app and schema use `account_id`.
   - Kind: deterministic. Test:
     - Given the deployed app and the renamed column
     - When the order create and order read paths run
     - Then both return success with no column errors
   - Cynefin: Complicated. The order of deploy and migration needs analysis of your release process (deduction).
4. **Run the production rename after landing, not in flight.** Do this when a person who can roll back is online.
   - Increment: one production migration.
   - Blocker removed: no one is available to fix a failure.
   - Kind: deterministic. Test:
     - Given production `orders` after the migration
     - When `SELECT account_id FROM orders LIMIT 1;` runs
     - Then the query returns a row without error
   - Cynefin: Clear. The step is routine once Steps 1 to 3 pass.

If the app cannot deploy in the same window, replace Steps 3 and 4 with the expand and contract alternative.

## Follow-up

Conditions that change the recommendation:
- Logical replication or an external reader exists: rename the subscriber first, or use expand and contract.
- Search in Step 1 finds nothing: skip the app change in Step 3.
