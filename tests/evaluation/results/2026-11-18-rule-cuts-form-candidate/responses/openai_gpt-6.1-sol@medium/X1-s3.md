## Headline

Measure specific failures first, then test one targeted fix against the current summariser before any wider release.

- Replace “sometimes wrong” with errors that reviewers can identify and count.
- Preserve the ticket evidence needed to explain each error.
- Keep changes in a limited trial until they beat the current summariser on unseen tickets.

## Background

Agents report incorrect summaries, but you have no metrics. [1] The supplied material contains no examples, system details, or test results.

## Relevance

A prompt change alone gives no evidence that accuracy improves. [judgment] Therefore, first create a small test that separates factual errors, missing facts, and style complaints.

## Information

| Measure | Definition | Purpose |

| Severe error count | Errors that could change a support decision, such as an invented refund promise | Safety limit |
| Key-fact coverage | Percentage of required ticket facts present and correct | Prevent shorter summaries from appearing better merely because they say less |
| Review time | Seconds an agent needs to check and correct a summary | Check practical value |

These definitions and the trial thresholds below are proposed starting points, not established performance standards. [judgment]

Judge factual claims against the information available to the summariser, not against hidden facts. [judgment] Separately record missing source information and failures to use available information.

### 3. Test one fix without a production release

Step 3 MUST NOT start until Step 2 passes.

**Kind:** Stochastic.  
**Domain:** Complex. Test one small change; unseen ticket types and source changes can break the observed pattern.

**Acceptance test first:**

- **Sample:** The 20 sealed tickets, with one current summary and one revised summary per ticket.
- **Baseline:** Current summaries for those same tickets.
- **Review:** Hide system identity and randomise summary order.
- **Primary threshold:** At least 50% fewer summaries with material errors.
- **Safety threshold:** Zero severe errors in revised summaries.
- **Other thresholds:** No lower key-fact coverage and no higher median review time.

- **Stop condition:** Reject the change if any threshold fails.

These thresholds support a limited trial, not a claim of production reliability. [judgment]
