### 1. Review ten cases and identify the first failure to address

**Kind:** Evaluative.  
**Domain:** Confused, because the available evidence does not establish the cause.

**Test first: weighted decision rubric**

Score each summary against its source conversation:

| Criterion | Weight | Evidence required | Score |
|---|---:|---|---|
| Facts match the source | 50% | Source passage for each factual claim | 1 if all match; otherwise 0 |
| Required facts appear | 30% | Issue, current status, and next action | 1 if all applicable facts appear; otherwise 0 |
| Status and commitments match | 20% | Source passages for status, owner, promises | 1 if all match; otherwise 0 |

**Pass threshold:** At least 90/100, with no invented commitment or incorrect resolution status. These thresholds are proposed judgments. [judgment]

**Work:** In one review session, select ten recent cases without filtering for quality. Add up to three agent-reported failures separately.

For each case, retain:

- The exact input supplied to the model.
- The summary, prompt version, and model configuration.
- The source conversation and reviewer correction.
- The rubric scores and defect type.

Score every criterion against the source. Keep reported failures separate from the random sample when calculating the baseline.

Record the percentage of random cases with any factual error, any missing required fact, and incorrect status or commitments. Also record review time.

**Output:** A scored baseline and one chosen defect, supported by examples.

This removes the diagnosis blocker. [judgment] Use the evidence to classify the next change: known fixes need analysis; uncertain fixes need a trial.

### 2. Prevent unchecked summaries from becoming authoritative

**Kind:** Deterministic.  
**Domain:** Clear, using deduction from the rule that unverified summaries require agent review.

**Test first:**

```gherkin
Given an agent opens a generated summary
When the summary appears
Then the interface labels it "Draft: verify against the conversation"

Given an agent prepares a customer-facing reply
When the reply includes the summary
Then the workflow requires explicit agent confirmation

Given the summariser is disabled
When an agent opens a case
Then the original conversation remains available
```

**Work:** In one session, add or verify the draft label, confirmation step, and disable control.

Do not send ticket content to a new external service for this review.

**Output:** A tested review barrier and a working fallback to the source conversation.

This limits unchecked use while quality remains unmeasured. [judgment] It does not establish that the summaries are accurate.

Run this alongside Step 1, unless the workflow assumption is false. In that case, complete this step first.

### 3. Test one change against the baseline

**Kind:** Stochastic, because model output varies between runs.  
**Domain:** Complex, using induction from trials; new ticket types or later model changes can break the observed pattern.

**Acceptance test first:**

- **Metric:** Percentage of summaries that pass Step 1’s rubric.
- **Baseline:** The current version on the same trial cases.
- **Sample:** Ten fresh cases, two runs per case for each version: 40 summaries total.
- **Threshold:** Candidate pass rate improves by at least 10 percentage points.
- **Safety threshold:** No invented commitments or incorrect resolution status in candidate outputs.
- **Comparison:** Review outputs without showing the reviewer which version produced them.

**Work:** After Step 1, choose one change that addresses its evidence.

For example, restore missing input before changing the prompt. If input is complete, test a prompt that forbids unsupported facts and marks absent details as “not stated.”

Freeze the model configuration and all other changes. Run the trials and score all outputs.

**Budget:** One 90-minute session.  
**Stop condition:** Stop the candidate trial after an invented commitment or incorrect resolution status.  
**Output:** A scored comparison and a retain-or-reject decision.

Accept the candidate only if every threshold passes. Otherwise, retain the current version with Step 2’s safeguards.

This is a small trial, not proof of a reliable production error rate. [judgment] Its leverage remains a guess until the trial produces evidence.

## Follow-up

If the trial passes, expand the evaluation before wider release. Include long conversations, reopened cases, handovers, and cases with no agreed next action. [judgment]
