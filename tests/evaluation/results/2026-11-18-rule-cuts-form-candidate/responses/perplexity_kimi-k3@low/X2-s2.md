**Headline**

Retrospectives fail because they end in talk, not in owned, tested commitments; fix this by closing every session with one to three assigned actions that are reviewed first at the next session.

- Action items lack a single owner, so no one acts between meetings. [judgment]
- Too many items are raised, so none get priority. [judgment]
- No one reopens old items, so the team learns that follow-up is optional. [judgment]

**Background**

Your retrospectives run on schedule but produce no change. The team attends but sees no effect from what it discusses.

**Relevance**

A retrospective that changes nothing costs the meeting time and builds cynicism. That combination makes later improvement efforts harder.

**Information**

Evidence: Derby and Larsen describe the retrospective as a cycle that ends in experiments with owners and follow-up [1]. Observed failure pattern in this case is inferred from your description [inference].

Assumption: The team runs a standard sprint retrospective with a facilitator. Why not measured: the material does not state it. Validate by: confirm the meeting format in one message. If wrong: adjust Step 2 to fit the actual format.

Assumption: The team has authority to change its own process. Why not measured: the material does not state it. Validate by: ask the team lead. If wrong: add a step to escalate blocked items to management.

Alternative considered: replace retrospectives with written async feedback. This loses because the core defect is missing follow-through, not the meeting format [judgment].

**End**

I recommend that we:

1. Start the next retrospective with a five-minute review of the last session's action items. This removes the blocker that old commitments vanish. Test (deterministic):
   - Given the last retrospective's action list,
   - When the facilitator opens the meeting,
   - Then each item is read aloud and marked done, in progress, or dropped.
   Cynefin domain: Clear. A known best practice exists for closing the loop [1].

2. Limit each session to one to three action items, each with one named owner and a date. This removes overload. Test (deterministic):
   - Given the discussion list,
   - When the team selects items,
   - Then each item shows a single owner, a due date, and a done definition.
   Cynefin domain: Clear. The rule is specified by the facilitator.

3. Run a one-time evaluative review of the last three retrospectives to find the root cause. Rubric (Pugh matrix): criteria are owner assigned, item count, follow-up held, item completed; weight each 25%; pass threshold is 75% of items compliant; evidence is meeting notes [no source: notes not yet reviewed]. Cynefin domain: Complicated. Analysis of records identifies which failure mode dominates.

Step 3 MAY run in parallel with Steps 1 and 2. No step waits on another.

**Follow-up**

If Step 3 shows that blocked items sit with management, add a step: escalate each blocked item to the manager within one week.
