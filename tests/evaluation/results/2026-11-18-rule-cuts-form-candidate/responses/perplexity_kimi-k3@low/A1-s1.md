## Headline

Pin all top-level dependencies in requirements.txt, and use a lock file for transitive dependencies.

- Two build breaks in one month show the current setup has a repeated failure mode.
- Pinning top-level packages removes the largest source of unplanned changes.
- A lock file (for example from pip-compile) fixes the full dependency tree, because top-level pins alone leave transitive versions free.
- Scheduled, tested updates control update risk better than random upstream releases.

## Background

The build broke twice last month after library updates, with no versions pinned in requirements.txt. The question is whether to pin versions. The failure evidence points to uncontrolled upgrades as the cause.

## Relevance

Each unplanned breakage costs debugging time and blocks releases. Pinning converts a random failure into a planned, testable change.
