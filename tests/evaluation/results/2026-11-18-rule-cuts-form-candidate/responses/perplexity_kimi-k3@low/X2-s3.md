# Headline

Run retrospectives only when each one produces one tested change with a named owner and a date.

- Attendance without change means the meeting asks for discussion but never demands a decision.
- The fix is structural: fewer action items, one owner per item, and a review of the last item before new topics.
- Start with a two-cycle trial, because the failed pattern is likely low ownership, not low honesty. [judgment]

# Background

The team holds retrospectives, people attend, and nothing changes afterward. The request is what to do.

# Relevance

A recurring meeting with no output costs time and teaches people that speaking up changes nothing. Fixing the output mechanism restores the value of the time already spent.

# Information

Retrospective failure of this kind is a known pattern: teams collect many action items, assign none to a single owner, and never review prior items [inference].

Scrum guidance treats the retrospective as a source of concrete improvement items added to the next sprint's plan, which supports the one-owner, one-change structure [1].

The recommendation rests on a judgment claim, so it is tested rather than assumed: two cycles will show whether items now complete.

Assumption: the team has the authority to change its own working agreements. Why not measured: the material does not state it. Validate by: ask the team lead before the first trial. If wrong: escalate approval for one change first, then run the trial.
Assumption: the failure is follow-through, not fear of speaking. Why not measured: the material does not state it. Validate by: an anonymous one-word survey in cycle one. If wrong: address safety first, and details are in Follow-up.

Alternative considered: replace the retrospective with written async feedback. This loses because async input has lower completion rates when accountability is already weak [judgment].

# End

I recommend that we run the following steps, ordered by leverage:

1. Cap action items at one per retrospective, each with one named owner and a due date. Increment: change the meeting script this week. Blocker removed: diffusion of responsibility. Task kind: deterministic. Test first: Given a retrospective produces action items, When the meeting ends, Then exactly one item exists with one owner and a date. Cynefin domain: Clear, because a known best practice applies by deduction from [1].
2. Open every retrospective with a status check on the prior item, before new topics. Increment: add this five-minute step at the next meeting. Blocker removed: completed work never confirmed or dropped work never examined. Task kind: deterministic. Test first: Given a prior action item exists, When the retrospective opens, Then its status is recorded as done, in progress, or dropped. Cynefin domain: Clear, deduced from [1].
3. Trial the format for two cycles and measure completion. Increment: run cycle one and two over the next four weeks. Task kind: stochastic, because attendance behavior varies. Acceptance test first: metric is completed action items, baseline is 0 per current report, pass threshold is at least 1 of 2 items done at a sample of 2 retrospectives. Stop condition: pause after cycle one if no item is selected. Cynefin domain: Complex, a safe-to-fail probe, because cause and effect here is induction from trials and could break if an outside blocker, such as workload, dominates.
4. After two cycles, keep, adjust, or replace the format based on the measured completion rate. Increment: one 15-minute review after cycle two. Task kind: evaluative. Rubric first: completion rate (weight 0.5, threshold 100%), participant rating of usefulness 1 to 5 (weight 0.3, threshold 4), meeting length under 60 minutes (weight 0.2). Pass threshold: weighted score of 0.7. Evidence: meeting notes and the survey. Cynefin domain: Complicated, because analysis picks the next practice.

Step 4 MUST NOT start until the trial in Step 3 completes its two cycles.

# Follow-up

Condition that changes the recommendation: if the survey shows people fear speaking up, replace Steps 1 and 2 with anonymous input and facilitation changes first, since silence, not ownership, is the blocker.
