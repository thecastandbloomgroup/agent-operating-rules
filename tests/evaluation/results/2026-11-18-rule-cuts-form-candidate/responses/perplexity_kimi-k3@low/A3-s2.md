**Relevance:** Bandwidth and latency directly affect API consumers and hosting cost, so this decision changes response time for every request.

**Information:** JSON compresses well because it is repetitive text. Typical gzip ratios for JSON are 70% to 90% size reduction [judgment]. A 400 KB response would likely drop to roughly 40 to 120 KB on the wire, with compression time of a few milliseconds on modern CPU. The trade-off: 400 KB is large enough that default gzip levels work well, and clients support gzip almost universally via the Accept-Encoding header. One caveat: if responses carry sensitive data and sit behind TLS, compression can expose length-based side channels (BREACH-style attacks) only when responses reflect user input and secrets together; for typical API payloads where the client cannot inject reflected content, the risk is low [judgment].
