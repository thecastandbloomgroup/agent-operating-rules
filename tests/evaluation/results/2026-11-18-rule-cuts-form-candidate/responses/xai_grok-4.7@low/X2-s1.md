Headline
Limit each retrospective to one owned change, and check that change before the next meeting.
The meeting already gathers people, so attendance is not the gap.
The gap is a missing owner, date, and result.

Background
The team still attends retrospectives. Those meetings no longer change the work. The request is what the team should do next.

Relevance
The next meeting is the cheapest place to restore the loop. If that meeting ends without an owner, the same pattern continues.

Information
The Scrum Guide says the team identifies helpful changes and addresses the most impactful ones as soon as possible [1].
Derby and Larsen structure a retrospective so it ends in a decision about what to do [2].
Therefore the current meetings miss that purpose when they end in discussion only.

Assumption: The team can change its own working agreements. Why not measured: The material does not state it. Validate by: Confirm approval rights with the person who sets team process. If wrong: Name that person as the owner of the first change.
Assumption: A retrospective is already on the calendar. Why not measured: The material does not state it. Validate by: Check the team calendar this week. If wrong: Book one meeting before any other step.

Alternative considered: Redesign the whole retrospective format. It loses because [1] requires prompt action on one improvement, and a new format delays that action.

End
I recommend that we take these steps.

1. Confused. Reason: The material does not show whether the stall is authority, time, or follow-through, so classification comes first.
Increment: In one session, list the last three retrospective outputs and mark each as done, owned, or dropped.
Blocker removed: Unknown cause of the stall.
Test first. Kind: evaluative. Rubric: three criteria, equal weight, pass at 2 of 3. Criterion 1: each past item has a status. Evidence: the written list. 2. Clear. Reason: Deduction from the rule in [1] that an impactful improvement is addressed soon.

3. Complicated. Reason: Analysis of the status list picks whether the change is a team habit or an outside constraint.
Increment: In one session, label the chosen change as team-controlled or outside-controlled.
Blocker removed: Effort spent on a change the team cannot make.
Test first. Kind: evaluative. Rubric: two criteria, equal weight, pass requires both. Criterion 1: the change has one control label. Evidence: the label on the note. Criterion 2: an outside change has a named approver. Evidence: the approver's name.

4. Complex. Reason: Cause and effect appear only after a trial, so this is a safe-to-fail probe. A single cycle can break the pattern if that cycle is atypical.
Increment: Spend at most 20 minutes mid-cycle to record whether the change is in use.
Blocker removed: No early signal before the next retrospective.
Budget: 20 minutes. Stop if the owner is absent. Do not add a second change in this cycle.
Test first. Kind: stochastic. Metric: share of sampled work items that show the change. Baseline: 0 confirmed uses before the probe. Pass threshold: at least 1 confirmed use. Sample size: 5 work items, or the full set if smaller than 5.
Step 4 MUST NOT start until the test in Step 2 passes.
