## Headline

Run `ALTER TABLE orders RENAME COLUMN user_id TO account_id;` and then update any views or queries that still read `user_id`. The rename changes only the catalog, so it finishes fast and does not rewrite table data [1]. Code that still references `user_id` will break until it is updated.

## Background

The request is a single schema change in Postgres before you board a plane. The change is one statement with a brief exclusive lock.

## Relevance

The statement itself is safe to run remotely. The risk is not the rename; it is the dependent objects that reference the old name.

## Information

Run this first:

```sql
ALTER TABLE orders RENAME COLUMN user_id TO account_id;
```

Postgres implements rename as a catalog-only change, so it does not rewrite table data and holds the exclusive lock only briefly [1].
