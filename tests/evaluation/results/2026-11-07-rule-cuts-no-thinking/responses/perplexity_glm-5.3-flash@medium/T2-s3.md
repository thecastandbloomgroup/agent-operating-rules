## Headline

No prompt can make the model stop hallucinating. The best prompt reduces the error rate, marks the rest, and pairs with a check after the answer.

1. Hallucination comes from how the model works, not from one line of instruction [1].
2. The prompt with the best effect forces sources, permits refusal, and demands a check per claim.
3. A verification pass after the answer removes more errors than any wording inside one prompt [2].
4. Measure the error rate on a fixed test set, because wording changes hide their own effect.

## Background

The user asks for one prompt that stops a model from inventing facts. The request assumes a chat model, reached through prompts only, with no access to model weights.

## Relevance

Unchecked invented facts cost trust and rework. A prompt plus a simple check gives most of the gain at near-zero cost.

## Information

Here is the prompt. Put it in the system message of every session.

```text
Answer only from the sources given in this conversation. For each fact, name the source or write: general knowledge.
If a source does not support a claim, write: not in the sources.
If you are not sure, write: not sure.
Do not guess. Do not invent names, numbers, or citations.
```

Why this wording works:

1. It demands a source per fact, so the model has to expose its evidence.
2. It adds cheap exit paths: "not in the sources" and "not sure". Models invent facts because they are forced to answer [1].
3. It bans the exact outputs users care about: names, numbers, citations.

A prompt alone is not enough. A second pass that lists each claim and verifies it cuts errors further [2]. Detection from repeated samples also works when no source exists [3].

Assumption: The user wants factual accuracy, not creative text. Why not measured: the material does not state it. Validate by: ask the user. If wrong: drop the refusal rules, because they lower creative range.

Assumption: The model used has a system message slot. Why not measured: the material does not state it. Validate by: check the product UI. If wrong: put the same text as the first user message.

Alternative considered: ask the model to "be honest" or "do not hallucinate". This loses. Words without a procedure change little, because the model lacks a refusal path and no check runs after the answer [judgment].

## End

I recommend that we do the following.

1. Paste the prompt above into the system message and use it in every session. This removes unsupported claims at the source. Cynefin: Clear. It is one step from a known rule. Test:

```gherkin
Given the prompt is in the system message
When the user asks a question with no source support
Then the answer contains "not in the sources" and no invented detail
```

2. Build a test set of 20 questions with known answers and run both prompts. This measures the error rate, so wording changes can be judged. Cynefin: Complicated. Simple counting analysis picks the winner. Test (stochastic): metric is factual error rate, baseline is the current prompt, threshold is a 50 percent lower rate at 20 questions, sample is the 20 questions. Step 2 waits for Step 1.

3. Add a verification pass: after each answer, the model lists each claim and checks it against the source. This removes errors that the first pass leaves. Cynefin: Complex. It is a safe-to-fail probe; the pattern could break on multi-part answers. Cap: 10 test questions. Stop condition: no error drop after the cap. Leverage is a guess.

## Follow-up

Condition that changes the recommendation: if the task is creative writing, drop the refusal rules in the prompt. They suppress invention, and invention is the goal there [judgment].
