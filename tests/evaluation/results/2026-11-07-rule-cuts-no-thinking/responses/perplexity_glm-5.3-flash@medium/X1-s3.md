## Headline

Measure the failures first, then fix the most common failure type, then keep the measurement running.

- Agent reports say "sometimes wrong" but name no error type, so no change can be tested.
- A labeled set of 50 summary and ticket pairs gives the error types, the baseline score, and the target.
- Per-sentence citation of ticket lines removes the top LLM failure, unsupported facts.
- One-click agent feedback grows the labeled set at near zero cost.

## Background

An LLM summariser sits in the support tool. Agents report that it is "sometimes wrong". The request is "make it better". There are no metrics, no labels, and no error list.

## Relevance

Without an error list, prompt changes are guesses [judgment]. One working session of labeling converts anecdote into a ranked target list.

## Information

The likely top failure class of summarisation is invented or unsupported statements. Moderate confidence, basis: agent reports only and common error patterns in this task type, no local labels [judgment]. Complete error classes are correct facts, missing facts, invented facts, wrong length, and wrong tone. Because the local mix is unknown, the first action must gather it.

## End

I recommend that we run four steps, in this order.

1. **Classify the errors (Confused).** Increment: in one session, write the rubric, then label 50 summary and ticket pairs from the past month. Rubric: correctness weight 0.4, completeness weight 0.3, length weight 0.15, tone weight 0.15, each scored 1 to 5 against the ticket text; pass threshold is a mean of 4.0. Record each failure under a named class. Blocker removed: "sometimes wrong" becomes a ranked error list with a baseline score. Test (before the work, evaluative): two labelers score the same 10 pairs, and agreement reaches 80 percent or higher; if not, sharpen the rubric first. Reason for the domain: the local error mix is unknown, so this action gathers the data needed to classify later work. This step MUST run before any other step.

2. **Ground every sentence (Clear).** Increment: in one session, change the prompt so each summary sentence cites one ticket line, and add a check that every cited span's text appears in the ticket. Blocker removed: invented facts become visible and rejectable before agents read them. Test (before the work, deterministic):
   - Given a ticket with statements A, B, and C
   - When the summariser produces a summary with cited spans
   - Then every cited span matches ticket text exactly, and the summary fails closed when a span does not match
   Reason for the domain: cause and effect are known, one rule applies. This step MUST NOT start before the rubric in Step 1 exists.

3. **Add one-click feedback (Clear).** Increment: in one session, add two buttons, "correct" and one tag per error class, and write each answer to the labeled set. Blocker removed: labels grow after release without paid label sessions. Test (before the work, deterministic):
   - Given an agent viewing a summary
   - When the agent presses a tag button
   - Then the pair, the tag, and the timestamp appear in the label store
   Reason for the domain: cause and effect are known, the rule is a simple write path.

4. **Re-score after Step 2 ships (Complicated).** Increment: in one session, score 50 fresh pairs with the same rubric, and compare two prompt variants with a Pugh matrix against the baseline. Blocker removed: it proves the change helped, or it names the next error class to attack. Acceptance test (before scoring, stochastic): metric is mean rubric score, baseline is Step 1's score, pass threshold is plus 0.3 points or more, sample size is 50 pairs per variant. Reason for the domain: several good practices exist, so analysis across variants picks one, and the inference is induction until 50 pairs agree.

Condition that changes this plan: if Step 1 shows that missing facts or wrong length dominate instead of unsupported facts, run Step 4 on a prompt that addresses that class, and reorder Step 2 behind it.
