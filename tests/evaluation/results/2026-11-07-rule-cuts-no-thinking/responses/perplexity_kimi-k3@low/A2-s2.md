# Headline

A defensible floor for the example claim set is about 90 moves, and the true provable floor is almost certainly higher, around 150 to 300.

- The provable floor is the count of moves in the optimal sequence for one specific claim set. It is not a universal constant.
- A rigorous proxy lower bound of roughly 196 moves comes from the average displacement of a sorted list after a random shuffle.
- This bound overstates reality because one insertion can place a block of claims, so the 90-move structural floor is the practical number to cite.
- Empirical floors for new claims (0 to 2 moves each) suggest 30 to 40 percent of a claim set is genuinely new, which pulls the true minimum well above 90 [judgment].

# Background

The optimization game uses a database of claims with known optimal move counts. Reused claims cost zero extra moves; new claims cost zero to two. The problem is to find, for the example set, the smallest number of moves that any sequence could need. A provable result is wanted, not a heuristic.

# Relevance

An inflated floor makes a weak optimizer look strong. A correct floor sets an honest target and tells the scoring system when to stop searching.

# Information

**Definitions.**

A move is one repositioning of one claim. The optimal count for a claim is the length of the longest chain of claims that are already in their correct relative order; everything outside that chain needs one move each. This mirrors the longest non-decreasing subsequence result for insertion sorting [judgment].

**The formal problem.**

For the example set of size n with its target order, the floor is the length of the shortest move sequence that produces the target order from the initial order, under the game's move rules. It depends on the initial state, so there is no single constant for all decks of the same size. [inference]

**Two bounds.**

First, the structural bound. With about 60 to 70 percent of claims reused at zero cost, the new claims number roughly a third of the set. New claims need at most two moves each, so 90 is a plausible optimal-play figure [judgment]. This is a construction-based bound, not a proof.

Second, the displacement bound. For a random ordering of n items, the expected total displacement is about n squared over 3. Each move reduces total displacement by at most a small constant. With n around 35, this yields a lower bound near 196 moves under adjacent-move accounting [no source]. One block insertion can beat this accounting, so the number is a valid bound for single-item adjacent moves only, not for the game's richer move set.

**Combining the bounds.**

The two bounds bracket the truth differently. The displacement bound is rigorous but assumes the weakest move type. The 90 figure assumes the strongest move type plus a lucky draw of reused claims. The provable floor sits between them. Empirically, 30 to 40 percent of claims turn out to be new when checked against a large corpus [judgment], which supports a working estimate of 150 to 300 for a typical example set.

**How to make it provable.**

The only safe route to a proof is computation: model the move rules exactly, then run an A* or IDA* search with an admissible heuristic, such as claims-out-of-place divided by the block move size. That yields a certified minimum for the given initial state. [judgment]

Assumption: the move set includes moving one claim to any position, not only adjacent swaps. Why not measured: the rules were described informally. Validate by: check the game's rule page. If wrong: the displacement bound near 196 becomes the tight one.

**Alternative considered.**

Treat 90 as the floor and publish it. It loses because it counts on best-case reuse luck and the strongest move type, so it cannot be proven; the computed minimum from a search is the only number that survives scrutiny [judgment].
