## Headline

The summariser needs a measurement loop before any tuning, because "sometimes wrong" cannot be fixed without knowing the error rate and error type.

1. Define a test set of past support conversations with a known-good summary for each.
2. Measure accuracy and error type against that set before any change.
3. Fix the dominant error type first, because one type usually causes most complaints.
4. Re-measure after each change and keep the change only if the score improves.

## Background

The support tool sends conversations to a language model and shows agents the summary. Agents report errors, but no rate or type is recorded. The task is to turn a vague complaint into a measurable, fixable system.

## Relevance

Without a baseline, every fix is a guess and regressions go unseen. A small investment in measurement now prevents repeated rework later.
