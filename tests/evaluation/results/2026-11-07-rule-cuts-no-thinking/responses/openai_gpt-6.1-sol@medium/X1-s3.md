## Background

## Relevance

“Wrong” does not identify whether the problem comes from missing context, invented facts, or lost details. [judgment] Therefore, changing the model now lacks a basis for choosing or judging the change. [judgment]

## Information

### What to measure

Use these error types to turn agent reports into evidence. The definitions and priorities below are proposed starting points. [judgment]

- **False claim:** The summary contradicts the conversation or states something the conversation does not support.
- **Missing fact:** The summary omits information needed for the next support action.
- **Usefulness defect:** The summary is accurate but requires needless edits or effort.
- **Severe error:** An error changes a payment, account action, security decision, customer promise, or next support action.

Measure errors at the **summary level**, not only the claim level. Otherwise, many correct claims can hide one harmful claim. [judgment]

Record the conversation reference, summary, model version, prompt version, and context supplied to the model. These records support diagnosis and repeat tests. [judgment] Keep records within existing access and retention controls; do not introduce a separate customer-data store. [judgment]

### 2. Audit 20 cases and select the main error cause

**Dependency:** Step 2 MUST NOT start until Step 1 passes.

**Kind:** Evaluative, meaning reviewers judge the output against stated criteria.

**Rubric first:** Use a weighted decision table. These weights and thresholds are proposed operating choices. [judgment]

| Criterion | Weight | Evidence required |
|---|---:|---|
| Factual support | 60% | Each claim matched to source conversation text |
| Required facts present | 25% | Reviewer’s required-fact list, written before reading the summary |
| Agent usefulness | 15% | Agent corrections and explanation of needed changes |

Score each criterion from 0 to 4: absent, poor, partial, mostly correct, or complete. Calculate the weighted score out of 100.

**Pass threshold:** At least 90/100, with no severe error. A severe error overrides the weighted score. [judgment]

**Work:** Review ten agent-flagged cases and ten randomly selected cases. If flagged cases do not exist, use twenty random cases.

For each failure, record the error type and inspect whether the model received the needed source facts. Then score every criterion against the recorded evidence.

**Increment and blocker:** Produce a scored audit and one priority cause. This replaces the vague complaint with a specific defect. [judgment]

Do not report this mixed sample as the overall error rate. Its selection favours reported problems. [judgment]

**Domain:** Complicated, through analysis of source text, supplied context, and summary claims.

**Current result:** Unscored. No cases or summaries accompany the request, so no observed scores exist.

### 3. Test one cause-specific change against the current version

**Dependency:** Step 3 MUST NOT start until Step 2 identifies a priority cause.

**Kind:** Stochastic, meaning outputs can vary between runs.

**Acceptance test first:** Use 30 unseen, randomly selected cases. Generate one current-version summary and one candidate summary per case.

Review all 60 summaries without showing reviewers which version produced them. Use the Step 2 rubric.

The proposed acceptance thresholds are: [judgment]

- **Primary metric:** Summaries with material errors fall by at least 50% against the current version.
- **Safety limit:** The candidate has zero severe errors across its 30 summaries.
- **Completeness limit:** The candidate omits required facts in no more cases than the current version.
- **Effort limit:** Median agent correction time does not exceed the current version.

If the current version has zero material errors, this sample cannot show the required improvement. Do not claim success.

**Work:** Change only the mechanism linked to the main cause:

- If needed facts never reach the model, fix the context supplied.
- If the model invents facts, require source-supported statements and explicit “not stated” responses.
- If it omits required facts, add named summary fields for those facts.

**Increment and blocker:** Produce one candidate and its paired test results. This tests cause rather than relying on agent preference alone. [judgment]

**Domain:** Complex, through induction from a small trial. Different case types or later model changes can break the observed pattern.

**Probe limits:** Cap the trial at 60 outputs and four hours. Stop on a severe candidate error. Do not release a candidate that fails any threshold.

**Current result:** No trial has run. These are acceptance criteria, not measured results.
