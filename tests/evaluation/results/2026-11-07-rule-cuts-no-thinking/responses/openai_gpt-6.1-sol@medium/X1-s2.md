## Background

Your support tool now includes an LLM-based summariser, which uses a large language model to shorten support records. Agents report errors, but you have no metrics. [1]

## Relevance

A fluent summary can still contain false facts or omit facts that change the next support action. [judgment] Therefore, measure correctness separately from agent preference and time saved. [judgment]

## Information

### What to measure

Use these definitions for the first trial. These are proposed measures, not existing results. [judgment]

| Measure | Definition |
|---|---|
| Material error rate | Share of summaries with an unsupported, incorrect, or missing fact that changes the next support action |
| Unsupported claim rate | Unsupported factual claims divided by all factual claims |
| Essential fact coverage | Included essential facts divided by essential facts identified from the source |
| Agent effort | Seconds needed to check and correct a summary |
| Severe error count | Errors involving identity, money, safety, access rights, or false commitments |

Reviewers must identify essential facts from the source before reading either summary. This reduces bias toward facts that the summariser already includes. [judgment]

Report counts alongside percentages. A small trial supports a limited pilot decision, not a claim of production reliability. [judgment]

### Assumption log

Assumption: Source records and summaries remain accessible under existing permissions. Why not measured: The material does not state it. Validate by: Retrieve one permitted example. If wrong: Establish restricted access before the trial.

### Alternative considered
