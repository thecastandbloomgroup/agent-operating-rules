## Headline

Yes, pin every version in requirements.txt, including indirect dependencies.

- Unpinned versions let a new release change your build without a code change, and this happened twice last month.
- Pinning only direct libraries is not enough, because their own dependencies still change.
- A pinned file needs a routine for upgrades, so the pins do not go stale.

## Background

Your requirements.txt lists libraries with no fixed versions. Each install fetches the newest release. The build broke twice last month after a library update [1]. You ask whether to pin the versions.

## Relevance

A build that breaks without a code change wastes team time and hides real defects. A pinned file makes each build repeatable now.

## Information
