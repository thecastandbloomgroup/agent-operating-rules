## Headline

Yes, pin every version in requirements.txt, including indirect packages, and update them on a schedule.

- Unpinned installs pick the newest release each time, so any upstream release can break your build.
- Pinning makes each build install the same versions, so a break only follows a change you made.
- Pinning alone leaves packages to age, so you need a routine to update them.
- The change is small: one session for the pins and one for the check.
