## Headline

Use a source-grounded prompt with an explicit "Not found" exit and a self-check, because no prompt removes hallucination completely.

- The prompt below forces each claim to carry a quote from supplied sources.
- It gives the model a permitted way to say it lacks the answer.
- A test on your own questions shows whether it works for your model.

## Background

You asked for one prompt that stops a model from inventing facts. Hallucination means output that sounds right but has no support in the sources or in reality. Research treats it as reducible, not removable.

## Relevance

A prompt that claims to fix the problem gives false comfort. A prompt plus a test gives you a measured error rate you can act on.

## Information

The best general prompt (paste your sources where marked):

```text
Answer only from the sources below.
If the sources do not contain the answer, write: "Not found in the sources."
Quote the exact sentence that supports each claim.
Mark any claim without a quote as [unsupported].
Do not guess names, numbers, dates, or links.
Before you send, check each claim against its quote.
Remove each claim that fails the check.

Sources:
<paste sources here>

Question:
<paste question here>
```

Why each part is there:

- First, "answer only from the sources" limits the model to supplied text. Grounding in retrieved text reduces invented facts in knowledge tasks [3].
- Next, the "Not found" exit matters because a model that must answer will guess. Some error is statistically unavoidable for rare facts [2].
- Then, the quote rule makes each claim checkable by you.
- Last, the self-check step matches a method that reduced hallucination in published tests [4].

Reference [1] surveys the causes and the main mitigation methods.

Assumption: You use a chat model and can paste source text. Why not measured: the material does not state your setup. Validate by: run the prompt once with and without sources. If wrong: without sources, the prompt cannot ground answers, so add a retrieval step first.

Assumption: Your tasks are factual questions, not creative writing. Why not measured: the material does not state the task. Validate by: check whether answers must match a source. If wrong: the "only from sources" rule blocks useful output, so relax it.

Alternative considered: Ask the model to "be accurate and do not hallucinate." This loses because it gives no source limit, no exit, and no check. [judgment]

## End

I recommend that we:

1. Build a test set of 50 questions with known answers, and make 10 of them unanswerable from your sources.
   - Increment: one working session to write the set.
   - Blocker removed: no way to measure error today.
   - Test (deterministic):
     - Given a file of 50 questions with answer keys
     - When a reviewer checks each key against the source
     - Then every key matches the source, or is marked "absent"
   - Domain: Clear. Deduction from a known rule: a test set needs keys.
2. Measure the baseline error rate with your current prompt. Step 3 MUST NOT start until this result is recorded.
   - Increment: run the 50 questions once.
   - Blocker removed: no baseline to compare against.
   - Test (stochastic): metric is the share of answers with an unsupported claim. Baseline is this run. Sample size is 50. Record the rate.
   - Domain: Complicated. Analysis picks the scoring rule: a claim counts as unsupported when no source sentence backs it.
3. Run the prompt above on the same 50 questions as a capped probe.
   - Increment: one run, one session, stop after two prompt edits.
   - Blocker removed: unknown effect on your model.
   - Test (stochastic): metric is the unsupported-claim rate. Baseline is Step 2. Pass threshold is a drop of at least half, and at least 8 of the 10 unanswerable questions get "Not found in the sources." Sample size is 50.
   - Domain: Complex. Induction from trials. A model update or a change in source style could break the pattern. The effect size is a guess until the run finishes.
4. If Step 3 fails, add retrieval so the model receives the relevant passages for each question.
   - Increment: connect one document set to one question flow.
   - Blocker removed: the model lacks the facts it needs.
   - Test (stochastic): same metric, baseline, and threshold as Step 3, with sample size 50.
   - Domain: Complicated. Analysis of the failed cases picks the retrieval method.

Condition that changes the recommendation: if your tasks need no sources, skip Step 4 and ask the model to state its confidence per claim.
