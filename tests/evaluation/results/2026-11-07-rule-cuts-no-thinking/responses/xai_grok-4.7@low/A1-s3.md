Background
The install list is requirements.txt, and no line states a version.
The build broke twice last month after a library update.
The request is whether those versions should be pinned.

Relevance
The next library release can break the build again before anyone reviews it.
A pin blocks that path until an update is chosen.

Information
A pin is a line that names one package and one exact version.
Write it as package==version.
Evidence: nothing is pinned, and two builds broke last month after a library update [1].
An unpinned file lets the installer pick a newer release on a later day [judgment].
Therefore the same file can install different code on two days.
Exact pins remove that change for named packages [judgment].
A transitive package is one your file does not name, but another package needs.
Those packages can still change unless a lock file pins them too [judgment].

Assumption: The installer is pip, and no lock file exists. Why not measured: The material does not state the installer. Validate by: Search for poetry.lock, Pipfile.lock, and uv.lock. If wrong: Use that tool's lock command instead of a pip pin.

Alternative considered: Pin only a lower bound, such as package>=1.2. It loses because a newer release can still break the build, which matches the two failures [judgment].
