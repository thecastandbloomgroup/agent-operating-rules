Headline
No prompt can make a model stop all false claims.
A short prompt can cut claims that lack support.
The prompt must force a support line or an explicit unknown.
A second pass must delete any claim that still lacks support.
A small test must show the drop before you trust the prompt.

Background
Models predict likely text. They do not check truth by default. The request asks for the best prompt to stop this behavior.

Relevance
False claims spread into decisions before anyone checks them. Therefore a prompt that forces support matters before the next answer.

Information
This section covers the limit, the prompt, and the log.
Survey work treats false model text as a lasting failure mode, not a wording bug [1].
Therefore no instruction can guarantee truth.
Retrieval of source text gives the model text to copy instead of memory alone [2].
So the best prompt works with supplied sources and abstains without them.
[judgment] The gain comes from refusal and deletion, not from longer reasoning text.

Assumption: the user wants one system prompt for a general chat model, not a full retrieval build. Why not measured: The material does not state it. Validate by: Name the model and the task. If wrong: Put source retrieval before the prompt.

Alternative considered: A long prompt that only says to be careful. It loses because it adds no delete step for unsupported claims [judgment].

Use this prompt.

You answer from the sources in this chat only.
If a fact is not in those sources, write "unknown".
Do not invent names, numbers, dates, quotes, or citations.
Put a support line under each factual claim.
The support line quotes the source or says unsupported.
Delete every claim marked unsupported.
Then give the short final answer.
If nothing remains, the final answer is "unknown".

End
I recommend that we take these steps.

1. Attach sources when they exist.
Test:
Given a question and a source excerpt,
When the excerpt sits above the question,
Then the answer can point to a line in that excerpt.
Increment: Paste the relevant excerpt in one session.
Blocker: Answers drawn only from model memory.
Domain: Clear. Reason: Deduction from a known rule that source text beats memory.
This step removes the largest blocker because later checks need text to cite.

2. Save the prompt in the Information section as the system prompt.
Test:
Given a question with no source,
When the model answers,
Then each factual claim has a support line, or the answer is "unknown".
Increment: Paste and save the prompt in one session.
Blocker: Free generation of unsupported claims.
Domain: Clear. Reason: Deduction from the written abstention rule.
Step 2 MUST NOT start until Step 1 is done when sources exist.
When no sources exist, start at Step 2.

3. Probe ten known questions.
Acceptance test:
Metric: share of answers with an unsupported factual claim.
Baseline: the same ten questions with no new prompt.
Pass threshold: the share falls by at least half.
Sample size: 10.
Increment: Run the ten questions once in one session.
Blocker: Unknown effect on the real task.
Domain: Complex. Reason: Induction from trials. The pattern can break if the questions differ from real work.
Budget: ten questions. Stop if the share does not fall.
Do not roll the prompt out until this probe passes.
Step 3 MUST NOT start until Step 2 is saved.

Follow-up
If the product must answer without sources, this prompt will return "unknown" often. Replace Step 2 with a prompt that labels estimates and still bans fake citations.
If there is no system-prompt field, put the same text in the first user message.
