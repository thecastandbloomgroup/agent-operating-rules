Headline

Measure error types on a labeled sample before any model change.

- A change with no baseline has no pass test. [judgment]
- "Wrong" can mean an invented fact, a missing fact, or the wrong tone. [judgment]
- Fifty labeled summaries can show which cause is largest. [judgment]
- The largest cause then sets the first fix. [judgment]

Background

The support tool now adds a summary from a large language model.
Agents say some summaries are wrong.
No metric exists, so the request is to make the summariser better.

Relevance

Agents act on these summaries during live tickets.
A wrong summary can send the wrong reply before anyone checks it. [judgment]

Information

This section covers the evidence, the assumptions, and the alternative.

Models that write a summary often add facts the source does not support.
[1]

Human scores of consistency are a standard way to judge that failure.
[2]

Therefore a labeled sample comes before a model change. [judgment]
A set of 50 recent summaries is enough to rank three error types for a first fix. [judgment]

Assumption: "Wrong" means an invented fact or a material omitted fact. Why not measured: The material does not state the error type. Validate by: Label 20 recent complaints. If wrong: Change the rubric weights before Step 2.

Assumption: The team can store a correction flag within one week. Why not measured: No tool can reach the product backlog. Validate by: Check the ticket schema for a flag field. If wrong: Use a shared sheet for the first 50 tickets.

Assumption: The model sees the full ticket text when it writes the summary. Why not measured: The material does not state the input. Validate by: Log one request payload. If wrong: Fix missing context before any prompt change.

Alternative considered: Swap the model now. It loses because there is no baseline, so a gain cannot be shown. [judgment]
