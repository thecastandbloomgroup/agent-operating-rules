Headline
Limit each retrospective to one owned change, and review that change at the next meeting.
A meeting with no decision cannot change the next sprint.
An action with no owner and no date does not get done.
The next retrospective must open by checking that one action.
A safety check is the next step only if actions already get done but hard topics stay hidden.

Background
The team holds retrospectives, and people attend, but the work does not change. The request is a next step that produces a real shift.

Relevance
Without a closed action loop, each meeting repeats the same talk. Therefore a small checked change is the fastest repair.

Information
The Scrum Guide says the team addresses the most impactful improvements as soon as possible, and may add them to the next Sprint Backlog.
[1]
Derby and Larsen close the retrospective by deciding what to do, after data and insight.
[2]
So the meeting fails when it stops before one chosen change enters the next sprint. [judgment]
Assumption: The main gap is follow-through, not a missing activity. Why not measured: The material does not state it. Validate by: Score the last three meeting notes. If wrong: Skip the action cap and run the safety probe first.
Alternative considered: Add new retrospective activities. It loses because activities do not create an owner, a date, or a review. [judgment]

End
I recommend that we take these four steps.
1. Classify the failure in one session before any format change. This removes the unknown cause. Domain: Confused, because the notes are not here yet, so the first act gathers what classifies the rest.
Test first, evaluative. Rubric: named owner on each action, weight 40. Done or not-done status, weight 40. At least one topic beyond logistics, weight 20. Pass threshold: 70 of 100. Evidence: notes from the last three retrospectives.
Increment: Score those three notes in one working session.
Step 2 MUST NOT start until this score exists.
2. If follow-through scores under 70, place one change on the next sprint backlog in the same session as the retrospective. This removes the unowned list. Domain: Clear, by deduction from the Scrum Guide rule to address the most impactful improvement soon.
Test first, deterministic.
Given one retrospective decision,
When the meeting ends,
Then the backlog holds one item with an owner and a due date.
3. Open the next retrospective with the status of that item. This removes the missing check on whether the change worked. Domain: Clear, by the same deduction, applied to the next meeting. Step 3 MUST NOT start until Step 2 has one backlog item.
Test first, deterministic.
Given the prior backlog item,
When the next retrospective starts,
Then the owner states done, not done, or blocked before any new topic.
4. If follow-through already scores 70 or more, and topic depth scores under 20, run one safety probe instead of Steps 2 and 3. This tests whether people can name a real obstacle. Domain: Complex, because cause shows only afterward, so this is a safe-to-fail probe. Leverage is a guess. Budget: one meeting. Stop if fewer than half the team answers.
Test first, stochastic. Metric: share of attendees who name one real obstacle. Baseline: no such names in the last three notes. Pass threshold: at least 50 percent. Sample size: one full team meeting.

Follow-up
Did the last three meetings name an owner for each action? The answer confirms or drops the follow-through assumption.
Do people name hard topics in the room? The answer starts or skips the safety probe.
If the follow-through score is already 70 or more, replace Steps 2 and 3 with Step 4.
