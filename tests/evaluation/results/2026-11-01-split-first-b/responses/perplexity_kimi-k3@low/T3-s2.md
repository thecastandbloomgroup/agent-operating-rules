# Headline

The session-to-JWT migration is a well-scoped engineering task; the sign-up conversion request is not, so split the work: run the migration now as a deterministic project, and treat conversion as a measurement-first experiment.

- The migration has fixed acceptance criteria and known cause and effect, so leverage estimates are reliable.
- Conversion improvement lacks a baseline and a metric, so any change without measurement is a guess.
- Mixing both into one deploy hides which change caused which outcome, so sequence them.

# Background

Two requests were made: migrate the auth service from server-side sessions to JSON Web Tokens (JWT), and improve sign-up conversion. No codebase, metrics, or rollout constraints were provided.

# Relevance

Combining an auth change with a conversion experiment in one release makes it impossible to attribute errors to either. Auth bugs also carry high rollback cost, so sequencing matters.
