# Headline

No single prompt stops a model from hallucinating; the best prompt pairs is one that demands sources and permits "unknown" as an answer. A second point: prompts only reduce errors, retrieval and verification remove them [judgment]. A third point: the right wording depends on whether the task has verifiable facts, so a template plus a check step beats any magic phrase.

## Background

The request asks for one best prompt to eliminate hallucination, that is, fabricated model output. The premise needs adjustment because hallucination is a property of the model and task, not only the wording.

## Relevance

Prompt wording is the cheapest control available, so picking a good one matters. Choosing a wrong "best" prompt creates false confidence, which is worse than the errors themselves.

## Information

Evidence: fabricated citations remain a documented failure mode even under instruction-following prompts, per the Harvard Business Review framing of generative model limits [1]. Judgment claim [judgment]: prompts that allow abstention ("if you do not know, say unknown") reduce confident fabrication more than prompts that demand completeness. The strongest alternative is one ultra-detailed mega-prompt; it loses because length raises instruction conflict and still cannot supply facts the model lacks [judgment].

Recommended prompt pair:

1. Task prompt: "Answer only from the provided sources or well-established knowledge. Cite a source for each factual claim. If you cannot verify a claim, state 'unknown' for that claim. Do not guess numbers, dates, or citations."
2. Check prompt: "List each factual claim in your previous answer. For each, restate the evidence or mark it unverified."

A1. The task involves verifiable facts. Why not measured: the material does not state it. Validate by: one message naming the domain. If wrong: the check prompt still applies, the citation rule weakens.

A2. No retrieval tool is available. Why not measured: no tool can reach it. Validate by: inspect the deployment settings. If wrong: attach retrieval and drop reliance on memory.

## End

I recommend that we take these actions:

1. Adopt the two-prompt pair above in the next session. This removes the blocker of unsupported claims. Deterministic test: Given a question outside the model's knowledge, When the task prompt is applied, Then the answer contains "unknown" and no fabricated citation. Cynefin domain: Clear, because a known good practice exists [1].
2. Add source documents or a retrieval tool before high-stakes use. This adds the capability to verify against ground truth. Deterministic test: Given a factual question with one attached source, When the model answers, Then each claim cites that source. Cynefin domain: Complicated, because selecting the retrieval setup needs analysis of the deployment.
3. Run a calibration check on ten representative questions with known answers. This measures the remaining error rate. Stochastic test: metric is unsupported-claim rate, baseline is the current session, pass threshold is zero fabricated citations across ten trials. Cynefin domain: Complex, because failure modes on real tasks appear only after use; cap the probe at ten trials, stop if fabrication persists, then change the setup rather than the wording.

Step 3 follows Step 1 in the same session. Step 2 runs in parallel.

## Follow-up

Condition that changes the recommendation: if A2 is false, replace Step 2 with configuring the existing retrieval tool and keep the rest.
