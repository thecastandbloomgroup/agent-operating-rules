## Headline

Resolve SQL formatting disputes with one auto-formatter in CI, not with a culture talk. Tools end the argument because the formatter decides, reviewers stop debating style. The team sets the config once, then automation enforces it. A culture fix fails here because the disagreement is about mechanics, not values.

## Background

The team cannot agree on SQL formatting. Reviews stall on style comments. The request asks for a culture fix, but the conflict is mechanical: no shared, enforced standard exists.

## Relevance

Every style debate in review costs reviewer time and delays merges. A settled standard returns that time this week.

## Information

Evidence [judgment]: formatting disputes persist in the absence of an objective arbiter. This pattern is documented: style enforcement by tool, not by policy, removes the dispute from human review [1][2].

A1. The team uses a single database dialect. Why not measured: the material does not state it. Validate by: run the formatter on the 20 most-edited SQL files and count parse failures. If wrong: add dialect flags to the config in Step 1, no change to the rest.

A2. Code review happens through pull requests with CI available. Why not measured: the material does not state it. Validate by: check for an existing CI pipeline file. If wrong: use a pre-commit hook instead of a CI job.

The alternative is a written style guide plus team agreement. It loses because humans still adjudicate violations in review, so the friction returns [judgment].

## End

I recommend that we do five steps, in order.

1. Pick and configure one formatter (sqlfluff or sqlfmt) in a one-hour team vote. This removes the "which standard" blocker. Deterministic test:

3. Reformat the whole repo in one commit. This removes false diffs in future work. Deterministic test:

Then no file changes.

4. Add a CI check that fails on unformatted SQL. Step 4 MUST NOT start until Step 3 passes. This removes enforcement from human reviewers. Deterministic test:

5. Add a review-norm line to the team docs: no style comments in review, link the formatter instead. Step 5 runs in parallel with Steps 1 to 4. This closes the culture gap with a rule, not a lecture. Deterministic test:
Given a new pull request,
When a style comment appears in review,
Then the reply links the formatter check and no debate follows (sample: next 10 pull requests).

## Follow-up

If A2 is false, replace Step 4 with a pre-commit hook. If Step 5 fails twice, schedule one 30-minute retrospective on review norms.
