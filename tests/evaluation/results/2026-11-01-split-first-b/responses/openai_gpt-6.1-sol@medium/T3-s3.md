## Background

The request covers two changes: replace sessions with JSON Web Tokens (JWTs), and improve sign-up conversion. [1] No service code, deployment details, or conversion data accompany the request.

## Relevance

JWT adoption requires explicit token validation rules, including algorithm and audience checks. [2] Meanwhile, a conversion baseline provides a test for whether sign-up changes help. [judgment]

## Information

**Scope and evidence**

JWTs do not, by themselves, define the service’s logout or account-disable requirements. [judgment] Those requirements must guide the design rather than follow from the token choice. [judgment]

For sign-up, use completed registrations divided by unique sign-up starts as the initial completion metric. [judgment] Keep activation and abuse rates as separate checks, rather than treating every new registration as success. [judgment]

**Assumption log**

A1. Preserve existing access controls. Why not measured: The material does not state them. Validate by: inspect authentication tests. If wrong: revise migration scope.

A2. Conversion means completed registration. Why not measured: The material does not state it. Validate by: inspect the product metric definition. If wrong: replace the metric.

**Alternative considered**

Replace sessions immediately, then simplify sign-up in the same release. This loses because it couples security changes with conversion changes before either has acceptance criteria. [judgment]
