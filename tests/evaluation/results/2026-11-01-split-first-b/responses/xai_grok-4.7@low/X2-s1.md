Headline
The team should close one past change before it adds a new one.
First, score the last actions so the cause is known.
Next, give one action one owner and one date.
Then, start the next meeting with that result.
Last, add a safety check only if people hide the real issue.

Background
A retrospective is a meeting where the team inspects its work and picks a change.
The team still holds these meetings, and people attend.
Nothing in the work changes after them.

Relevance
The next meeting can restore the link between talk and change.
Without that link, the meeting only records unused ideas.

Information
This section covers the evidence, the assumptions, and the alternative.

The Scrum Guide says the team addresses the most helpful improvement as soon as possible.
[1]
Derby and Larsen say the team picks a small experiment and then inspects the result.
[2]
Therefore, a retrospective fails when the chosen change is not checked.
Kerth asks the team to assume good intent, so blame does not block the facts.
[3]

The symptom matches a follow-through gap more than an attendance gap.
That match is [judgment].
Confidence is likely (66 to 100%), because people attend and work does not change.
No number with units is in the request.
The baseline is a meeting that produces no change in the next work cycle. [judgment]

A1. Past actions are written but not owned. Why not measured: the material does not state the action log. Validate by: open the last three meeting notes. If wrong: Step 2 starts from a blank board.

A2. The team can change its own way of work. Why not measured: the material does not state team control. Validate by: check whether the last failed change needed a manager. If wrong: send that change to the manager and keep a team-sized one.

A3. People will name real issues in the room. Why not measured: the material does not state what is said. Validate by: count unnamed issues in one anonymous note round. If wrong: run the safety probe before new actions.

A4. The team has at least five people. Why not measured: the material does not state team size. Validate by: count people in the next meeting. If wrong: set the probe pass count to half the people present, rounded up.

Alternative considered:
A new meeting exercise is the strongest alternative.
It loses because a new exercise still fails if no one checks the last change. [judgment]

End
I recommend that we do these five steps in this order.

1. Score the last three meeting notes before any new change.
Rubric: owner named, 25 points.
Date named, 25 points.
Status recorded, 25 points.
The team can do the work, 25 points.
Pass threshold: 75 of 100.
Evidence: the written notes.
The increment is one session that scores those notes.
It removes the unknown cause.
Domain: Confused, because the cause is not yet visible.
Step 2 MUST NOT start until the score is written.

2. Put one open action on the team board.
Given a note that scores under 75,
When the board is updated,
Then one owner and one check date are visible to the team.
The increment is one session that updates the board.
It removes the lack of an owner.
Domain: Clear, because the team tracks one improvement by a known practice.
This step uses the result of Step 1.

3. Start the next retrospective with that action's result.
Given the check date has passed,
When the meeting starts,
Then the owner states done, not done, or dropped.
The increment is the first ten minutes of that meeting.
It removes new talk that hides old work.
Domain: Clear, because the order is a fixed practice.
Step 3 MUST NOT start until Step 2 is on the board.

4. Accept only one change the team can finish in one cycle.
Rubric: the team controls the change, 50 points.
The change fits one cycle, 50 points.
Pass threshold: 100 of 100.
Evidence: the owner confirms both facts.
The increment is the close of the same meeting.
It removes changes that are too large.
Domain: Complicated, because size and control need a short check.
Step 4 starts after the result in Step 3 is stated.

5. Run one safety probe if the notes show blame or silence.
Metric: notes that name a work problem.
Baseline: zero named issues in the open talk. [judgment]
Pass threshold: at least three notes.
Sample size: one meeting.
Given fear is the open question,
When each person writes one unnamed issue,
Then count notes that name a work problem.
Stop if a note names a person.
Budget: ten minutes.
The increment is that ten-minute probe, not a new meeting design.
It tests whether safety blocks the facts.
Domain: Complex, because the effect shows only after the probe.
Leverage is a guess.
Run it in parallel with Steps 2 and 3, inside the ten-minute cap.
If A3 is false, run Step 5 before Step 4.

Follow-up
If A1 is false, Step 2 starts from one new action.
If A2 is false, send the blocked change to the manager.
If A4 is false, set the probe pass count to half the people present, rounded up.
